# diffusion_planner/train_epoch.py 详解

本文档解释 `diffusion_planner/train_epoch.py` 的代码结构、函数输入输出、变量含义和调用关系。这个文件负责单个 epoch 的训练主循环，是数据读取、数据增强、归一化、loss 计算、反向传播、参数更新和 epoch loss 汇总的连接点。

## 1. 文件作用

`train_epoch.py` 当前只有一个核心函数：

```python
train_epoch(data_loader, model, optimizer, args, ema, aug=None)
```

它完成一个 epoch 内所有 batch 的训练流程：

1. 从 `data_loader` 取 batch。
2. 把 batch tuple 拆成模型输入 `inputs`、ego future、neighbor future。
3. 可选调用 `StatePerturbation` 做训练数据增强。
4. 把 future heading 从角度转成 `[cos, sin]`。
5. 构造 neighbor future 的 padding mask。
6. 对 observation 输入做归一化。
7. 调用 `diffusion_loss_func()` 计算扩散训练 loss。
8. 组合总 loss。
9. 反向传播、梯度裁剪、优化器更新。
10. 更新 EMA 模型参数。
11. 汇总当前 epoch 的平均 loss。
12. 如果启用 DDP，对多进程 loss 做同步平均。

整体调用链：

```text
train_predictor.py
    ├── 构造 train_loader
    ├── 构造 diffusion_planner
    ├── 构造 optimizer
    ├── 构造 model_ema
    ├── 可选构造 StatePerturbation
    └── train_epoch(train_loader, diffusion_planner, optimizer, args, model_ema, aug)
            ├── aug(inputs, ego_future, neighbors_future)
            │       └── StatePerturbation.__call__(...)
            ├── args.observation_normalizer(inputs)
            │       └── ObservationNormalizer.__call__(...)
            ├── diffusion_loss_func(...)
            │       ├── args.state_normalizer(...)
            │       ├── model.sde.marginal_prob(...)
            │       └── model(merged_inputs)
            ├── loss["loss"].backward()
            ├── nn.utils.clip_grad_norm_(...)
            ├── optimizer.step()
            ├── ema.update(model)
            ├── get_epoch_mean_loss(epoch_loss)
            └── ddp.reduce_and_average_losses(...)
```

## 3. train_epoch 函数签名

```python
def train_epoch(data_loader, model, optimizer, args, ema, aug: StatePerturbation=None):
```

## 4. 函数作用

`train_epoch()` 负责训练一个完整 epoch。

它不负责：

- 创建模型。
- 创建数据集。
- 创建优化器。
- 保存 checkpoint。
- 调度学习率。

这些由 `train_predictor.py` 或其他工具负责。

它负责：

- 每个 batch 的前向、loss、反向、优化器更新。
- 当前 epoch 的 loss 汇总。

## 5. 输入参数

### 5.1 `data_loader`

```python
data_loader
```

通常是 PyTorch 的 `DataLoader`。

它从 `DiffusionPlannerData` 数据集读取 batch。

每个 `batch` 是一个 tuple，顺序由 `diffusion_planner/utils/dataset.py` 中的 `DiffusionPlannerData.__getitem__()` 决定：

```text
batch[0]  -> ego_current_state
batch[1]  -> ego_future_gt
batch[2]  -> neighbor_agents_past
batch[3]  -> neighbors_future_gt
batch[4]  -> lanes
batch[5]  -> lanes_speed_limit
batch[6]  -> lanes_has_speed_limit
batch[7]  -> route_lanes
batch[8]  -> route_lanes_speed_limit
batch[9]  -> route_lanes_has_speed_limit
batch[10] -> static_objects
```

常见数据结构：

```text
ego_current_state         -> [B, 10]
ego_future_gt             -> [B, T, 3]
neighbor_agents_past      -> [B, A, H, 11]
neighbors_future_gt       -> [B, Pn, T, 3]
lanes                     -> [B, L, P, 12]
lanes_speed_limit         -> [B, L, 1] 或 [B, L]
lanes_has_speed_limit     -> [B, L, 1] 或 [B, L]
route_lanes               -> [B, R, P, 12]
route_lanes_speed_limit   -> [B, R, 1] 或 [B, R]
route_lanes_has_speed_limit -> [B, R, 1] 或 [B, R]
static_objects            -> [B, S, 10]
```

其中：

- `B`：batch size。
- `T`：future_len，通常是 80。
- `A`：历史输入中的 neighbor 数量。
- `H`：历史轨迹长度，通常是 21。
- `Pn`：需要预测 future 的 neighbor 数量。
- `L`：周围 lane 数量。
- `R`：route lane 数量。
- `P`：每条 polyline 的点数。
- `S`：静态物体数量。

```python
model
```

训练中的 Diffusion Planner 模型，通常是：

```text
Diffusion_Planner
```

或者 DDP 包装后的模型：

```text

```

函数中会执行：

```python

```

使模型进入训练模式。

后续在 `diffusion_loss_func()` 内部会调用：

```python
_, decoder_output = model(merged_inputs)
```

### 5.3 `optimizer`

```python
optimizer
```

PyTorch 优化器，例如 AdamW。

函数中使用：

```python

optimizer.step()
```

分别用于清空历史梯度和更新模型参数。

```python
args
```

## 7. 函数内部流程详解

### 7.1 初始化 epoch_loss

```python
epoch_loss = []
```

`epoch_loss` 用于保存当前 epoch 内每个 batch 的 loss 字典。

每个元素类似：

```python
{
    "neighbor_prediction_loss": tensor(...),
    "ego_planning_loss": tensor(...),
    "loss": tensor(...)
}
```

最后会传给：

```python
get_epoch_mean_loss(epoch_loss)
```

求平均。

### 7.2 设置模型为训练模式

```python
model.train()
```

这会影响：

- Dropout：训练时启用随机丢弃。
- BatchNorm：使用 batch 统计量。
- 其他依赖 `self.training` 的模块。

在本项目中，`Decoder.forward()` 会根据 `self.training` 走不同逻辑：

```text
training=True:
    使用 inputs["sampled_trajectories"] 和 inputs["diffusion_time"]
    返回 decoder_output["score"]

training=False:
    从噪声采样，调用 dpm_sampler
    返回 decoder_output["prediction"]
```

所以这里必须调用 `model.train()`，否则 decoder 会走推理采样逻辑。

### 7.3 DDP CUDA 同步

```python
if args.ddp:
    torch.cuda.synchronize()
```

如果启用 DDP，先同步当前 CUDA 设备。

作用是确保前面的 GPU 操作完成，减少多进程训练中异步操作造成的统计或状态不一致。

### 7.4 创建 tqdm 进度条

```python
with tqdm(data_loader, desc="Training", unit="batch") as data_epoch:
```

`data_epoch` 是被 tqdm 包装后的 dataloader。

后面可以用：

```python
data_epoch.set_postfix(loss='{:.4f}'.format(total_loss))
```

动态显示当前 batch 的 loss。

### 7.5 遍历 batch

```python
for batch in data_epoch:
```

每次循环处理一个 batch。

`batch` 是 tuple，不是 dict。它的顺序必须和 `DiffusionPlannerData.__getitem__()` 返回的 `tuple(data.values())` 保持一致。

## 9. 数据增强 aug

```python
if aug is not None:
    inputs, ego_future, neighbors_future = aug(inputs, ego_future, neighbors_future)
```

如果传入了 `StatePerturbation`，这里会执行增强。

`StatePerturbation.__call__()` 的输入：

```text
inputs           -> dict
ego_future       -> [B, T, 3]
neighbors_future -> [B, Pn, T, 3]
```

输出形状不变：

```text
inputs           -> dict
ego_future       -> [B, T, 3]
neighbors_future -> [B, Pn, T, 3]
```

但内容会变：

- 一部分样本的 `ego_current_state` 被扰动。
- ego future 前 2 秒被五次多项式重新插值。
- ego、neighbor、lane、route lane、static object 都被转换到扰动后的 ego 坐标系。

如果 `aug is None`，这里什么都不做。

## 10. ego_future heading 转 cos/sin

```python
ego_future = torch.cat(
[
    ego_future[..., :2],
    torch.stack(
        [ego_future[..., 2].cos(), ego_future[..., 2].sin()], dim=-1
    ),
],
dim=-1,
)
```

### 10.1 输入结构

转换前：

```text
ego_future -> [B, T, 3]
```

字段：

```text
[x, y, heading]
```

### 10.2 代码含义

```python
ego_future[..., :2]
```

取出：

```text
[x, y]
```

形状：

```text
[B, T, 2]
```

```python
ego_future[..., 2].cos()
ego_future[..., 2].sin()
```

把 heading 转成：

```text
cos_heading
sin_heading
```

各自形状：

```text
[B, T]
```

```python
torch.stack([...], dim=-1)
```

把二者堆叠成：

```text
[B, T, 2]
```

最后 `torch.cat(..., dim=-1)` 拼成：

```text
[B, T, 4]
```

字段变为：

```text
[x, y, cos_heading, sin_heading]
```

### 10.3 为什么要这样做

直接用 heading 角度会有 `pi` 和 `-pi` 附近的不连续问题。

例如：

```text
179° 和 -179°
```

从角度数值看差了 358°，但实际方向只差 2°。

用 `[cos, sin]` 表达朝向可以避免这个跳变。

## 11. neighbor future mask 构造

```python
mask = torch.sum(torch.ne(neighbors_future[..., :3], 0), dim=-1) == 0
```

### 11.1 输入结构

此时 `neighbors_future` 还没转 cos/sin，形状是：

```text
[B, Pn, T, 3]
```

字段：

```text
[x, y, heading]
```

### 11.2 计算逻辑

```python
torch.ne(neighbors_future[..., :3], 0)
```

判断前三个字段是否不等于 0。

输出形状：

```text
[B, Pn, T, 3]
```

每个元素是 bool。

```python
torch.sum(..., dim=-1)
```

对最后一维求和。

输出形状：

```text
[B, Pn, T]
```

如果某个 future 点 `[x, y, heading]` 全是 0，那么 sum 就是 0。

```python
== 0
```

得到 padding mask：

```text
mask=True  -> 该 neighbor future 点无效或 padding
mask=False -> 该 neighbor future 点有效
```

### 11.3 输出结构

```text
mask -> [B, Pn, T]
```

这个 mask 会传给：

```python
diffusion_loss_func(..., (ego_future, neighbors_future, mask), ...)
```

用于只统计有效 neighbor future 的 loss。

## 12. neighbors_future heading 转 cos/sin

```python
neighbors_future = torch.cat(
[
    neighbors_future[..., :2],
    torch.stack(
        [neighbors_future[..., 2].cos(), neighbors_future[..., 2].sin()], dim=-1
    ),
],
dim=-1,
)
```

转换前：

```text
neighbors_future -> [B, Pn, T, 3]
```

字段：

```text
[x, y, heading]
```

转换后：

```text
neighbors_future -> [B, Pn, T, 4]
```

字段：

```text
[x, y, cos_heading, sin_heading]
```

## 13. padding 位置重新置零

```python
neighbors_future[mask] = 0.
```

这一步很重要。

如果某个 padding 点原来是：

```text
[0, 0, 0]
```

经过 heading 转 cos/sin 后会变成：

```text
[0, 0, cos(0), sin(0)] = [0, 0, 1, 0]
```

这样 padding 点就不再是全 0，会被后续逻辑误认为有效数据。

所以必须用刚才的 `mask` 把这些位置重新清零：

```text
[0, 0, 1, 0] -> [0, 0, 0, 0]
```

## 14. observation 输入归一化

```python
inputs = args.observation_normalizer(inputs)
```

调用的是：

```text
ObservationNormalizer.__call__()
```

主要作用：

- 对 `neighbor_agents_past`
- `lanes`
- `route_lanes`
- `static_objects`
- 其他配置中的 observation 特征

做：

```text
normalized = (data - mean) / std
```

同时保持 padding 位置为 0。

注意：

```text
ego_future 和 neighbors_future 不在这里归一化
```

future 标签会在 `diffusion_loss_func()` 里面通过：

```python
args.state_normalizer
```

做归一化。

## 15. 清空梯度

```python
optimizer.zero_grad()
```

PyTorch 默认会累积梯度。

所以每个 batch 反向传播前都需要清空上一轮的梯度，否则多个 batch 的梯度会叠加。

```python
loss = {}
```

## 17. 调用 diffusion_loss_func

```python
loss, _ = diffusion_loss_func(
    model,
    inputs,
    ddp.get_model(model, args.ddp).sde.marginal_prob,
    (ego_future, neighbors_future, mask),
    args.state_normalizer,
    loss,
    args.diffusion_model_type
)
```

### 17.1 `model`

传入当前训练模型。

`diffusion_loss_func()` 内部会调用：

```python
model(merged_inputs)
```

### 17.2 `inputs`

传入归一化后的 observation 输入。

形如：

```text
{
  "ego_current_state": ...,
  "neighbor_agents_past": ...,
  "lanes": ...,
  "route_lanes": ...,
  "static_objects": ...
}
```

### 17.3 `ddp.get_model(model, args.ddp).sde.marginal_prob`

这里分两步：

```python
ddp.get_model(model, args.ddp)
```

如果是 DDP：

```text
返回 model.module
```

如果不是 DDP：

```text
返回 model
```

然后取：

```python
.sde.marginal_prob
```

这是扩散 SDE 的边缘概率函数，用于构造加噪轨迹：

```text
x_t = mean(x_0, t) + std(t) * z
```

### 17.4 `(ego_future, neighbors_future, mask)`

这是 future 标签元组。

传入时结构：

```text
ego_future       -> [B, T, 4]
neighbors_future -> [B, Pn, T, 4]
mask             -> [B, Pn, T]
```

其中 `mask=True` 表示 neighbor future 无效。

### 17.5 `args.state_normalizer`

用于在 `diffusion_loss_func()` 内部归一化 future 标签。

### 17.6 `args.diffusion_model_type`

控制扩散训练目标：

```text
"score"   -> 预测 score
"x_start" -> 预测干净 future
```

### 17.7 返回值

`diffusion_loss_func()` 返回：

```text
loss
decoder_output
```

这里用 `_` 忽略 `decoder_output`：

```python
loss, _ = ...
```

因为训练循环只需要 loss 做反向传播。

## 18. 组合总 loss

```python
loss['loss'] = loss['neighbor_prediction_loss'] + args.alpha_planning_loss * loss['ego_planning_loss']
```

总 loss 由两部分组成：

```text
neighbor_prediction_loss
ego_planning_loss
```

公式：

```text
total_loss = neighbor_prediction_loss + alpha_planning_loss * ego_planning_loss
```

其中：

```python
args.alpha_planning_loss
```

用于调节 ego planning loss 的权重。

如果：

```text
alpha_planning_loss = 1.0
```

那么 ego 和 neighbor loss 等权相加。

如果：

```text
alpha_planning_loss = 2.0
```

那么 ego planning loss 权重加倍。

## 19. 取 total_loss 数值

```python
total_loss = loss['loss'].item()
```

`.item()` 会把标量 tensor 转成 Python 数值。

这里主要用于：

```python
data_epoch.set_postfix(loss='{:.4f}'.format(total_loss))
```

显示进度条，不参与反向传播。

## 20. 反向传播

```python
loss['loss'].backward()
```

对总 loss 做反向传播，计算模型参数梯度。

这里反向的是：

```text
neighbor_prediction_loss + alpha_planning_loss * ego_planning_loss
```

## 21. 梯度裁剪

```python
nn.utils.clip_grad_norm_(model.parameters(), 5)
```

作用：

```text
把模型参数梯度的总范数限制在 5 以内
```

目的：

- 防止梯度爆炸。
- 提高扩散模型训练稳定性。

输入：

```text
model.parameters()
```

输出：

```text
返回裁剪前的总梯度范数
```

但当前代码没有接收这个返回值。

## 22. 参数更新

```python
optimizer.step()
```

根据当前梯度更新模型参数。

执行顺序是标准 PyTorch 训练顺序：

```text
zero_grad()
loss.backward()
clip_grad_norm_()
optimizer.step()
```

## 23. 更新 EMA

```python
ema.update(model)
```

EMA 表示 Exponential Moving Average，指数滑动平均。

它维护一份更平滑的模型参数：

```text
ema_param = decay * ema_param + (1 - decay) * current_param
```

当前代码在每次 optimizer 更新后立刻更新 EMA。

EMA 模型通常用于：

- 验证。
- 推理。
- 保存更稳定的 checkpoint。

## 24. DDP step 后同步

```python
if args.ddp:
    torch.cuda.synchronize()
```

如果使用 DDP，当前 step 后再次同步 CUDA。

这样可以确保当前 batch 的 GPU 操作完成后再更新进度和统计。

## 25. 更新进度条

```python
data_epoch.set_postfix(loss='{:.4f}'.format(total_loss))
```

在 tqdm 右侧显示当前 batch 的总 loss。

显示格式类似：

```text
Training:  30%|...| loss=0.1234
```

## 26. 保存 batch loss

```python
epoch_loss.append(loss)
```

把当前 batch 的 loss 字典加入列表。

每个 batch 的 `loss` 字典大致是：

```python
{
    "neighbor_prediction_loss": tensor(...),
    "ego_planning_loss": tensor(...),
    "loss": tensor(...)
}
```

后面用它计算 epoch 平均 loss。

## 27. 计算 epoch 平均 loss

```python
epoch_mean_loss = get_epoch_mean_loss(epoch_loss)
```

`get_epoch_mean_loss()` 会遍历 `epoch_loss` 中的每个 loss 字典，按 key 收集数值，然后求平均。

输入：

```text
epoch_loss -> List[Dict[str, Tensor]]
```

输出：

```text
epoch_mean_loss -> Dict[str, float]
```

例如：

```python
{
    "neighbor_prediction_loss": 0.31,
    "ego_planning_loss": 0.24,
    "loss": 0.55
}
```

## 28. DDP loss 同步平均

```python
if args.ddp:
    epoch_mean_loss = ddp.reduce_and_average_losses(epoch_mean_loss, torch.device(args.device))
```

如果使用分布式训练，每个进程只看到了自己那部分数据。

所以每个进程算出来的 `epoch_mean_loss` 是局部平均。

`ddp.reduce_and_average_losses()` 会：

1. 对每个 loss key 做 `dist.all_reduce(SUM)`。
2. 除以 `world_size`。
3. 得到所有进程的全局平均 loss。

输出仍然是：

```text
Dict[str, float]
```

## 29. 只在 rank 0 打印

```python
if ddp.get_rank() == 0:
    print(f"epoch train loss: {epoch_mean_loss['loss']:.4f}\n")
```

DDP 中每个 GPU 进程都会执行同一份代码。

如果每个进程都打印，会出现重复日志。

所以这里只在主进程：

```text
rank == 0
```

打印 epoch loss。

## 30. 返回结果

```python
return epoch_mean_loss, epoch_mean_loss['loss']
```

返回：

```text
epoch_mean_loss       -> Dict[str, float]
epoch_mean_loss["loss"] -> float
```

`train_predictor.py` 中使用：


后续会：

- 用 `train_total_loss` 保存 checkpoint 文件名或训练状态。

## 32. 一个简单例子

假设：

```text
B = 2
T = 80
Pn = 10
```

从 `data_loader` 取出：

```text
ego_future       -> [2, 80, 3]
neighbors_future -> [2, 10, 80, 3]
```

构造 mask：

```text
mask -> [2, 10, 80]
```

heading 转 cos/sin 后：

```text
ego_future       -> [2, 80, 4]
neighbors_future -> [2, 10, 80, 4]
```

进入 `diffusion_loss_func()` 后，会在 agent 维拼接 ego 和 neighbor：

```text
gt_future -> [2, 11, 80, 4]
```

其中：

```text
agent 0      -> ego
agent 1..10  -> neighbors
```

loss 函数返回：

```python
loss = {
    "neighbor_prediction_loss": tensor(0.30),
    "ego_planning_loss": tensor(0.20)
}
```

如果：

```text
args.alpha_planning_loss = 1.0
```

则：

```python
loss["loss"] = 0.30 + 1.0 * 0.20 = 0.50
```

然后：

```text
backward -> clip grad -> optimizer step -> EMA update
```

当前 batch 的 loss 字典会加入 `epoch_loss`，最后统计 epoch 平均。

## 33. 需要特别注意的点

1. `batch` 是 tuple，不是 dict，所以索引顺序必须和 `DiffusionPlannerData.__getitem__()` 保持一致。
2. `ego_future` 和 `neighbors_future` 原始是 `[x, y, heading]`，进入 loss 前会转换成 `[x, y, cos_h, sin_h]`。
3. neighbor future 的 `mask=True` 表示无效或 padding。
4. `neighbors_future[mask] = 0.` 是必要的，否则 padding 的 heading 经过 cos/sin 后会变成 `[1, 0]`。
5. observation 输入由 `args.observation_normalizer` 归一化，future 标签由 `args.state_normalizer` 在 loss 函数内归一化。
6. `model.train()` 很关键，否则 decoder 会走推理采样逻辑，而不是训练时的 score/x_start 输出逻辑。
7. 总 loss 在 `train_epoch.py` 中组合，不在 `loss.py` 中组合。
8. DDP 下 epoch loss 需要经过 `ddp.reduce_and_average_losses()` 才是全局平均。
