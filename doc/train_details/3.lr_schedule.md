# diffusion_planner/utils/lr_schedule.py 详解

本文档详细解释 `diffusion_planner/utils/lr_schedule.py` 中的函数、变量、调用关系，以及输入输出数据结构。

这个文件目前只定义了一个函数：

```python
def CosineAnnealingWarmUpRestarts(...)
```

需要注意：虽然函数名里有 `CosineAnnealing` 和 `Restarts`，但当前源码**没有使用 cosine annealing，也没有实现 restart**。当前实际逻辑是：

```text
前 warm_up_epoch 个 epoch：LinearLR 线性 warm up
warm up 之后：MultiplicativeLR，lambda 恒为 1.0，也就是保持学习率不变
```

## 文件位置

```text
diffusion_planner/utils/lr_schedule.py
```

## 上下游调用关系

`lr_schedule.py` 主要被训练入口 `train_predictor.py` 使用。

导入位置：

```python
from diffusion_planner.utils.lr_schedule import CosineAnnealingWarmUpRestarts
```

创建 scheduler：

```python
params = [{
    'params': ddp.get_model(diffusion_planner, args.ddp).parameters(),
    'lr': args.learning_rate,
}]

optimizer = optim.AdamW(params)
scheduler = CosineAnnealingWarmUpRestarts(
    optimizer,
    train_epochs,
    args.warm_up_epoch,
)
```

每个 epoch 结束后更新学习率：

```python
scheduler.step()
```

checkpoint 保存：

```python
'schedule': scheduler.state_dict()
```

checkpoint 恢复：

```python
scheduler.load_state_dict(ckpt['schedule'])
```

完整链路：

```text
train_predictor.py
    -> model_training(args)
        -> optimizer = AdamW(...)
        -> scheduler = CosineAnnealingWarmUpRestarts(...)
            -> LinearLR(...)
            -> MultiplicativeLR(...)
            -> SequentialLR(...)
        -> for epoch in range(...)
            -> train_epoch(...)
            -> scheduler.step()
        -> save_model(...)
            -> scheduler.state_dict()
        -> resume_model(...)
            -> scheduler.load_state_dict(...)
```

## 导入项

源码：

```python
from torch.optim.lr_scheduler import SequentialLR, LinearLR, MultiplicativeLR
```

| 导入项 | 类型 | 作用 |
|---|---|---|
| `SequentialLR` | PyTorch scheduler 类 | 将多个 scheduler 按顺序串起来 |
| `LinearLR` | PyTorch scheduler 类 | 按线性比例调整学习率，用于 warm up |
| `MultiplicativeLR` | PyTorch scheduler 类 | 每次 step 时用 lambda 返回值乘当前学习率 |

## CosineAnnealingWarmUpRestarts()

函数定义：

```python
def CosineAnnealingWarmUpRestarts(
    optimizer,
    epoch,
    warm_up_epoch,
    start_factor=0.1,
):
```

### 作用

构造并返回一个 PyTorch `SequentialLR` 学习率调度器。

返回的 scheduler 由两个阶段组成：

1. `warmup_scheduler = LinearLR(...)`
2. `fixed_scheduler = MultiplicativeLR(...)`

然后用：

```python
SequentialLR(
    optimizer,
    schedulers=[warmup_scheduler, fixed_scheduler],
    milestones=[T_warmup],
)
```

串起来。

### 输入数据结构

| 参数 | 数据结构 | 含义 |
|---|---|---|
| `optimizer` | `torch.optim.Optimizer` | 需要被调度学习率的优化器，例如 `AdamW` |
| `epoch` | `int` | 总训练 epoch 数，训练入口中传入 `train_epochs` |
| `warm_up_epoch` | `int` | warm up 阶段持续多少个 epoch |
| `start_factor` | `float` | warm up 初始学习率比例，默认 `0.1` |

在 `train_predictor.py` 中，对应关系是：

| `CosineAnnealingWarmUpRestarts` 参数 | 来源 |
|---|---|
| `optimizer` | `optimizer = optim.AdamW(params)` |
| `epoch` | `train_epochs = args.train_epochs` |
| `warm_up_epoch` | `args.warm_up_epoch` |
| `start_factor` | 默认 `0.1` |

### 输出数据结构

| 返回值 | 数据结构 | 含义 |
|---|---|---|
| `scheduler` | `torch.optim.lr_scheduler.SequentialLR` | 组合学习率调度器，可调用 `step()`、`state_dict()`、`load_state_dict()` |

这个返回值会赋给：

```python
scheduler = CosineAnnealingWarmUpRestarts(...)
```

后续训练循环中调用：

```python
scheduler.step()
```

## 分步骤解释

### 第一步：检查 epoch 合法性

源码：

```python
assert epoch >= warm_up_epoch
```

含义：

```text
总训练轮数必须大于等于 warm up 轮数。
```

如果：

```text
epoch < warm_up_epoch
```

程序会直接触发 `AssertionError`。

### 第二步：记录 warm up 切换点

源码：

```python
T_warmup = warm_up_epoch
```

`T_warmup` 后面会作为 `SequentialLR` 的 milestone：

```python
milestones=[T_warmup]
```

含义：

```text
前 T_warmup 个 scheduler step 使用 LinearLR；
到达 milestone 后切换到 MultiplicativeLR。
```

### 第三步：创建 LinearLR warmup_scheduler

源码：

```python
warmup_scheduler = LinearLR(
    optimizer,
    start_factor=start_factor,
    total_iters=warm_up_epoch - 1,
)
```

作用：

```text
把学习率从 start_factor * base_lr 线性增加到 base_lr。
```

其中：

| 参数 | 含义 |
|---|---|
| `optimizer` | 被调整学习率的优化器 |
| `start_factor` | 初始学习率比例 |
| `total_iters` | 线性 warm up 的迭代次数 |

如果基础学习率：

```text
base_lr = args.learning_rate = 5e-4
```

默认：

```text
start_factor = 0.1
```

那么 warm up 初始学习率大约是：

```text
5e-4 * 0.1 = 5e-5
```

在 `total_iters=warm_up_epoch - 1` 的过程中逐步升到：

```text
5e-4
```

### 第四步：创建 fixed_scheduler

源码：

```python
fixed_scheduler = MultiplicativeLR(
    optimizer,
    lr_lambda=lambda epoch: 1.0,
)
```

`MultiplicativeLR` 的含义是：

```text
每次 scheduler.step() 时，把当前 lr 乘以 lr_lambda(epoch)。
```

这里：

```python
lambda epoch: 1.0
```

恒等于 `1.0`，所以：

```text
new_lr = old_lr * 1.0
```

也就是 warm up 结束后学习率保持不变。

### 第五步：用 SequentialLR 串联两个 scheduler

源码：

```python
scheduler = SequentialLR(
    optimizer,
    schedulers=[warmup_scheduler, fixed_scheduler],
    milestones=[T_warmup],
)
```

含义：

| 阶段 | scheduler | 学习率行为 |
|---|---|---|
| `0 <= step < T_warmup` | `warmup_scheduler` | 线性 warm up |
| `step >= T_warmup` | `fixed_scheduler` | 学习率保持不变 |

### 第六步：返回 scheduler

源码：

```python
return scheduler
```

返回的是组合后的 `SequentialLR`，不是 `LinearLR` 或 `MultiplicativeLR` 单独某一个。

## 学习率变化例子

假设：

```text
learning_rate = 5e-4
warm_up_epoch = 5
start_factor = 0.1
```

那么大致逻辑是：

```text
warm up 初始 lr: 5e-5
warm up 结束 lr: 5e-4
之后 lr: 5e-4，保持不变
```

可以理解为：

```text
前 5 个 epoch 慢慢升学习率；
第 5 个 epoch 之后不再衰减，也不 cosine，也不 restart。
```

注意：具体每个 epoch 的精确 lr 数值由 PyTorch `LinearLR` 和 `SequentialLR` 的内部 step 计数决定。本项目在每个 epoch 末尾调用：

```python
scheduler.step()
```

所以学习率是在 epoch 结束后推进到下一阶段。

## 与 train_predictor.py 的关系

### 创建 optimizer

源码：

```python
params = [{
    'params': ddp.get_model(diffusion_planner, args.ddp).parameters(),
    'lr': args.learning_rate,
}]

optimizer = optim.AdamW(params)
```

`params` 是一个 list，里面每个元素是 optimizer param group。

当前只有一个 param group：

| key | 数据结构 | 含义 |
|---|---|---|
| `params` | iterator / parameters | 模型参数 |
| `lr` | `float` | 初始学习率 |

### 创建 scheduler

源码：

```python
scheduler = CosineAnnealingWarmUpRestarts(
    optimizer,
    train_epochs,
    args.warm_up_epoch,
)
```

这一步把 optimizer 交给 scheduler 管理学习率。

### 记录当前学习率

源码：

```python
lr_dict = {'lr': optimizer.param_groups[0]['lr']}
wandb_logger.log_metrics({f"lr/{k}": v for k, v in lr_dict.items()}, step=epoch+1)
```

这里读的是：

```python
optimizer.param_groups[0]['lr']
```

也就是第 0 个参数组当前学习率。

### 每个 epoch 结束后 step

源码：

```python
scheduler.step()
train_sampler.set_epoch(epoch + 1)
```

顺序上，当前代码先完成训练、记录指标、可能保存模型，然后再推进 scheduler 到下一个 epoch。

### 保存 scheduler 状态

在 `diffusion_planner/utils/train_utils.py` 的 `save_model()` 中：

```python
'schedule': scheduler.state_dict()
```

保存的是 `SequentialLR` 的状态，其中也包含内部子 scheduler 的状态。

### 恢复 scheduler 状态

在 `resume_model()` 中：

```python
scheduler.load_state_dict(ckpt['schedule'])
```

这样断点续训时 scheduler 会恢复到之前的 step 位置，而不是重新从 warm up 开始。

## 函数输入输出数据结构速查

### CosineAnnealingWarmUpRestarts()

```python
def CosineAnnealingWarmUpRestarts(optimizer, epoch, warm_up_epoch, start_factor=0.1):
```

| 项 | 数据结构 | 含义 |
|---|---|---|
| 输入 `optimizer` | `torch.optim.Optimizer` | 被调度学习率的优化器 |
| 输入 `epoch` | `int` | 总训练 epoch 数 |
| 输入 `warm_up_epoch` | `int` | warm up epoch 数 |
| 输入 `start_factor` | `float` | warm up 初始学习率比例，默认 0.1 |
| 输出 `scheduler` | `torch.optim.lr_scheduler.SequentialLR` | 包含 `LinearLR` 和 `MultiplicativeLR` 的组合 scheduler |

输出对象常用方法：

| 方法 | 输出/作用 | 含义 |
|---|---|---|
| `scheduler.step()` | 无显式返回 | 推进学习率调度一步 |
| `scheduler.state_dict()` | `dict` | 返回 scheduler 当前状态，用于 checkpoint 保存 |
| `scheduler.load_state_dict(state)` | 无显式返回 | 从 checkpoint 恢复 scheduler 状态 |
| `scheduler.get_last_lr()` | `List[float]` | 返回最近一次计算的学习率 |

## 关键变量速查

| 变量 | 数据结构 | 含义 |
|---|---|---|
| `optimizer` | `torch.optim.Optimizer` | 训练优化器 |
| `epoch` | `int` | 总训练 epoch 数 |
| `warm_up_epoch` | `int` | warm up 轮数 |
| `start_factor` | `float` | warm up 初始学习率比例 |
| `T_warmup` | `int` | `SequentialLR` 切换 scheduler 的 milestone |
| `warmup_scheduler` | `LinearLR` | warm up 阶段 scheduler |
| `fixed_scheduler` | `MultiplicativeLR` | warm up 后保持学习率不变的 scheduler |
| `scheduler` | `SequentialLR` | 最终返回的组合 scheduler |
| `args.learning_rate` | `float` | optimizer 初始学习率 |
| `args.warm_up_epoch` | `int` | 训练配置中的 warm up epoch 数 |

## 注意事项

1. 函数名是 `CosineAnnealingWarmUpRestarts`，但当前实现没有 cosine annealing，也没有 restarts。
2. `assert epoch >= warm_up_epoch` 会在总 epoch 小于 warm up epoch 时直接报错。
3. `LinearLR(total_iters=warm_up_epoch - 1)` 要求 `warm_up_epoch` 通常大于 1；如果传 1，`total_iters=0` 可能不符合预期。
4. warm up 后的 `MultiplicativeLR(lambda epoch: 1.0)` 不会衰减学习率。
5. 当前训练代码在每个 epoch 末尾调用 `scheduler.step()`，因此记录到日志中的 lr 是 step 之前的当前 epoch 学习率。
6. scheduler 状态会被 `save_model()` 保存，也会被 `resume_model()` 恢复，断点续训不会重新 warm up。
