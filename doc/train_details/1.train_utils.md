# diffusion_planner/utils/train_utils.py 详解

本文档详细解释 `diffusion_planner/utils/train_utils.py` 中的函数、变量、输入输出数据结构和调用关系。

这个文件是训练辅助工具集合，主要负责：

1. 读取 JSON 配置或数据列表。
2. 读取 `.npz` 训练样本。
3. 设置随机种子。
4. 统计一个 epoch 的平均 loss。
5. 保存训练 checkpoint。
6. 从 checkpoint 恢复训练状态。

## 文件位置

```text
diffusion_planner/utils/train_utils.py
```

## 上下游调用关系

`train_utils.py` 被多个训练相关模块调用：

```text
train_predictor.py
    -> set_seed()
    -> save_model()
    -> resume_model()

diffusion_planner/utils/dataset.py
    -> openjson()
    -> opendata()

diffusion_planner/utils/normalizer.py
    -> openjson()

diffusion_planner/train_epoch.py
    -> get_epoch_mean_loss()
```

更完整的训练链路：

```text
train_predictor.py
    -> get_args()
        -> StateNormalizer.from_json()
            -> openjson()
        -> ObservationNormalizer.from_json()
            -> openjson()
    -> model_training(args)
        -> set_seed()
        -> DiffusionPlannerData(...)
            -> openjson(train_set_list)
            -> opendata(npz_path)
        -> resume_model()     # 如果指定 --resume_model_path
        -> train_epoch()
            -> get_epoch_mean_loss()
        -> save_model()       # 每隔 save_utd 个 epoch 保存
```

## openjson()

函数定义：

```python
def openjson(path):
```

### 作用

读取一个 JSON 文件，并把 JSON 文本解析成 Python 对象。

源码流程：

```python
value = fileio.get_text(path)
dict = json.loads(value)
return dict
```

这里变量名叫 `dict`，但它不一定真的是字典。如果 JSON 最外层是数组，返回值就是 list。

### 输入数据结构

| 参数 | 数据结构 | 含义 |
|---|---|---|
| `path` | `str` | JSON 文件路径，可以是本地路径，也可以是 mmengine fileio 支持的路径 |

### 输出数据结构

| 返回值 | 数据结构 | 含义 |
|---|---|---|
| `dict` | `dict`、`list` 或其他 JSON 可表达对象 | JSON 反序列化后的 Python 对象 |

## opendata()

函数定义：

```python
def opendata(path):
```

### 作用

读取 `.npz` 训练样本文件，并返回 `np.load()` 加载后的对象。

源码流程：

```python
npz_bytes = fileio.get(path)
buff = io.BytesIO(npz_bytes)
npz_data = np.load(buff)
return npz_data
```

这里不用 `np.load(path)`，而是先通过 `fileio.get(path)` 读取 bytes。这样可以兼容 mmengine 支持的不同文件后端。

### 输入数据结构

| 参数 | 数据结构 | 含义 |
|---|---|---|
| `path` | `str` | `.npz` 文件路径 |

### 输出数据结构

| 返回值 | 数据结构 | 含义 |
|---|---|---|
| `npz_data` | `numpy.lib.npyio.NpzFile` | 类似字典的对象，可以通过 key 读取 `.npz` 中的数组 |

### `.npz` 中常见字段

这些字段由 `DataProcessor.work()` 生成：

| key | 数据结构 | 含义 |
|---|---|---|
| `ego_current_state` | `np.ndarray`，形状 `[10]` | 当前 ego 状态 |
| `ego_agent_future` | `np.ndarray`，形状 `[80, 3]` | ego 未来轨迹标签 |
| `neighbor_agents_past` | `np.ndarray`，形状 `[agent_num, 21, 11]` | 动态 agent 历史输入 |
| `neighbor_agents_future` | `np.ndarray`，形状 `[agent_num, 80, 3]` | 动态 agent 未来标签 |
| `lanes` | `np.ndarray`，形状 `[lane_num, lane_len, 12]` | lane 输入 |
| `route_lanes` | `np.ndarray`，形状 `[route_num, route_len, 12]` | route lane 输入 |
| `static_objects` | `np.ndarray`，形状 `[static_objects_num, 10]` | 静态目标输入 |

### 实际调用位置

文件：

```text
diffusion_planner/utils/dataset.py
```

调用：

```python
data = opendata(os.path.join(self.data_dir, self.data_list[idx]))
```

然后 `DiffusionPlannerData.__getitem__()` 会从 `data` 中读取各个字段，并返回一个 tuple。

## set_seed()

函数定义：

```python
def set_seed(CUR_SEED):
```

### 作用

设置 Python、numpy、PyTorch 和 cuDNN 的随机性控制，尽量让训练实验可复现。

### 输入数据结构

| 参数 | 数据结构 | 含义 |
|---|---|---|
| `CUR_SEED` | `int` | 当前进程使用的随机种子 |

### 输出数据结构

| 返回值 | 含义 |
|---|---|
| 无显式返回 | 通过全局状态影响 `random`、`numpy`、`torch` 和 cuDNN |

### 分步骤解释

#### 第一步：设置 Python random

```python
random.seed(CUR_SEED)
```

影响 Python 内置 `random` 模块产生的随机数。

#### 第二步：设置 numpy

```python
np.random.seed(CUR_SEED)
```

影响 `np.random` 相关随机操作。

#### 第三步：设置 PyTorch CPU 随机种子

```python
torch.manual_seed(CUR_SEED)
```

影响 PyTorch 的随机初始化、随机采样等操作。

#### 第四步：设置 cuDNN 确定性

```python
torch.backends.cudnn.deterministic = True
torch.backends.cudnn.benchmark = False
```

含义：

| 配置 | 含义 |
|---|---|
| `deterministic=True` | 尽量使用确定性算法 |
| `benchmark=False` | 不让 cuDNN 根据输入尺寸自动选择最快算法，减少非确定性 |

### 实际调用位置

文件：

```text
train_predictor.py
```

调用：

```python
set_seed(args.seed + global_rank)
```

为什么加 `global_rank`：

```text
DDP 多进程训练时，每个进程 rank 不同。
args.seed + global_rank 可以让不同进程使用不同随机种子。
```

## get_epoch_mean_loss()

函数定义：

```python
def get_epoch_mean_loss(epoch_loss):
```

### 作用

把一个 epoch 内每个 batch 记录的 loss 字典汇总成平均 loss 字典。

### 输入数据结构

| 参数 | 数据结构 | 含义 |
|---|---|---|
| `epoch_loss` | `List[Dict[str, Union[int, float, torch.Tensor]]]` | 一个 epoch 内每个 batch 的 loss 记录 |

输入例子：

```python
epoch_loss = [
    {
        "neighbor_prediction_loss": torch.tensor(0.8),
        "ego_planning_loss": torch.tensor(0.4),
        "loss": torch.tensor(1.2),
    },
    {
        "neighbor_prediction_loss": torch.tensor(0.6),
        "ego_planning_loss": torch.tensor(0.3),
        "loss": torch.tensor(0.9),
    },
]
```

### 输出数据结构

| 返回值 | 数据结构 | 含义 |
|---|---|---|
| `epoch_mean_loss` | `Dict[str, np.float64]` | 每个 loss key 对应的 epoch 平均值 |

输出例子：

```python
{
    "neighbor_prediction_loss": 0.7,
    "ego_planning_loss": 0.35,
    "loss": 1.05,
}
```

### 分步骤解释

#### 第一步：初始化容器

```python
epoch_mean_loss = {}
```

它先不是均值，而是用来收集每个 loss 名称的一串 batch 数值。

#### 第二步：遍历每个 batch 的 loss

```python
for current_loss in epoch_loss:
    for key, value in current_loss.items():
```

`current_loss` 是一个 batch 的 loss 字典。

#### 第三步：把 tensor 转成 Python 标量

```python
value if isinstance(value, (int, float)) else value.item()
```

如果 `value` 是：

| value 类型 | 处理方式 |
|---|---|
| `int` 或 `float` | 直接保存 |
| `torch.Tensor` | 调用 `.item()` 转成 Python 标量 |

#### 第四步：按 key 收集列表

如果 key 已存在：

```python
epoch_mean_loss[key].append(...)
```

如果 key 第一次出现：

```python
epoch_mean_loss[key] = [...]
```

中间结构类似：

```python
{
    "loss": [1.2, 0.9, 1.1],
    "ego_planning_loss": [0.4, 0.3, 0.35],
}
```

#### 第五步：计算平均值

```python
for key, values in epoch_mean_loss.items():
    epoch_mean_loss[key] = np.mean(np.array(values))
```

最终每个 key 从 list 变成一个平均数。

### 实际调用位置

文件：

```text
diffusion_planner/train_epoch.py
```

调用：

```python
epoch_mean_loss = get_epoch_mean_loss(epoch_loss)
```

随后如果是 DDP 训练：

```python
epoch_mean_loss = ddp.reduce_and_average_losses(...)
```

最后返回：

```python
return epoch_mean_loss, epoch_mean_loss['loss']
```

## save_model()

函数定义：

```python
def save_model(model, optimizer, scheduler, save_path, epoch, train_loss, wandb_id, ema):
```

### 作用

保存训练 checkpoint。checkpoint 不只保存模型参数，还保存训练状态：

```text
epoch
model
ema_state_dict
optimizer
schedule
loss
wandb_id
```

这样 `resume_model()` 可以恢复训练。

### 输入数据结构

| 参数 | 数据结构 | 含义 |
|---|---|---|
| `model` | `torch.nn.Module` 或 `DistributedDataParallel` | 当前训练模型 |
| `optimizer` | `torch.optim.Optimizer` | 优化器，例如 `AdamW` |
| `scheduler` | 学习率调度器对象 | 需要实现 `state_dict()` |
| `save_path` | `str` | checkpoint 保存目录 |
| `epoch` | `int` | 当前 epoch 下标，从 0 开始 |
| `train_loss` | `float` 或可格式化数值 | 当前 epoch 的总训练 loss |
| `wandb_id` | `str` 或 `None` | wandb run id，用于恢复日志 |
| `ema` | `torch.nn.Module` | EMA 模型对象，调用 `ema.state_dict()` 保存 |

### 输出数据结构

| 返回值 | 含义 |
|---|---|
| 无显式返回 | 写入两个 checkpoint 文件 |

输出文件：

| 文件 | 含义 |
|---|---|
| `model_epoch_{epoch+1}_trainloss_{train_loss:.4f}.pth` | 带 epoch 和 loss 的历史 checkpoint |
| `latest.pth` | 最新 checkpoint，方便断点续训 |

### checkpoint 字典结构

源码：

```python
save_model = {
    'epoch': epoch + 1,
    'model': model.state_dict(),
    'ema_state_dict': ema.state_dict(),
    'optimizer': optimizer.state_dict(),
    'schedule': scheduler.state_dict(),
    'loss': train_loss,
    'wandb_id': wandb_id,
}
```

字段含义：

| key | 数据结构 | 含义 |
|---|---|---|
| `epoch` | `int` | 下次恢复训练的起始 epoch |
| `model` | `Dict[str, torch.Tensor]` | 模型参数 |
| `ema_state_dict` | `Dict[str, torch.Tensor]` | EMA 模型参数 |
| `optimizer` | `dict` | 优化器内部状态 |
| `schedule` | `dict` | 学习率调度器状态 |
| `loss` | `float` | 保存时的训练 loss |
| `wandb_id` | `str` 或 `None` | wandb run id |

### 分步骤解释

#### 第一步：组装 checkpoint 字典

```python
save_model = {...}
```

它把模型状态和训练状态都放进一个 Python dict。

#### 第二步：创建内存缓冲区

```python
with io.BytesIO() as f:
```

`BytesIO` 是内存中的二进制文件对象。

#### 第三步：序列化 checkpoint

```python
torch.save(save_model, f)
```

把 checkpoint 写入内存缓冲区，而不是直接写到磁盘。

#### 第四步：写入带 epoch 的 checkpoint

```python
fileio.put(
    f.getvalue(),
    f'{save_path}/model_epoch_{epoch+1}_trainloss_{train_loss:.4f}.pth'
)
```

文件名包含训练轮数和 loss，便于回看历史 checkpoint。

#### 第五步：写入 latest.pth

```python
fileio.put(f.getvalue(), f"{save_path}/latest.pth")
```

`latest.pth` 总是最新一份，`resume_model()` 默认加载它。

### 实际调用位置

文件：

```text
train_predictor.py
```

调用：

```python
save_model(
    diffusion_planner,
    optimizer,
    scheduler,
    save_path,
    epoch,
    train_total_loss,
    wandb_logger.id,
    model_ema.ema,
)
```

触发条件：

```python
if (epoch + 1) % args.save_utd == 0:
```

也就是每隔 `args.save_utd` 个 epoch 保存一次。

## resume_model()

函数定义：

```python
def resume_model(path: str, model, optimizer, scheduler, ema, device):
```

### 作用

从：

```text
{path}/latest.pth
```

恢复：

```text
model
optimizer
scheduler
init_epoch
wandb_id
ema
```

### 输入数据结构

| 参数 | 数据结构 | 含义 |
|---|---|---|
| `path` | `str` | checkpoint 目录，不是 checkpoint 文件本身 |
| `model` | `torch.nn.Module` 或 `DistributedDataParallel` | 要加载参数的模型 |
| `optimizer` | `torch.optim.Optimizer` | 要恢复状态的优化器 |
| `scheduler` | 学习率调度器对象 | 要恢复状态的调度器 |
| `ema` | `timm.utils.ModelEma` 或类似对象 | 需要有 `ema.ema` 子模块 |
| `device` | `str` 或 `torch.device` | 传入但源码中没有实际用于 `torch.load(map_location=...)` |

### 输出数据结构

返回：

```python
return model, optimizer, scheduler, init_epoch, wandb_id, ema
```

| 返回项 | 数据结构 | 含义 |
|---|---|---|
| `model` | 原模型对象 | 已尽量加载 checkpoint 中的模型参数 |
| `optimizer` | 原优化器对象 | 如果 checkpoint 有 optimizer，则已恢复状态 |
| `scheduler` | 原调度器对象 | 如果 checkpoint 有 schedule，则已恢复状态 |
| `init_epoch` | `int` | 恢复训练起始 epoch；checkpoint 没有时为 0 |
| `wandb_id` | `str` 或 `None` | 恢复 wandb run 的 id |
| `ema` | 原 EMA 对象 | 如果 checkpoint 有 `ema_state_dict`，则已恢复 EMA 参数 |

### 分步骤解释

#### 第一步：拼接 latest.pth 路径

```python
path = os.path.join(path, 'latest.pth')
```

所以调用时传入的是目录，例如：

```text
./training_log/run_name/time/
```

而不是：

```text
./training_log/run_name/time/latest.pth
```

#### 第二步：通过 fileio 读取 checkpoint bytes

```python
ckpt = fileio.get(path)
```

`ckpt` 此时是二进制 bytes。

#### 第三步：用 torch.load 反序列化

```python
with io.BytesIO(ckpt) as f:
    ckpt = torch.load(f)
```

反序列化后，`ckpt` 通常是 `save_model()` 保存的 dict。

#### 第四步：加载模型参数

```python
try:
    model.load_state_dict(ckpt['model'])
except:
    model.load_state_dict(ckpt)
```

这里兼容两种 checkpoint：

| checkpoint 结构 | 加载方式 |
|---|---|
| `{"model": state_dict, ...}` | 加载 `ckpt['model']` |
| 直接是 `state_dict` | 直接加载 `ckpt` |

#### 第五步：加载 optimizer

```python
try:
    optimizer.load_state_dict(ckpt['optimizer'])
except:
    print("no pretrained optimizer found")
```

如果 checkpoint 没有 optimizer，就跳过。

#### 第六步：加载 scheduler

```python
try:
    scheduler.load_state_dict(ckpt['schedule'])
except:
    print("no schedule found,")
```

如果 checkpoint 没有 schedule，就跳过。

#### 第七步：读取 init_epoch

```python
try:
    init_epoch = ckpt['epoch']
except:
    init_epoch = 0
```

`save_model()` 保存的是 `epoch + 1`，所以恢复后从下一个 epoch 开始。

#### 第八步：读取 wandb_id

```python
try:
    wandb_id = ckpt['wandb_id']
except:
    wandb_id = None
```

如果存在，则训练日志可以继续接到同一个 wandb run。

#### 第九步：加载 EMA

```python
try:
    ema.ema.load_state_dict(ckpt['ema_state_dict'])
    ema.ema.eval()
    for p in ema.ema.parameters():
        p.requires_grad_(False)
except:
    print('no ema shadow found')
```

这里操作的是 `ema.ema`，不是外层 `ema`。

加载后：

1. 设置 EMA 模型为 eval 模式。
2. 冻结 EMA 参数。
3. 返回外层 `ema` 对象。

### 实际调用位置

文件：

```text
train_predictor.py
```

调用：

```python
diffusion_planner, optimizer, scheduler, init_epoch, wandb_id, model_ema = resume_model(
    args.resume_model_path,
    diffusion_planner,
    optimizer,
    scheduler,
    model_ema,
    args.device,
)
```

触发条件：

```python
if args.resume_model_path is not None:
```

## 函数输入输出数据结构速查

| 函数 | 输入 | 输出 | 主要用途 |
|---|---|---|---|
| `openjson(path)` | `path: str` | `dict` / `list` / JSON 对象 | 读取训练列表或 normalization 配置 |
| `opendata(path)` | `path: str` | `numpy.lib.npyio.NpzFile` | 读取单个 `.npz` 训练样本 |
| `set_seed(CUR_SEED)` | `CUR_SEED: int` | `None` | 设置随机种子和 cuDNN 确定性 |
| `get_epoch_mean_loss(epoch_loss)` | `List[Dict[str, scalar/tensor]]` | `Dict[str, np.float64]` | 统计一个 epoch 的平均 loss |
| `save_model(...)` | 模型、优化器、调度器、路径、epoch、loss、wandb id、EMA | `None` | 保存 checkpoint |
| `resume_model(...)` | checkpoint 目录、模型、优化器、调度器、EMA、device | `(model, optimizer, scheduler, init_epoch, wandb_id, ema)` | 恢复训练状态 |

| 变量 | 所在函数 | 含义 |

| `epoch_loss` | `get_epoch_mean_loss()` | 一个 epoch 内所有 batch loss 字典列表 |

| `save_model` | `save_model()` | checkpoint 字典，变量名和函数名相同但作用域不同 |

## 注意事项

1. `openjson()` 中局部变量命名为 `dict`，会遮蔽 Python 内置 `dict` 类型；当前函数内不影响运行，但命名不理想。
2. `opendata()` 返回的是 `NpzFile`，不是普通 `dict`；使用方式类似 `data['key']`。
3. `set_seed()` 没有调用 `torch.cuda.manual_seed_all()`，多 GPU 随机性主要由 `torch.manual_seed()` 和 DDP rank seed 控制。
4. `save_model()` 传入的 `model` 如果是 DDP 包装对象，保存的是 DDP 对象的 `state_dict()`，key 可能带 `module.` 前缀。
5. `resume_model()` 的 `device` 参数在源码中没有实际用于 `torch.load(map_location=device)`。
6. `resume_model()` 使用裸 `except`，会吞掉具体异常；如果加载失败，只能从打印信息初步判断原因。
7. `save_model()` 要求 `save_path` 已经存在；目录创建发生在 `train_predictor.py` 中。
