# diffusion_planner/utils/config.py 详解

本文档详细解释 `diffusion_planner/utils/config.py` 中的类、函数、变量、调用关系，以及输入输出数据结构。

这个文件只定义了一个类：

```python
class Config
```

它的核心作用是：**在仿真/推理阶段，从训练保存的 `args.json` 中恢复模型配置，并把其中的 normalizer 字典重新构造成可调用对象。**

也就是说，`Config` 不是训练参数解析器。训练参数解析发生在：

```text
train_predictor.py -> get_args()
```

`Config` 主要用于 nuPlan planner 配置里：

```yaml
_target_: diffusion_planner.utils.config.Config
args_file: ???
guidance_fn: null
```

或者 guidance 版本：

```yaml
guidance_fn:
  _target_: diffusion_planner.model.guidance.guidance_wrapper.GuidanceWrapper
```

## 文件位置

```text
diffusion_planner/utils/config.py
```

## 上下游调用关系

### 训练阶段如何生成 args.json

`train_predictor.py` 中会保存训练参数：

```python
args_dict = vars(args)
args_dict = {
    k: v if not isinstance(v, (StateNormalizer, ObservationNormalizer)) else v.to_dict()
    for k, v in args_dict.items()
}
dump(args_dict, os.path.join(save_path, 'args.json'), file_format='json', indent=4)
```

这里会把：

```text
StateNormalizer 对象 -> 普通 dict
ObservationNormalizer 对象 -> 普通 dict
```

这样 `args.json` 才能被 JSON 序列化保存。

### 推理阶段如何加载 args.json

nuPlan planner yaml 中：

```yaml
diffusion_planner:
  _target_: diffusion_planner.planner.planner.DiffusionPlanner

  config:
    _target_: diffusion_planner.utils.config.Config
    args_file: ???
    guidance_fn: null
```

运行脚本中会覆盖 `args_file`：

```bash
planner.diffusion_planner.config.args_file=$ARGS_FILE
```

例如：

```bash
ARGS_FILE=./checkpoints/args.json
```

Hydra 根据 `_target_` 实例化：

```text
Config(args_file, guidance_fn)
```

然后传给：

```python
DiffusionPlanner(config, ckpt_path, ...)
```

### DiffusionPlanner 中的使用

`diffusion_planner/planner/planner.py` 中：

```python
self._config = config
self._planner = Diffusion_Planner(config)
self.data_processor = DataProcessor(config)
self.observation_normalizer = config.observation_normalizer
```

也就是说，`Config` 对象会同时被：

| 使用方 | 用途 |
|---|---|
| `Diffusion_Planner(config)` | 构造模型结构，例如 `hidden_dim`、`lane_num`、`future_len`、normalizer、guidance |
| `DataProcessor(config)` | 获取 `agent_num`、`static_objects_num`、`lane_num`、`lane_len`、`route_num`、`route_len` |
| `planner.py` | 获取 `config.observation_normalizer`，用于推理输入归一化 |

### Decoder 中的使用

`diffusion_planner/model/module/decoder.py` 中：

```python
self._state_normalizer: StateNormalizer = config.state_normalizer
self._observation_normalizer: ObservationNormalizer = config.observation_normalizer
self._guidance_fn = config.guidance_fn
```

推理输出会用：

```python
x0 = self._state_normalizer.inverse(x0.reshape(B, P, -1, 4))[:, :, 1:]
```

guidance 会用：

```python
"observation_normalizer": self._observation_normalizer,
"state_normalizer": self._state_normalizer
```

## 导入项

```python
import json
import torch
from diffusion_planner.utils.normalizer import StateNormalizer, ObservationNormalizer
```

| 导入项 | 作用 |
|---|---|
| `json` | 读取 `args_file` 中的 JSON 配置 |
| `torch` | 把 observation normalizer 的 mean/std 转成 tensor |
| `StateNormalizer` | 恢复状态归一化器 |
| `ObservationNormalizer` | 恢复观测归一化器 |

## Config 类

类定义：

```python
class Config:
```

### 作用

`Config` 做三件事：

1. 读取 `args_file`。
2. 把 JSON 中的所有 key 动态设置成 `self.xxx` 属性。
3. 把 `state_normalizer` 和 `observation_normalizer` 从普通字典恢复成真正的对象。
4. 保存外部传入的 `guidance_fn`。

最终这个 `Config` 对象就像训练时的 `args` 一样，可以通过属性访问：

```python
config.agent_num
config.lane_num
config.hidden_dim
config.state_normalizer
config.observation_normalizer
config.guidance_fn
```

## Config.__init__()

函数定义：

```python
def __init__(self, args_file, guidance_fn):
```

### 输入数据结构

| 参数 | 数据结构 | 含义 |
|---|---|---|
| `args_file` | `str` | 训练保存的 `args.json` 路径 |
| `guidance_fn` | callable、对象或 `None` | 扩散采样 guidance 函数/包装器；普通 planner 配置中为 `None` |

### 输出数据结构

| 返回值 | 含义 |
|---|---|
| 无显式返回 | 初始化 `Config` 实例属性 |

初始化后的关键属性：

| 属性 | 数据结构 | 来源 | 含义 |
|---|---|---|---|
| `self.<key>` | 任意 JSON 可表达类型 | `args_file` 中的每个 key | 训练参数或模型配置 |
| `self.state_normalizer` | `StateNormalizer` | `args_file["state_normalizer"]` | 状态归一化/反归一化器 |
| `self.observation_normalizer` | `ObservationNormalizer` | `args_file["observation_normalizer"]` | 观测归一化/反归一化器 |
| `self.guidance_fn` | callable/object/`None` | 构造函数参数 `guidance_fn` | 推理 guidance |

## 分步骤解释

### 第一步：读取 args_file

源码：

```python
with open(args_file, 'r') as f:
    args_dict = json.load(f)
```

输入：

```text
args_file: str
```

输出：

```text
args_dict: Dict[str, Any]
```

`args_dict` 是训练保存的参数字典，通常包含：

```text
agent_num
static_objects_num
lane_num
lane_len
route_num
route_len
future_len
predicted_neighbor_num
hidden_dim
encoder_depth
decoder_depth
diffusion_model_type
state_normalizer
observation_normalizer
...
```

### 第二步：动态注册属性

源码：

```python
for key, value in args_dict.items():
    setattr(self, key, value)
```

含义是：把 JSON 中每个键值对变成 `Config` 对象属性。

例如 `args_dict` 中有：

```python
{
    "predicted_neighbor_num": 10,
    "future_len": 80,
    "hidden_dim": 192
}
```

执行后就可以访问：

```python
self.predicted_neighbor_num  # 10
self.future_len              # 80
self.hidden_dim              # 192
```

这个设计让 `Config` 能替代训练时的 `args`，直接传给模型构造函数。

### 第三步：恢复 StateNormalizer

源码：

```python
self.state_normalizer = StateNormalizer(
    self.state_normalizer['mean'],
    self.state_normalizer['std']
)
```

在执行这句之前：

```text
self.state_normalizer 是普通 dict
```

结构类似：

```python
{
    "mean": [[[...]], [[...]], ...],
    "std": [[[...]], [[...]], ...]
}
```

执行之后：

```text
self.state_normalizer 是 StateNormalizer 对象
```

可以直接调用：

```python
self.state_normalizer(data)
self.state_normalizer.inverse(data)
```

为什么要恢复成对象：

```text
decoder.py 和 loss.py 需要调用 normalizer 的 __call__() 和 inverse() 方法；
普通 dict 没有这些方法。
```

### 第四步：恢复 ObservationNormalizer

源码：

```python
self.observation_normalizer = ObservationNormalizer({
    k: {
        'mean': torch.as_tensor(v['mean']),
        'std': torch.as_tensor(v['std'])
    } for k, v in self.observation_normalizer.items()
})
```

在执行这句之前：

```text
self.observation_normalizer 是普通嵌套 dict
```

结构类似：

```python
{
    "neighbor_agents_past": {
        "mean": [...],
        "std": [...]
    },
    "lanes": {
        "mean": [...],
        "std": [...]
    }
}
```

字典推导式逐项转换：

```python
k: {
    'mean': torch.as_tensor(v['mean']),
    'std': torch.as_tensor(v['std'])
}
```

例如：

```python
k = "lanes"
v = {
    "mean": [10, 0, 0, 0, ...],
    "std": [20, 20, 20, 20, ...]
}
```

转换后：

```python
"lanes": {
    "mean": torch.Tensor([...]),
    "std": torch.Tensor([...])
}
```

最终传给：

```python
ObservationNormalizer(...)
```

执行后：

```text
self.observation_normalizer 是 ObservationNormalizer 对象
```

可以调用：

```python
self.observation_normalizer(inputs)
self.observation_normalizer.inverse(inputs)
```

### 第五步：保存 guidance_fn

源码：

```python
self.guidance_fn = guidance_fn
```

`guidance_fn` 来自 Hydra 配置。

普通无 guidance 配置：

```yaml
guidance_fn: null
```

此时：

```python
self.guidance_fn = None
```

带 guidance 配置：

```yaml
guidance_fn:
  _target_: diffusion_planner.model.guidance.guidance_wrapper.GuidanceWrapper
```

Hydra 会先实例化：

```python
GuidanceWrapper()
```

再传给：

```python
Config(args_file, guidance_fn)
```

于是：

```python
self.guidance_fn = GuidanceWrapper()
```

decoder 中会根据是否为 `None` 决定采样类型：

```python
"guidance_type": "classifier" if self._guidance_fn is not None else "uncond"
```

## 输入输出数据结构速查

### Config.__init__()

```python
def __init__(self, args_file, guidance_fn):
```

| 项 | 数据结构 | 含义 |
|---|---|---|
| 输入 `args_file` | `str` | 训练保存的 `args.json` 路径 |
| 输入 `guidance_fn` | `None`、callable 或 Hydra 实例化对象 | 扩散采样 guidance |
| 中间变量 `args_dict` | `Dict[str, Any]` | 从 JSON 读取出的配置字典 |
| 输出 | 无显式返回 | 初始化当前 `Config` 实例 |

初始化后 `Config` 对象的数据结构：

```python
config = Config(...)

config.agent_num                 # int
config.static_objects_num        # int
config.lane_num                  # int
config.route_num                 # int
config.future_len                # int
config.predicted_neighbor_num    # int
config.hidden_dim                # int
config.state_normalizer          # StateNormalizer
config.observation_normalizer    # ObservationNormalizer
config.guidance_fn               # None or GuidanceWrapper
```

## args_file / args.json 的关键字段

`Config` 不显式列出字段，而是把 JSON 里的所有 key 都设置为属性。实际使用中，下面这些字段比较关键：

| 字段 | 数据结构 | 使用位置 | 含义 |
|---|---|---|---|
| `agent_num` | `int` | `DataProcessor`、encoder | 动态 agent 数量 |
| `static_objects_num` | `int` | `DataProcessor`、encoder | 静态目标数量 |
| `lane_num` | `int` | `DataProcessor`、encoder | lane 数量 |
| `lane_len` | `int` | `DataProcessor`、encoder/decoder | 每条 lane 点数 |
| `route_num` | `int` | `DataProcessor`、decoder | route lane 数量 |
| `route_len` | `int` | `DataProcessor` | 每条 route lane 点数 |
| `future_len` | `int` | decoder | 未来轨迹长度 |
| `predicted_neighbor_num` | `int` | decoder/loss | 要预测未来的 neighbor 数量 |
| `hidden_dim` | `int` | model modules | 隐藏层维度 |
| `encoder_depth` | `int` | encoder | encoder 层数 |
| `decoder_depth` | `int` | decoder | decoder 层数 |
| `num_heads` | `int` | DiT blocks | attention head 数量 |
| `diffusion_model_type` | `str` | loss/DiT | `score` 或 `x_start` |
| `state_normalizer` | `dict` -> `StateNormalizer` | decoder/guidance | 未来状态归一化参数 |
| `observation_normalizer` | `dict` -> `ObservationNormalizer` | planner/decoder/guidance | 输入观测归一化参数 |

## 和 train_predictor.py 的关系

训练保存 `args.json` 时，normalizer 被转成普通 dict：

```python
args_dict = {
    k: v if not isinstance(v, (StateNormalizer, ObservationNormalizer)) else v.to_dict()
    for k, v in args_dict.items()
}
```

因此 `args.json` 里不能直接保存 Python 对象，只能保存：

```text
list / dict / int / float / str / bool / null
```

`Config` 的任务就是把其中的 normalizer dict 恢复回 Python 对象。

## 和 planner yaml 的关系

无 guidance：

```yaml
config:
  _target_: diffusion_planner.utils.config.Config
  args_file: ???
  guidance_fn: null
```

有 guidance：

```yaml
config:
  _target_: diffusion_planner.utils.config.Config
  args_file: ???
  guidance_fn:
    _target_: diffusion_planner.model.guidance.guidance_wrapper.GuidanceWrapper
```

运行脚本通常传入：

```bash
planner.diffusion_planner.config.args_file=$ARGS_FILE
planner.diffusion_planner.ckpt_path=$CKPT_FILE
```

`args_file` 和 `ckpt_path` 要匹配同一次训练：

```text
args_file: 模型结构和归一化参数
ckpt_path: 模型权重
```

如果两者不匹配，可能出现：

1. 模型结构维度不一致。
2. normalizer shape 不一致。
3. checkpoint 加载失败。
4. 推理输出尺度错误。

## 关键变量速查

| 变量 | 数据结构 | 含义 |
|---|---|---|
| `args_file` | `str` | 配置 JSON 文件路径 |
| `guidance_fn` | `None` 或对象 | 扩散采样 guidance |
| `f` | file object | 打开的 JSON 文件句柄 |
| `args_dict` | `Dict[str, Any]` | 从 `args_file` 解析出的配置字典 |
| `key` | `str` | 配置项名称 |
| `value` | Any | 配置项值 |
| `self.state_normalizer` 初始化前 | `dict` | JSON 中保存的 mean/std |
| `self.state_normalizer` 初始化后 | `StateNormalizer` | 可调用状态归一化器 |
| `self.observation_normalizer` 初始化前 | `dict` | JSON 中保存的观测 mean/std |
| `self.observation_normalizer` 初始化后 | `ObservationNormalizer` | 可调用观测归一化器 |
| `k` | `str` | observation 特征名 |
| `v` | `Dict[str, list]` | observation 特征的 mean/std |

## 注意事项

1. `Config` 假设 `args_file` 中一定有 `state_normalizer` 和 `observation_normalizer` 字段，否则会报错。
2. `setattr(self, key, value)` 会把 JSON 里所有 key 动态挂到对象上，如果 JSON 中有意外 key，也会成为属性。
3. `Config` 只用 Python 原生 `open()` 读取本地文件，不使用 `mmengine.fileio`，因此不直接支持远程后端路径。
4. `guidance_fn` 由 Hydra 负责实例化；如果传入 `null`，则推理是无 guidance 的 uncond 模式。
5. `torch.as_tensor(v['mean'])` 没有显式指定 dtype，会根据输入 list 推断 dtype；训练阶段 `ObservationNormalizer.from_json()` 使用的是 `float32`。
6. `args_file` 和 checkpoint 权重必须对应同一套训练配置，否则模型结构或归一化维度可能不匹配。
