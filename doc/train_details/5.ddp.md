# diffusion_planner/utils/ddp.py 详解

本文档详细解释 `diffusion_planner/utils/ddp.py` 中的函数、变量、调用关系，以及每个函数的输入输出数据结构。

这个文件负责训练阶段的 DDP 分布式训练辅助逻辑，主要功能包括：

1. 初始化分布式进程组。
2. 兼容单卡、`torchrun`、SLURM 三种启动方式。
3. 控制非主进程是否打印日志。
4. 获取当前 rank 和 world size。
5. 获取 DDP 包装内部的真实模型。
6. 汇总多进程上的 loss 并取平均。

## 文件位置

```text
diffusion_planner/utils/ddp.py
```

## ddp_setup_universal()

函数定义：

```python
def ddp_setup_universal(verbose=False, args=None):
```

### 作用

初始化训练环境的 DDP 分布式配置。

它兼容三种情况：

| 情况 | 判断条件 | 行为 |
|---|---|---|
| 不使用 DDP | `args.ddp == False` | 返回单进程信息，不初始化 `torch.distributed` |
| `torchrun` / `torch.distributed.launch` | 环境变量中有 `RANK` 和 `WORLD_SIZE` | 从环境变量读取 rank/world size/local rank |
| SLURM 集群 | 环境变量中有 `SLURM_PROCID` | 从 SLURM 环境变量推导 rank/world size/gpu/master addr |

### 输入数据结构

| 参数 | 数据结构 | 含义 |
|---|---|---|
| `verbose` | `bool` | 是否调用 `setup_for_distributed()` 控制非主进程 print |
| `args` | `argparse.Namespace` 或类似对象 | 训练参数对象，至少需要 `ddp` 字段；DDP 时通常还需要 `port` 字段 |

`args` 依赖字段：

| 字段 | 数据结构 | 含义 |
|---|---|---|
| `args.ddp` | `bool` | 是否启用 DDP |
| `args.port` | `str` 或 `int` | 分布式主节点通信端口 |

### 输出数据结构

返回：

```python
return rank, gpu, world_size
```

| 返回项 | 数据结构 | 含义 |
|---|---|---|
| `rank` | `int` | 当前进程的全局 rank |
| `gpu` | `int` | 当前进程绑定的本地 GPU 编号 |
| `world_size` | `int` | 总进程数 |

在 `train_predictor.py` 中接收为：

```python
global_rank, rank, _ = ddp.ddp_setup_universal(True, args)
```

这里变量命名稍微容易混淆：

```text
global_rank <- ddp_setup_universal 返回的 rank
rank        <- ddp_setup_universal 返回的 gpu
```

所以 `train_predictor.py` 后面：

```python
diffusion_planner.to(rank if args.device == 'cuda' else args.device)
DDP(diffusion_planner, device_ids=[rank])
```

这里的 `rank` 实际是本地 GPU id。

### 分步骤解释

#### 第一步：处理 args.ddp=False

源码：

```python
if args.ddp == False:
    print(f"do not use ddp, train on GPU 0")
    return 0, 0, 1
```

含义：

```text
rank = 0
gpu = 0
world_size = 1
```

此时不会调用 `init_process_group()`。

#### 第二步：处理 torchrun 环境

源码：

```python
if 'RANK' in os.environ and 'WORLD_SIZE' in os.environ:
    rank = int(os.environ["RANK"])
    world_size = int(os.environ['WORLD_SIZE'])
    gpu = int(os.environ['LOCAL_RANK'])
    os.environ['MASTER_PORT'] = str(getattr(args, 'port', '29529'))
    os.environ["MASTER_ADDR"] = "localhost"
```

典型启动方式：

```bash
torchrun --nproc_per_node=4 train_predictor.py ...
```

环境变量含义：

| 环境变量 | 含义 |
|---|---|
| `RANK` | 当前进程全局 rank |
| `WORLD_SIZE` | 总进程数 |
| `LOCAL_RANK` | 当前机器上的 GPU 编号 |
| `MASTER_PORT` | 主进程通信端口 |
| `MASTER_ADDR` | 主进程地址 |

当前代码把 `MASTER_ADDR` 设置为：

```text
localhost
```

这通常适合单机多卡训练。

#### 第三步：处理 SLURM 环境

源码：

```python
elif 'SLURM_PROCID' in os.environ:
    rank = int(os.environ['SLURM_PROCID'])
    gpu = rank % torch.cuda.device_count()
    world_size = int(os.environ['SLURM_NTASKS'])
    node_list = os.environ['SLURM_NODELIST']
    num_gpus = torch.cuda.device_count()
    addr = subprocess.getoutput(f'scontrol show hostname {node_list} | head -n1')
    os.environ['MASTER_PORT'] = str(args.port)
    os.environ['MASTER_ADDR'] = addr
```

SLURM 变量含义：

| 环境变量 | 含义 |
|---|---|
| `SLURM_PROCID` | 当前进程全局编号 |
| `SLURM_NTASKS` | 任务总数，对应 world size |
| `SLURM_NODELIST` | SLURM 分配的节点列表 |

`gpu = rank % torch.cuda.device_count()` 的含义：

```text
如果每台机器有 8 张 GPU，rank 0-7 用 GPU 0-7，rank 8-15 在下一台机器也用 GPU 0-7。
```

`addr` 是通过 `scontrol` 从节点列表中取第一个节点作为主节点。

注意：源码中 `num_gpus = torch.cuda.device_count()` 被赋值但没有后续使用。

#### 第四步：处理非 DDP 环境

源码：

```python
else:
    print("Not using DDP mode")
    return 0, 0, 1
```

如果既没有 torchrun 环境变量，也没有 SLURM 环境变量，则回退到单进程模式。

#### 第五步：写回标准 DDP 环境变量

源码：

```python
os.environ['WORLD_SIZE'] = str(world_size)
os.environ['LOCAL_RANK'] = str(gpu)
os.environ['RANK'] = str(rank)
```

这些变量会被 `env://` 初始化方式使用。

#### 第六步：绑定当前 GPU

源码：

```python
torch.cuda.set_device(gpu)
```

每个 DDP 进程通常绑定一张 GPU。

#### 第七步：设置通信后端和初始化地址

源码：

```python
dist_backend = 'nccl'
dist_url = "env://"
```

含义：

| 变量 | 含义 |
|---|---|
| `nccl` | NVIDIA GPU 上常用的高性能通信后端 |
| `env://` | 从环境变量读取 `MASTER_ADDR`、`MASTER_PORT`、`RANK`、`WORLD_SIZE` |

#### 第八步：初始化进程组

源码：

```python
init_process_group(
    backend=dist_backend,
    world_size=world_size,
    rank=rank,
)
```

初始化后，`dist.is_initialized()` 才会返回 `True`。

#### 第九步：全局同步

源码：

```python
torch.distributed.barrier()
```

所有进程都执行到 barrier 后才会继续，避免有些进程还没初始化完成就进入训练。

#### 第十步：控制 print

源码：

```python
if verbose:
    setup_for_distributed(rank == 0)
```

如果 `verbose=True`，就调用 `setup_for_distributed()`，让非主进程默认不打印。

## setup_for_distributed()

函数定义：

```python
def setup_for_distributed(is_master):
```

### 作用

重写 Python 内置 `print()`，让非主进程默认不打印日志，避免多卡训练时重复输出。

### 输入数据结构

| 参数 | 数据结构 | 含义 |
|---|---|---|
| `is_master` | `bool` | 当前进程是否为主进程，通常是 `rank == 0` |

### 输出数据结构

| 返回值 | 含义 |
|---|---|
| 无显式返回 | 修改全局内置 `print` 函数 |

### 分步骤解释

#### 第一步：导入 builtins

```python
import builtins as __builtin__
```

`builtins.print` 是 Python 全局默认 print 函数。

#### 第二步：保存原始 print

```python
builtin_print = __builtin__.print
```

后面新 print 内部仍需要调用原始 print。

#### 第三步：定义新的 print

```python
def print(*args, **kwargs):
    force = kwargs.pop('force', False)
    if is_master or force:
        builtin_print(*args, **kwargs)
```

逻辑：

| 条件 | 是否打印 |
|---|---|
| `is_master=True` | 打印 |
| `is_master=False` 且 `force=False` | 不打印 |
| `is_master=False` 且 `force=True` | 强制打印 |

用法示例：

```python
print("debug", force=True)
```

#### 第四步：替换 builtins.print

```python
__builtin__.print = print
```

替换后，当前进程中后续普通 `print()` 都会走新逻辑。

## get_model()

函数定义：

```python
def get_model(model, use_ddp):
```

### 作用

获取真正的模型对象。

使用 PyTorch DDP 后，模型会被包装成：

```python
DistributedDataParallel(model)
```

真实模型保存在：

```python
model.module
```

所以这个函数根据 `use_ddp` 判断返回 `model.module` 还是 `model`。

### 输入数据结构

| 参数 | 数据结构 | 含义 |
|---|---|---|
| `model` | `torch.nn.Module` 或 `DistributedDataParallel` | 当前模型对象 |
| `use_ddp` | `bool` | 是否使用 DDP 包装 |

### 输出数据结构

| 返回值 | 数据结构 | 含义 |
|---|---|---|
| 模型对象 | `torch.nn.Module` | 如果 `use_ddp=True` 返回 `model.module`，否则返回 `model` |

### 实际调用位置

`train_predictor.py` 中统计参数：

```python
sum(p.numel() for p in ddp.get_model(diffusion_planner, args.ddp).parameters())
```

构造优化器：

```python
params = [{
    'params': ddp.get_model(diffusion_planner, args.ddp).parameters(),
    'lr': args.learning_rate,
}]
```

`train_epoch.py` 中取 SDE：

```python
ddp.get_model(model, args.ddp).sde.marginal_prob
```

如果直接对 DDP 包装对象访问 `.sde`，可能访问不到；所以这里先用 `get_model()` 拿内部原始模型。

## reduce_and_average_losses()

函数定义：

```python
def reduce_and_average_losses(loss_dict, device):
```

### 作用

在 DDP 多进程训练中，把每个进程上的 loss 做求和，然后除以 world size，得到所有进程的平均 loss。

### 输入数据结构

| 参数 | 数据结构 | 含义 |
|---|---|---|
| `loss_dict` | `Dict[str, scalar]`，通常 value 是 `np.float64` 或 0 维 tensor | 当前进程统计得到的 epoch 平均 loss |
| `device` | `torch.device` | 用于创建通信 tensor 的设备，例如 `torch.device("cuda")` |

输入例子：

```python
loss_dict = {
    "neighbor_prediction_loss": np.float64(0.8),
    "ego_planning_loss": np.float64(0.4),
    "loss": np.float64(1.2),
}
```

### 输出数据结构

| 返回值 | 数据结构 | 含义 |
|---|---|---|
| `loss_dict` | `Dict[str, float]` | 每个 key 已替换为所有进程平均后的 loss |

### 分步骤解释

#### 第一步：同步所有进程

源码：

```python
torch.distributed.barrier()
```

确保各个进程都已经算完本地 loss。

#### 第二步：获取 world_size

源码：

```python
world_size = dist.get_world_size()
```

例如 4 卡训练时：

```text
world_size = 4
```

#### 第三步：遍历 loss 字典

源码：

```python
for key in loss_dict.keys():
```

每个 key 单独做一次 all_reduce。

#### 第四步：把当前 loss 转成 tensor

源码：

```python
loss_tensor = torch.tensor([loss_dict[key].item()]).to(device)
```

这里假设：

```text
loss_dict[key] 有 .item() 方法
```

通常 `get_epoch_mean_loss()` 返回的是 `np.float64`，它有 `.item()` 方法。

如果 value 是普通 Python `float`，则没有 `.item()`，这里会报错。

#### 第五步：跨进程求和

源码：

```python
dist.all_reduce(loss_tensor, op=dist.ReduceOp.SUM)
```

假设 4 个进程上的 `loss` 分别是：

```text
rank0: 1.0
rank1: 1.2
rank2: 0.8
rank3: 1.4
```

`all_reduce(SUM)` 后，每个进程都会得到：

```text
4.4
```

#### 第六步：除以 world_size

源码：

```python
loss_dict[key] = loss_tensor.item() / world_size
```

最终：

```text
4.4 / 4 = 1.1
```

每个进程的 `loss_dict["loss"]` 都会变成同一个平均值。

### 实际调用位置

`diffusion_planner/train_epoch.py`：

```python
if args.ddp:
    epoch_mean_loss = ddp.reduce_and_average_losses(
        epoch_mean_loss,
        torch.device(args.device),
    )
```

也就是说，只有 `args.ddp=True` 时才会调用该函数。

## 注意事项

1. `ddp_setup_universal()` 中 `args=None` 只是默认值，但源码直接访问 `args.ddp`，所以实际调用必须传入有 `ddp` 字段的对象。
2. `torchrun` 分支中 `MASTER_ADDR` 被固定为 `localhost`，适合单机多卡；多机 torchrun 场景下通常需要更谨慎地设置主节点地址。
3. `SLURM` 分支中 `num_gpus` 被赋值但没有使用。
4. `reduce_and_average_losses()` 假设 `loss_dict[key]` 有 `.item()` 方法；如果传入普通 Python float 会报错。
5. 源码没有提供 `destroy_process_group()` 或 `cleanup()` 函数，训练结束时没有在这个模块中显式销毁进程组。
6. `setup_for_distributed()` 会修改当前进程的全局 `print`，这会影响后续所有普通 `print()` 行为。
7. `get_model()` 的 `use_ddp` 必须和模型是否真的被 DDP 包装保持一致；否则 `use_ddp=True` 但模型没有 `.module` 会报错。
