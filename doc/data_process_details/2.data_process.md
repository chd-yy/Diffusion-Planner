# data_process.py 详解

`data_process.py` 是本项目的离线训练数据预处理入口。它负责从 nuPlan 原始数据库中筛选 scenario，调用 `DataProcessor` 把每个 scenario 转成模型训练用的 `.npz` 样本，并生成训练样本列表 `diffusion_planner_training.json`。

整体数据流如下：

```text
nuPlan raw db + maps
    -> NuPlanScenarioBuilder
    -> ScenarioFilter
    -> scenarios
    -> DataProcessor.work()
    -> 每个 scenario 保存为一个 .npz
    -> diffusion_planner_training.json
    -> train_predictor.py / DiffusionPlannerData
```

## 入口位置

源码位置：

```text
data_process.py
```

相关核心实现：

```text
diffusion_planner/data_process/data_processor.py
diffusion_planner/data_process/agent_process.py
diffusion_planner/data_process/ego_process.py
diffusion_planner/data_process/map_process.py
diffusion_planner/data_process/utils.py
```

## 运行方式

README 中建议通过 `data_process.sh` 运行：

```bash
python data_process.py \
  --data_path $NUPLAN_DATA_PATH \
  --map_path $NUPLAN_MAP_PATH \
  --save_path $TRAIN_SET_PATH \
  --total_scenarios 1000000
```

也可以直接手动运行，例如：

```bash
python data_process.py \
  --data_path /data/nuplan-v1.1/trainval \
  --map_path /data/nuplan-v1.1/maps \
  --save_path ./cache \
  --total_scenarios 100
```

运行前需要先安装并配置好 `nuplan-devkit`，并且本地要有 nuPlan 数据库和地图文件。

## 命令行参数

`data_process.py` 使用 `argparse` 定义预处理参数。

| 参数 | 默认值 | 作用 |
| --- | --- | --- |
| `--data_path` | `/data/nuplan-v1.1/trainval` | nuPlan 原始数据库路径 |
| `--map_path` | `/data/nuplan-v1.1/maps` | nuPlan 地图路径 |
| `--save_path` | `./cache` | 预处理后 `.npz` 文件保存目录 |
| `--scenarios_per_type` | `None` | 每种 scenario type 最多取多少个 |
| `--total_scenarios` | `10` | 总 scenario 数量限制 |
| `--shuffle_scenarios` | `True` | 是否打乱 scenario |
| `--agent_num` | `32` | 保留的动态 agent 数量 |
| `--static_objects_num` | `5` | 保留的静态物体数量 |
| `--lane_len` | `20` | 每条 lane polyline 的采样点数 |
| `--lane_num` | `70` | 保留的 lane 数量 |
| `--route_len` | `20` | 每条 route lane 的采样点数 |
| `--route_num` | `25` | 保留的 route lane 数量 |

这些参数后续会传给 `DataProcessor(args)`，用于控制输出张量的固定尺寸。

## get_filter_parameters()

`get_filter_parameters()` 用来组装 nuPlan `ScenarioFilter` 的参数。

```python
def get_filter_parameters(
    num_scenarios_per_type=None,
    limit_total_scenarios=None,
    shuffle=True,
    scenario_tokens=None,
    log_names=None,
):
```

它返回的是一组位置参数，直接传给：

```python
ScenarioFilter(*get_filter_parameters(...))
```

当前代码里主要启用的过滤条件是：

| 字段 | 当前逻辑 |
| --- | --- |
| `scenario_tokens` | 默认不指定，除非调用方传入 |
| `log_names` | 从 `nuplan_train.json` 读取，只处理训练 log |
| `num_scenarios_per_type` | 来自 `--scenarios_per_type` |
| `limit_total_scenarios` | 来自 `--total_scenarios` |
| `shuffle` | 来自 `--shuffle_scenarios` |
| `expand_scenarios` | 固定为 `True` |
| `remove_invalid_goals` | 固定为 `False` |

其他过滤条件例如 `scenario_types`、`map_names`、`timestamp_threshold_s`、`ego_displacement_minimum_m` 等都被设为 `None`，表示不额外限制。

注意：文件中导入了 `ScenarioMapping`，但当前没有使用。

## 主流程

`if __name__ == "__main__":` 下面是完整执行流程。

### 1. 解析参数

```python
args = parser.parse_args()
```

解析后的 `args` 会同时用于：

- 构建 nuPlan scenario builder/filter
- 初始化 `DataProcessor`
- 控制输出样本的固定尺寸

### 2. 创建保存目录

```python
os.makedirs(args.save_path, exist_ok=True)
```

如果 `--save_path` 不存在，会自动创建。

### 3. 读取训练 log 列表

```python
with open('./nuplan_train.json', "r", encoding="utf-8") as file:
    log_names = json.load(file)
```

`nuplan_train.json` 是一个很大的 JSON 文件，里面记录了训练集 log 名称。代码通过 `log_names` 限制只预处理训练数据。

### 4. 构建 NuPlanScenarioBuilder

```python
map_version = "nuplan-maps-v1.0"
builder = NuPlanScenarioBuilder(
    args.data_path,
    args.map_path,
    sensor_root,
    db_files,
    map_version,
)
```

这里 `sensor_root = None`，`db_files = None`，表示让 builder 根据 `data_path` 下的数据自行发现数据库文件。地图版本固定为 `nuplan-maps-v1.0`。

### 5. 构建 ScenarioFilter

```python
scenario_filter = ScenarioFilter(
    *get_filter_parameters(
        args.scenarios_per_type,
        args.total_scenarios,
        args.shuffle_scenarios,
        log_names=log_names,
    )
)
```

这个 filter 决定最终会取哪些 scenario。项目默认通过 `nuplan_train.json` 限定训练 log，再通过 `--total_scenarios` 控制总数量。

### 6. 并行获取 scenarios

```python
worker = SingleMachineParallelExecutor(use_process_pool=True)
scenarios = builder.get_scenarios(scenario_filter, worker)
```

`SingleMachineParallelExecutor(use_process_pool=True)` 会使用本机多进程加速 scenario 构建。构建结束后打印：

```python
print(f"Total number of scenarios: {len(scenarios)}")
```

### 7. 调用 DataProcessor 处理 scenario

```python
processor = DataProcessor(args)
processor.work(scenarios)
```

真正的数据转换发生在 `DataProcessor.work()` 中。`data_process.py` 本身不直接处理 ego、agent、map，只负责把 scenarios 交给 `DataProcessor`。

### 8. 生成训练样本列表

```python
npz_files = [f for f in os.listdir(args.save_path) if f.endswith('.npz')]

with open('./diffusion_planner_training.json', 'w') as json_file:
    json.dump(npz_files, json_file, indent=4)
```

预处理完成后，代码会扫描 `save_path` 下所有 `.npz` 文件，把文件名写入根目录的 `diffusion_planner_training.json`。

训练时 `DiffusionPlannerData` 会读取这个 JSON 列表，并从 `train_set` 目录中加载对应 `.npz`：

```python
train_set = DiffusionPlannerData(
    args.train_set,
    args.train_set_list,
    args.agent_num,
    args.predicted_neighbor_num,
    args.future_len,
)
```

## DataProcessor.work() 做了什么

`DataProcessor.work(scenarios)` 会遍历每个 scenario，并保存一个 `.npz`。

单个 scenario 的处理逻辑可以拆成五步：

```text
1. 取当前 ego pose 作为局部坐标系 anchor
2. 处理 ego 历史和动态/静态障碍物
3. 查询并处理局部矢量地图
4. 处理 ego 和 neighbor 的未来轨迹标签
5. 保存为 .npz
```

### 1. 当前 ego 作为 anchor

```python
ego_state = scenario.initial_ego_state
anchor_ego_state = np.array([
    ego_state.rear_axle.x,
    ego_state.rear_axle.y,
    ego_state.rear_axle.heading,
], dtype=np.float64)
```

后续大部分坐标都会转换到这个 ego-centric 坐标系下，也就是以当前 ego rear axle 为原点，以当前 heading 为朝向。

### 2. 处理历史 ego 和 agent

ego 历史：

```python
ego_agent_past, time_stamps_past = get_ego_past_array_from_scenario(...)
```

默认配置来自 `DataProcessor.__init__()`：

```python
self.past_time_horizon = 2
self.num_past_poses = 10 * self.past_time_horizon
```

也就是取过去 2 秒、20 个历史采样点，加上当前帧后总共 21 帧。

动态 agent：

```python
past_tracked_objects = [...]
sampled_past_observations = past_tracked_objects + [present_tracked_objects]
neighbor_agents_past, neighbor_agents_types = sampled_tracked_objects_to_array_list(...)
```

只保留三类动态目标：

- `VEHICLE`
- `PEDESTRIAN`
- `BICYCLE`

随后调用：

```python
agent_past_process(...)
```

它会完成：

- 把 agent 坐标转到 ego-centric 坐标系
- 对历史缺失帧做 padding
- 按当前距离 ego 的远近选择最多 `agent_num` 个 agent
- 限制 pedestrian/bicycle 的数量，避免非车辆目标占满 slots
- 给 agent 添加 one-hot 类型编码

输出的 `neighbor_agents_past` 形状大致为：

```text
[agent_num, 21, 11]
```

最后一维含义：

```text
x, y, cos(heading), sin(heading), vx, vy, width, length, type_vehicle, type_pedestrian, type_bicycle
```

静态物体也在 `agent_past_process()` 中处理。它会保留最近的 `static_objects_num` 个静态物体，并添加类型 one-hot。

`static_objects` 形状大致为：

```text
[static_objects_num, 10]
```

最后一维含义：

```text
x, y, cos(heading), sin(heading), width, length, type_czone_sign, type_barrier, type_traffic_cone, type_generic_object
```

### 3. 处理地图

先取 route roadblock 和当前交通灯：

```python
route_roadblock_ids = scenario.get_route_roadblock_ids()
traffic_light_data = list(scenario.get_traffic_light_status_at_iteration(0))
```

如果 route 非空，则调用：

```python
route_roadblock_correction(...)
```

用于修正不连续 route。

然后查询 ego 周围半径 100 米内的矢量地图：

```python
coords, traffic_light_data, speed_limit, lane_route = get_neighbor_vector_set_map(...)
```

`DataProcessor` 中定义的地图特征：

```python
self._map_features = [
    'LANE',
    'LEFT_BOUNDARY',
    'RIGHT_BOUNDARY',
    'ROUTE_LANES',
]
```

其中真正从 map API 查询的是 lane/lane connector 的：

- baseline path
- left boundary
- right boundary
- speed limit
- traffic light encoding
- roadblock id

再调用：

```python
vector_map = map_process(...)
```

`map_process()` 会做：

- 按离 ego 的距离排序 lane
- 截断或 padding 到固定 `lane_num`
- 每条 lane 插值到固定 `lane_len`
- 转换到 ego-centric 坐标系
- 组合 lane center、方向向量、左右边界向量、交通灯状态
- 根据 route roadblock 生成 `route_lanes`

主要输出字段：

| 字段 | 默认形状 | 含义 |
| --- | --- | --- |
| `lanes` | `[70, 20, 12]` | 周围 lane 特征 |
| `lanes_speed_limit` | `[70, 1]` | lane 限速 |
| `lanes_has_speed_limit` | `[70, 1]` | lane 是否有限速 |
| `route_lanes` | `[25, 20, 12]` | route 上的 lane 特征 |
| `route_lanes_speed_limit` | `[25, 1]` | route lane 限速 |
| `route_lanes_has_speed_limit` | `[25, 1]` | route lane 是否有限速 |

`lanes` / `route_lanes` 最后一维 12 个特征来自：

```text
center_x, center_y,
direction_x, direction_y,
left_boundary_dx, left_boundary_dy,
right_boundary_dx, right_boundary_dy,
traffic_green, traffic_yellow, traffic_red, traffic_unknown
```

### 4. 处理未来轨迹标签

ego future：

```python
ego_agent_future = get_ego_future_array_from_scenario(...)
```

默认取未来 8 秒、80 个采样点：

```python
self.future_time_horizon = 8
self.num_future_poses = 10 * self.future_time_horizon
```

`ego_agent_future` 形状大致为：

```text
[80, 3]
```

最后一维是：

```text
x, y, heading
```

neighbor future：

```python
future_tracked_objects = [...]
neighbor_agents_future = agent_future_process(...)
```

它会根据历史阶段选中的 `neighbor_indices` 对齐未来 agent，保证 `neighbor_agents_past[i]` 和 `neighbor_agents_future[i]` 对应同一个 agent slot。

`neighbor_agents_future` 形状大致为：

```text
[agent_num, 80, 3]
```

最后一维也是：

```text
x, y, heading
```

如果某个 agent 的未来不存在，则对应位置为 0。

### 5. 计算 ego 当前状态

```python
ego_current_state = calculate_additional_ego_states(
    ego_agent_past,
    time_stamps_past,
)
```

输出形状为：

```text
[10]
```

含义：

```text
x, y, cos(heading), sin(heading), vx, vy, ax, ay, steering_angle, yaw_rate
```

训练时模型主要使用其中前 4 维作为当前 ego 状态。

### 6. 保存样本

每个 scenario 最终保存为：

```python
np.savez(f"{dir}/{data['map_name']}_{data['token']}.npz", **data)
```

文件名格式：

```text
{map_name}_{scenario_token}.npz
```

## 单个 .npz 的字段

每个 `.npz` 中包含以下主要字段：

| 字段 | 默认形状 | 说明 |
| --- | --- | --- |
| `map_name` | scalar/string | 地图名称 |
| `token` | scalar/string | scenario token |
| `ego_current_state` | `[10]` | ego 当前状态 |
| `ego_agent_future` | `[80, 3]` | ego 未来轨迹标签 |
| `neighbor_agents_past` | `[32, 21, 11]` | 周围动态 agent 历史 |
| `neighbor_agents_future` | `[32, 80, 3]` | 周围动态 agent 未来标签 |
| `static_objects` | `[5, 10]` | 静态物体 |
| `lanes` | `[70, 20, 12]` | 局部 lane 特征 |
| `lanes_speed_limit` | `[70, 1]` | lane 限速 |
| `lanes_has_speed_limit` | `[70, 1]` | lane 是否有限速 |
| `route_lanes` | `[25, 20, 12]` | route lane 特征 |
| `route_lanes_speed_limit` | `[25, 1]` | route lane 限速 |
| `route_lanes_has_speed_limit` | `[25, 1]` | route lane 是否有限速 |

这些字段后续由 `diffusion_planner/utils/dataset.py` 读取。

## 和训练代码的关系

训练入口 `train_predictor.py` 中会使用：

```python
train_set = DiffusionPlannerData(
    args.train_set,
    args.train_set_list,
    args.agent_num,
    args.predicted_neighbor_num,
    args.future_len,
)
```

其中：

- `args.train_set` 对应 `data_process.py --save_path`
- `args.train_set_list` 对应 `diffusion_planner_training.json`

`DiffusionPlannerData.__getitem__()` 会读取 `.npz`，返回训练需要的字段：

```text
ego_current_state
ego_future_gt
neighbor_agents_past
neighbors_future_gt
lanes
lanes_speed_limit
lanes_has_speed_limit
route_lanes
route_lanes_speed_limit
route_lanes_has_speed_limit
static_objects
```

然后 `train_epoch.py` 会把这些字段整理成模型输入，并把未来轨迹标签传给 `diffusion_loss_func()`。

## 坐标系约定

预处理后的主要几何量都在当前 ego 坐标系下：

- 原点：当前时刻 ego rear axle
- 朝向：当前时刻 ego heading
- 过去轨迹、未来轨迹、周车、静态物体、lane 坐标都会转换到该坐标系

这样模型不需要直接学习全局地图坐标，而是学习以当前自车为中心的局部规划问题。

## 注意事项

1. `data_process.py` 依赖 nuPlan devkit，不能只安装 `requirements_torch.txt`。
2. `nuplan_train.json` 必须存在于项目根目录，否则无法读取训练 log 列表。
3. 输出的 `diffusion_planner_training.json` 固定写在项目根目录，不在 `save_path` 下。
4. 默认 `--total_scenarios=10`，如果想大规模训练，需要显式改大，例如脚本里的 `1000000`。
5. `--shuffle_scenarios` 使用 `type=bool`，命令行中传字符串时要小心，`argparse` 的 `bool("False")` 仍然可能被当成 `True`。实际使用时建议不传该参数，或改代码使用更严格的 boolean parser。
6. 预处理会保存大量 `.npz` 文件，`save_path` 需要有足够磁盘空间。

## 函数输入输出数据结构速查

这一节专门补充 `data_process.py` 中函数和主流程关键调用的输入、输出结构。

### get_filter_parameters()

```python
def get_filter_parameters(
    num_scenarios_per_type=None,
    limit_total_scenarios=None,
    shuffle=True,
    scenario_tokens=None,
    log_names=None,
):
```

输入数据结构：

| 参数 | 数据结构 | 含义 |
|---|---|---|
| `num_scenarios_per_type` | `None` 或 `int` | 每种 scenario type 最多保留多少个场景；`None` 表示不限制 |
| `limit_total_scenarios` | `None`、`int` 或 `float` | 总场景数量限制；`int` 表示数量，`float` 通常表示比例 |
| `shuffle` | `bool` | 是否打乱筛选后的 scenario 顺序 |
| `scenario_tokens` | `None` 或 `List[str]` | 只保留指定 scenario token；`None` 表示不过滤 token |
| `log_names` | `None` 或 `List[str]` | 只保留指定 log 文件中的 scenarios；本项目从 `nuplan_train.json` 读取 |

输出数据结构：

| 返回位置 | 返回值 | 数据结构 | 含义 |
|---|---|---|---|
| 0 | `scenario_types` | `None` 或 `List[str]` | 场景类型过滤条件；源码中固定为 `None` |
| 1 | `scenario_tokens` | `None` 或 `List[str]` | scenario token 过滤条件 |
| 2 | `log_names` | `None` 或 `List[str]` | log 名称过滤条件 |
| 3 | `map_names` | `None` 或 `List[str]` | 地图名称过滤条件；源码中固定为 `None` |
| 4 | `num_scenarios_per_type` | `None` 或 `int` | 每类场景数量限制 |
| 5 | `limit_total_scenarios` | `None`、`int` 或 `float` | 总场景数量限制 |
| 6 | `timestamp_threshold_s` | `None` 或 `float` | 初始 lidar 时间戳间隔过滤阈值；源码中固定为 `None` |
| 7 | `ego_displacement_minimum_m` | `None` 或 `float` | 自车最小位移过滤阈值；源码中固定为 `None` |
| 8 | `expand_scenarios` | `bool` | 是否展开 multi-sample scenario；源码中固定为 `True` |
| 9 | `remove_invalid_goals` | `bool` | 是否移除 mission goal 无效的场景；源码中固定为 `False` |
| 10 | `shuffle` | `bool` | 是否打乱场景 |
| 11 | `ego_start_speed_threshold` | `None` 或 `float` | 起步速度过滤阈值；源码中固定为 `None` |
| 12 | `ego_stop_speed_threshold` | `None` 或 `float` | 停车速度过滤阈值；源码中固定为 `None` |
| 13 | `speed_noise_tolerance` | `None` 或 `float` | 速度噪声容忍阈值；源码中固定为 `None` |

这个返回值不是字典，而是一个 14 项 tuple，后面通过 `*get_filter_parameters(...)` 直接展开给 `ScenarioFilter`：

```python
scenario_filter = ScenarioFilter(*get_filter_parameters(...))
```

### __main__ 主流程

`data_process.py` 的主流程没有封装成函数，但它也是这个文件最重要的执行入口。

输入数据结构：

| 输入来源 | 数据结构 | 含义 |
|---|---|---|
| 命令行参数 `args.data_path` | `str` | nuPlan 原始数据库目录，例如 `/data/nuplan-v1.1/trainval` |
| 命令行参数 `args.map_path` | `str` | nuPlan 地图目录，例如 `/data/nuplan-v1.1/maps` |
| 命令行参数 `args.save_path` | `str` | `.npz` 缓存输出目录 |
| 命令行参数 `args.agent_num` | `int` | 每个样本最多保留的动态 agent 数量 |
| 命令行参数 `args.static_objects_num` | `int` | 每个样本最多保留的静态目标数量 |
| 命令行参数 `args.lane_num` / `args.lane_len` | `int` / `int` | lane 数量和每条 lane 采样点数 |
| 命令行参数 `args.route_num` / `args.route_len` | `int` / `int` | route lane 数量和每条 route lane 采样点数 |
| `nuplan_train.json` | `List[str]` | 训练用 log name 列表 |
| `NuPlanScenarioBuilder.get_scenarios(...)` | `List[AbstractScenario]` | 经过 `ScenarioFilter` 过滤后的 nuPlan scenario 对象列表 |

输出数据结构：

| 输出位置 | 数据结构 | 含义 |
|---|---|---|
| `args.save_path/*.npz` | 多个 `.npz` 文件 | 每个文件对应一个处理后的 scenario 样本 |
| `diffusion_planner_training.json` | `List[str]` | 所有 `.npz` 文件名列表，供训练数据集读取 |

单个 `.npz` 样本的主要字段结构：

| 字段 | 数据结构 | 含义 |
|---|---|---|
| `ego_current_state` | `np.ndarray`，形状 `[10]` | 当前自车状态，包含 `x,y,cos_h,sin_h,vx,vy,ax,ay,steering_angle,yaw_rate` |
| `ego_agent_future` | `np.ndarray`，形状 `[num_future_poses, 3]` | 自车未来轨迹标签，字段为相对 `x,y,heading` |
| `neighbor_agents_past` | `np.ndarray`，形状 `[agent_num, num_past_frames, 11]` | 动态 agent 历史输入，含状态 8 维和类别 one-hot 3 维 |
| `neighbor_agents_future` | `np.ndarray`，形状 `[agent_num, num_future_frames, 3]` | 被选中动态 agent 的未来轨迹标签 |
| `static_objects` | `np.ndarray`，形状 `[static_objects_num, 10]` | 静态目标输入，含状态 6 维和类别 one-hot 4 维 |
| `lanes` | `np.ndarray`，形状 `[lane_num, lane_len, 12]` | 附近 lane 特征 |
| `route_lanes` | `np.ndarray`，形状 `[route_num, route_len, 12]` | 导航 route 上的 lane 特征 |
| `lanes_speed_limit` / `route_lanes_speed_limit` | `np.ndarray` | lane 和 route lane 限速值 |
| `lanes_has_speed_limit` / `route_lanes_has_speed_limit` | `np.ndarray`，`bool` | lane 和 route lane 是否有限速 |
