# diffusion_planner/data_process/roadblock_utils.py 详解

本文档详细解释 `diffusion_planner/data_process/roadblock_utils.py` 的类、函数、变量和调用关系。这个文件主要负责 **修正 nuPlan route roadblock 序列**，让后续地图处理能稳定得到 route lane 特征。

在本项目的数据链路里，`roadblock_utils.py` 位于地图特征处理之前：

```text
DataProcessor.work() / DataProcessor.observation_adapter()
    -> route_roadblock_correction()
    -> get_neighbor_vector_set_map()
    -> map_process()
    -> route_lanes
```

`route_roadblock_correction()` 输出修正后的 `route_roadblock_ids`，后续 `map_process()` 会根据这些 id 判断哪些 lane 在 route 上，并生成模型输入字段：

```text
route_lanes
route_lanes_speed_limit
route_lanes_has_speed_limit
```

## 文件位置

```text
diffusion_planner/data_process/roadblock_utils.py
```

直接调用位置：

```python
# diffusion_planner/data_process/data_processor.py
from diffusion_planner.data_process.roadblock_utils import route_roadblock_correction
```

使用位置一，闭环仿真/推理：

```python

    ego_state, map_api, route_roadblock_ids
)
```

使用位置二，离线训练数据预处理：

```python
route_roadblock_ids = scenario.get_route_roadblock_ids()

if route_roadblock_ids != ['']:
    route_roadblock_ids = route_roadblock_correction(
        ego_state, map_api, route_roadblock_ids

```

## normalize_angle()

函数定义：

```python
def normalize_angle(angle: np.ndarray):
    return (angle + np.pi) % (2 * np.pi) - np.pi
```

作用：把角度归一化到：

```text
[-pi, pi)
```

它用于计算 ego heading 和 lane heading 的差值，避免角度跨越 `pi/-pi` 时误差异常。

例子：

```text
angle = 3.5 rad
normalize_angle(3.5) ≈ -2.783 rad
```

调用位置：

```python
heading_error = np.abs(
    normalize_angle(lane_discrete_path[argmin].heading - ego_pose.heading)
)
```

这里比较的是：

```text
离 ego 最近的 lane path 点的 heading
-
ego 当前 heading
```

归一化后再取绝对值，得到合理的 heading error。

## BreadthFirstSearchRoadBlock

类定义：

```python
class BreadthFirstSearchRoadBlock:
```

这是一个在 roadblock 图上做 BFS 的工具类。它可以沿驾驶方向搜索，也可以反向搜索。

roadblock 图的边来自 nuPlan map object：

```python
current_edge.outgoing_edges
current_edge.incoming_edges
```

其中：

- `outgoing_edges` 表示沿 route/驾驶方向的后继 roadblock。
- `incoming_edges` 表示反方向的前驱 roadblock。

### __init__()

函数定义：

```python
def __init__(
    self,
    start_roadblock_id: int,
    map_api: Optional[AbstractMap],
    forward_search: str = True,
):
```

参数：

| 参数 | 含义 |
| --- | --- |
| `start_roadblock_id` | BFS 起点 roadblock id |
| `map_api` | nuPlan 地图 API |
| `forward_search` | 是否沿 `outgoing_edges` 搜索；否则沿 `incoming_edges` 搜索 |

初始化代码：

```python
self._map_api = map_api
self._queue = deque([self.id_to_roadblock(start_roadblock_id), None])
self._parent = dict()
self._forward_search = forward_search
self._target_roadblock_ids = None
```

重要变量：

| 变量 | 作用 |
| --- | --- |
| `self._map_api` | 用于根据 id 取 roadblock object |
| `self._queue` | BFS 队列，初始包含起点和一个 `None` 分层哨兵 |
| `self._parent` | 记录 BFS 路径回溯关系 |
| `self._forward_search` | 决定使用 `outgoing_edges` 还是 `incoming_edges` |
| `self._target_roadblock_ids` | 搜索目标 id 列表，在 `search()` 中设置 |

`None` 哨兵用于标记 BFS 深度层级结束。每遇到一个 `None`，说明当前深度处理完了，`depth += 1`。

### id_to_roadblock()

函数定义：

```python
def id_to_roadblock(self, id: str) -> RoadBlockGraphEdgeMapObject:
```

作用：根据 id 从 map API 中取 roadblock 或 roadblock connector。

代码：

```python
block = self._map_api._get_roadblock(id)
block = block or self._map_api._get_roadblock_connector(id)
return block
```

它先尝试：

```python
self._map_api._get_roadblock(id)
```

如果拿不到，再尝试：

```python
self._map_api._get_roadblock_connector(id)
```

注意：这里使用的是 nuPlan map API 的私有方法 `_get_roadblock()` 和 `_get_roadblock_connector()`。当前项目依赖这个实现细节。

### search()

函数定义：

```python
def search(
    self,
    target_roadblock_id: Union[str, List[str]],
    max_depth: int,
) -> Tuple[List[RoadBlockGraphEdgeMapObject], bool]:
```

参数：

| 参数 | 含义 |
| --- | --- |
| `target_roadblock_id` | 目标 roadblock id，支持单个字符串或字符串列表 |
| `max_depth` | BFS 最大搜索深度 |

返回：

```text
((path, path_id), path_found)
```

其中：

| 返回项 | 含义 |
| --- | --- |
| `path` | `RoadBlockGraphEdgeMapObject` 列表 |
| `path_id` | 与 `path` 对应的 roadblock id 列表 |
| `path_found` | 是否真的找到了目标 |

虽然类型注解写的是 `Tuple[List[RoadBlockGraphEdgeMapObject], bool]`，但实际 `_construct_path()` 返回 `(path, path_id)`，所以实际调用通常是：

```python
(path, path_id), path_found = graph_search.search(...)
```

#### 第一步：统一 target 格式

```python
if isinstance(target_roadblock_id, str):
    target_roadblock_id = [target_roadblock_id]
self._target_roadblock_ids = target_roadblock_id
```

如果传入单个 id，包装成 list，方便后面统一判断：

```python
current_edge.id in self._target_roadblock_ids
```

#### 第二步：初始化 BFS 状态

```python
start_edge = self._queue[0]

path_found = False
end_edge = start_edge
end_depth = 1
depth = 1

self._parent[start_edge.id + f"_{depth}"] = None
```

`self._parent` 的 key 不是简单的 roadblock id，而是：

```text
{roadblock_id}_{depth}
```

这是因为 roadblock 图中可能存在环，同一个 id 可能在不同深度被访问到。加上 depth 可以避免简单 key 冲突。

#### 第三步：循环弹出队列

```python
while self._queue:
    current_edge = self._queue.popleft()
```

每次从队列左侧取一个元素。

#### 第四步：检查深度是否超过 max_depth

```python
if self._check_end_condition(depth, max_depth):
    break
```

`_check_end_condition()` 实际逻辑是：

```python
return depth > max_depth
```

超过最大深度后停止搜索。

#### 第五步：处理 None 分层哨兵

```python
if current_edge is None:
    depth += 1
    self._queue.append(None)
    if self._queue[0] is None:
        break
    continue
```

含义：

1. 如果当前弹出的是 `None`，说明上一层已经处理完。
2. `depth += 1`，进入下一层。
3. 再向队尾追加一个 `None`，用于标记下一层结束。
4. 如果队首也是 `None`，说明没有更多真实节点，搜索结束。

#### 第六步：检查是否到达目标

```python
if self._check_goal_condition(current_edge, depth, max_depth):
    end_edge = current_edge
    end_depth = depth
    path_found = True
    break
```

`_check_goal_condition()` 的逻辑是：

```python
return current_edge.id in self._target_roadblock_ids and depth <= max_depth
```

只要当前 roadblock id 在目标列表里，并且深度不超过限制，就认为找到了路径。

#### 第七步：选择邻居方向

```python
neighbors = (
    current_edge.outgoing_edges if self._forward_search else current_edge.incoming_edges
)
```

如果 `forward_search=True`：

```text
沿 outgoing_edges 搜索
```

如果 `forward_search=False`：

```text
沿 incoming_edges 反向搜索
```

#### 第八步：扩展邻居并记录 parent

```python
for next_edge in neighbors:
    self._queue.append(next_edge)
    self._parent[next_edge.id + f"_{depth + 1}"] = current_edge
    end_edge = next_edge
    end_depth = depth + 1
```

每个邻居都进入队列，并记录它的父节点是当前 roadblock。

这里没有显式 visited set，所以在有环图里可能重复入队；搜索依赖 `max_depth` 限制避免无限扩张。

#### 第九步：构造路径

```python
return self._construct_path(end_edge, end_depth), path_found
```

即使 `path_found=False`，也会返回一条从 `end_edge` 回溯出来的路径。但调用方通常只有在 `path_found=True` 时使用它。

### _construct_path()

函数定义：

```python
def _construct_path(
    self,
    end_edge: RoadBlockGraphEdgeMapObject,
    depth: int,
) -> List[RoadBlockGraphEdgeMapObject]:
```

实际返回：

```text
(path, path_id)
```

代码步骤：

```python
path = [end_edge]
path_id = [end_edge.id]
```

从终点开始。

```python
while self._parent[end_edge.id + f"_{depth}"] is not None:
    path.append(self._parent[end_edge.id + f"_{depth}"])
    path_id.append(path[-1].id)
    end_edge = self._parent[end_edge.id + f"_{depth}"]
    depth -= 1
```

沿 `self._parent` 一直回溯到起点。

```python
if self._forward_search:
    path.reverse()
    path_id.reverse()
```

如果是正向搜索，回溯得到的是终点到起点，需要 reverse 成起点到终点。

如果是反向搜索，当前代码不 reverse。这样在 `route_roadblock_correction()` 的 Fix 1 中，反向搜索结果可以直接插到 route 开头。

## get_current_roadblock_candidates()

函数定义：

```python
def get_current_roadblock_candidates(
    ego_state: EgoState,
    map_api: AbstractMap,
    route_roadblocks_dict: Dict[str, RoadBlockGraphEdgeMapObject],
    heading_error_thresh: float = np.pi / 4,
    displacement_error_thresh: float = 3,
) -> Tuple[RoadBlockGraphEdgeMapObject, List[RoadBlockGraphEdgeMapObject]]:
```

作用：判断 ego 当前最可能位于哪个 roadblock 上，并返回候选 roadblocks。

参数：

| 参数 | 含义 |
| --- | --- |
| `ego_state` | 当前 ego 状态 |
| `map_api` | nuPlan 地图 API |
| `route_roadblocks_dict` | 当前 route id 到 roadblock object 的字典 |
| `heading_error_thresh` | heading 误差阈值，默认 `pi/4` |
| `displacement_error_thresh` | 距离误差阈值，默认 3 米 |

返回：

```text
(best_candidate, candidates)
```

其中：

- `best_candidate` 是最可信的当前 roadblock。
- `candidates` 是候选 roadblock 列表。

### 第一步：取 ego rear axle 位姿

```python
ego_pose: StateSE2 = ego_state.rear_axle
```

这里仍然使用 rear axle，而不是 vehicle center。

### 第二步：在 ego 附近 1 米内找 roadblock

```python
layers = [SemanticMapLayer.ROADBLOCK, SemanticMapLayer.ROADBLOCK_CONNECTOR]
roadblock_dict = map_api.get_proximal_map_objects(
    point=ego_pose.point, radius=1.0, layers=layers
)
roadblock_candidates = (
    roadblock_dict[SemanticMapLayer.ROADBLOCK]
    + roadblock_dict[SemanticMapLayer.ROADBLOCK_CONNECTOR]
)
```

先查 ego 周围半径 1 米内的：

- `ROADBLOCK`
- `ROADBLOCK_CONNECTOR`

这一步得到初始候选。

### 第三步：如果附近没有 roadblock，则找最近 roadblock

```python
if not roadblock_candidates:
    for layer in layers:
        roadblock_id_, distance = map_api.get_distance_to_nearest_map_object(
            point=ego_pose.point, layer=layer
        )
        roadblock = map_api.get_map_object(roadblock_id_, layer)

        if roadblock:
            roadblock_candidates.append(roadblock)
```

如果 1 米内查不到，就分别从 `ROADBLOCK` 和 `ROADBLOCK_CONNECTOR` 层找最近对象。

变量 `distance` 被接收但没有使用。

### 第四步：初始化候选容器

```python
on_route_candidates, on_route_candidate_displacement_errors = [], []
candidates, candidate_displacement_errors = [], []

roadblock_displacement_errors = []
roadblock_heading_errors = []
```

含义：

| 变量 | 含义 |
| --- | --- |
| `on_route_candidates` | 满足阈值且在当前 route 上的候选 |
| `on_route_candidate_displacement_errors` | 对应的距离误差 |
| `candidates` | 满足阈值但不在 route 上的候选 |
| `candidate_displacement_errors` | 对应的距离误差 |
| `roadblock_displacement_errors` | 每个 roadblock 的最小距离误差，兜底使用 |
| `roadblock_heading_errors` | 每个 roadblock 的最小 heading 误差，当前只记录未用于返回 |

### 第五步：遍历候选 roadblock 的 interior_edges

```python
for idx, roadblock in enumerate(roadblock_candidates):
    lane_displacement_error, lane_heading_error = np.inf, np.inf

    for lane in roadblock.interior_edges:
        lane_discrete_path = lane.baseline_path.discrete_path
```

每个 roadblock 内部有若干 lane edge，代码通过 lane baseline path 判断 ego 更接近哪条 lane。

### 第六步：计算 ego 到 lane path 的最近点

```python
lane_discrete_points = np.array(
    [state.point.array for state in lane_discrete_path], dtype=np.float64
)
lane_state_distances = (
    (lane_discrete_points - ego_pose.point.array[None, ...]) ** 2.0
).sum(axis=-1) ** 0.5
argmin = np.argmin(lane_state_distances)
```

这里做了：

1. 把 lane baseline path 上每个 `StateSE2` 的 point 取成 numpy 数组。
2. 计算 ego point 到每个 lane path 点的欧氏距离。
3. 找到最近点下标 `argmin`。

### 第七步：计算 heading error 和 displacement error

```python
heading_error = np.abs(
    normalize_angle(lane_discrete_path[argmin].heading - ego_pose.heading)
)
displacement_error = lane_state_distances[argmin]
```

`displacement_error` 是 ego 到 lane 最近离散点的距离。

`heading_error` 是 lane 最近点 heading 和 ego heading 的角度误差。

### 第八步：记录当前 roadblock 的最小误差

```python
if displacement_error < lane_displacement_error:
    lane_heading_error, lane_displacement_error = (
        heading_error,
        displacement_error,
    )
```

对一个 roadblock 的所有 interior lanes，记录最小距离误差及其对应 heading error。

### 第九步：根据阈值筛选候选

```python
if (
    heading_error < heading_error_thresh
    and displacement_error < displacement_error_thresh
):
    if roadblock.id in route_roadblocks_dict.keys():
        on_route_candidates.append(roadblock)
        on_route_candidate_displacement_errors.append(displacement_error)
    else:
        candidates.append(roadblock)
        candidate_displacement_errors.append(displacement_error)
```

只有同时满足：

```text
heading_error < pi/4
displacement_error < 3m
```

才会进入可信候选。

如果 roadblock id 在 `route_roadblocks_dict` 中，优先放入 `on_route_candidates`。

否则放入普通 `candidates`。

### 第十步：返回最优候选

优先级：

1. 如果存在 on-route 候选，返回距离误差最小的 on-route roadblock。
2. 否则如果存在普通候选，返回距离误差最小的普通 roadblock。
3. 否则返回所有 `roadblock_candidates` 中距离误差最小的 roadblock。

代码：

```python
if on_route_candidates:
    return (
        on_route_candidates[np.argmin(on_route_candidate_displacement_errors)],
        on_route_candidates,
    )
elif candidates:
    return candidates[np.argmin(candidate_displacement_errors)], candidates

return (
    roadblock_candidates[np.argmin(roadblock_displacement_errors)],
    roadblock_candidates,
)
```

这一步体现了一个策略：**如果 ego 当前可能在 route 上，就优先相信 route 上的 roadblock**。

## route_roadblock_correction()

函数定义：

```python
def route_roadblock_correction(
    ego_state: EgoState,
    map_api: AbstractMap,
    route_roadblock_ids: List[str],
    search_depth_backward: int = 15,
    search_depth_forward: int = 30,
) -> List[str]:
```

这是本文件的主入口函数。作用是修正 route roadblock id 序列。

参数：

| 参数 | 含义 |
| --- | --- |
| `ego_state` | 当前 ego 状态 |
| `map_api` | nuPlan 地图 API |
| `route_roadblock_ids` | 原始 route roadblock id 序列 |
| `search_depth_backward` | 反向 BFS 最大深度，默认 15 |
| `search_depth_forward` | 正向 BFS 最大深度，默认 30 |

输出：

```text
修正后的 route_roadblock_ids
```

它分成三个修正步骤：

```text
Fix 1: ego 起点不在 route 上时，把当前 roadblock 和原 route 接起来
Fix 2: route 中相邻 roadblock 不连通时，用 BFS 补齐中间 roadblock
Fix 3: 如果 route 形成 loop，裁剪 loop 后面的部分
```

### 第一步：把 route id 转成 roadblock object

```python
route_roadblock_dict = {}
for id_ in route_roadblock_ids:
    block = map_api.get_map_object(id_, SemanticMapLayer.ROADBLOCK)
    block = block or map_api.get_map_object(
        id_, SemanticMapLayer.ROADBLOCK_CONNECTOR
    )
    route_roadblock_dict[id_] = block
```

对每个 id：

1. 先按 `ROADBLOCK` 查。
2. 查不到再按 `ROADBLOCK_CONNECTOR` 查。
3. 保存到 `route_roadblock_dict`。

此处不会过滤 `block is None` 的情况。如果某个 id 无法解析，后续访问 `.incoming_edges` 等属性时可能出错。

### 第二步：识别 ego 当前 roadblock

```python
starting_block, starting_block_candidates = get_current_roadblock_candidates(
    ego_state, map_api, route_roadblock_dict
)
starting_block_ids = [roadblock.id for roadblock in starting_block_candidates]
```

`starting_block` 是当前 ego 最可能所在 roadblock。

`starting_block_candidates` 是当前 ego 所在 roadblock 候选集合。

后续 Fix 1 会判断：

```python
if starting_block.id not in route_roadblock_ids:
```

如果当前 ego 不在 route 上，就尝试修正 route 起点。

### 第三步：准备 route list

```python
route_roadblocks = list(route_roadblock_dict.values())
route_roadblock_ids = list(route_roadblock_dict.keys())
```

之后代码同时维护：

```text
route_roadblocks: roadblock object 列表
route_roadblock_ids: roadblock id 列表
```

这两个列表必须保持同样顺序。

## Fix 1：ego 起点不在 route 上

代码入口：

```python
if starting_block.id not in route_roadblock_ids:
```

这种情况表示：

```text
ego 当前所在 roadblock 不在原始 route_roadblock_ids 中
```

常见原因可能是 route 起点缺失、ego 初始位置略偏离 route、route 中间断开等。

### Fix 1A：从原 route 第一个 block 反向搜到 ego 当前 block

代码：

```python
graph_search = BreadthFirstSearchRoadBlock(
    route_roadblock_ids[0], map_api, forward_search=False
)
(path, path_id), path_found = graph_search.search(
    starting_block_ids, max_depth=search_depth_backward
)
```

含义：

```text
从原 route 的第一个 roadblock 出发，沿 incoming_edges 反向搜索，
看能否找到 ego 当前所在 roadblock 候选。
```

如果找到了：

```python
route_roadblocks[:0] = path[:-1]
route_roadblock_ids[:0] = path_id[:-1]
```

把搜索路径插到 route 开头。

为什么是 `path[:-1]`？

因为 `path` 最后一项通常已经是原 route 第一个 block，原 route 中已有它，避免重复插入。

结果类似：

```text
原 route:        [R3, R4, R5]
反向找到路径:    [R1, R2, R3]
修正后 route:    [R1, R2, R3, R4, R5]
```

### Fix 1B：如果反向失败，从 ego 当前 block 正向搜到 route 前几个 block

代码：

```python
graph_search = BreadthFirstSearchRoadBlock(
    starting_block.id, map_api, forward_search=True
)
(path, path_id), path_found = graph_search.search(
    route_roadblock_ids[:3], max_depth=search_depth_forward
)
```

含义：

```text
从 ego 当前所在 roadblock 出发，沿 outgoing_edges 正向搜索，
看能否连到原 route 的前三个 roadblock 之一。
```

为什么只搜 `route_roadblock_ids[:3]`？

这是一个启发式策略：优先尝试接回原 route 开头附近，避免连接到后面太远的位置导致 route 被大幅截断。

如果找到：

```python
end_roadblock_idx = np.argmax(
    np.array(route_roadblock_ids) == path_id[-1]
)

route_roadblocks = route_roadblocks[end_roadblock_idx + 1 :]
route_roadblock_ids = route_roadblock_ids[end_roadblock_idx + 1 :]

route_roadblocks[:0] = path
route_roadblock_ids[:0] = path_id
```

分步骤解释：

1. `path_id[-1]` 是搜索路径接上的原 route roadblock。
2. `end_roadblock_idx` 找到这个 id 在原 route 中的位置。
3. 删除原 route 中从开头到该 id 的部分。
4. 把从当前 ego block 到该 id 的路径插到 route 开头。

结果类似：

```text
原 route:      [R3, R4, R5, R6]
ego 当前:      R1
正向路径:      [R1, R2, R3]
删除原前缀:    [R4, R5, R6]
修正后:        [R1, R2, R3, R4, R5, R6]
```

## Fix 2：补齐不连通的相邻 roadblocks

代码入口：

```python
roadblocks_to_append = {}
for i in range(len(route_roadblocks) - 1):
    next_incoming_block_ids = [
        _roadblock.id for _roadblock in route_roadblocks[i + 1].incoming_edges
    ]
    is_incoming = route_roadblock_ids[i] in next_incoming_block_ids

    if is_incoming:
        continue
```

对 route 中每一对相邻 roadblock：

```text
route_roadblocks[i] -> route_roadblocks[i + 1]
```

检查 `route_roadblocks[i]` 是否在下一个 block 的 `incoming_edges` 中。

如果在，说明二者连通，跳过。

如果不在，说明 route 断了，需要搜索中间缺失 roadblocks。

### 搜索中间路径

```python
graph_search = BreadthFirstSearchRoadBlock(
    route_roadblock_ids[i], map_api, forward_search=True
)
(path, path_id), path_found = graph_search.search(
    route_roadblock_ids[i + 1], max_depth=search_depth_forward
)
```

含义：

```text
从当前 roadblock 正向搜索到下一个 route roadblock。
```

如果找到，并且路径长度至少为 3：

```python
if path_found and path and len(path) >= 3:
    path, path_id = path[1:-1], path_id[1:-1]
    roadblocks_to_append[i] = (path, path_id)
```

为什么 `len(path) >= 3`？

只有当路径至少包含：

```text
[起点, 中间点, 终点]
```

才说明确实有中间缺失 roadblock 需要插入。

为什么 `path[1:-1]`？

起点和终点已经存在于原 route 中，只需要插入中间缺失部分。

### 插入缺失 roadblocks

```python
offset = 1
for i, (path, path_id) in roadblocks_to_append.items():
    route_roadblocks[i + offset : i + offset] = path
    route_roadblock_ids[i + offset : i + offset] = path_id
    offset += len(path)
```

这里用 `offset` 是因为每插入一批中间 roadblocks，后续原始索引都会向后移动。

例子：

```text
原 route: [R1, R4]
BFS path: [R1, R2, R3, R4]
插入:     [R2, R3]
结果:     [R1, R2, R3, R4]
```

## Fix 3：裁剪 route loop

代码：

```python
route_roadblocks, route_roadblock_ids = remove_route_loops(
    route_roadblocks, route_roadblock_ids
)
```

这个函数会检查 route 中的 roadblock connector polygon 是否和前面出现过的 connector polygon 有明显重叠。如果有，认为 route 形成了 loop，然后裁剪 loop 起点之后的部分。

最后：

```python
return route_roadblock_ids
```

`route_roadblock_correction()` 只返回 id 列表，不返回 roadblock object。

## remove_route_loops()

函数定义：

```python
def remove_route_loops(
    route_roadblocks: List[RoadBlockGraphEdgeMapObject],
    route_roadblock_ids: List[str],
) -> Tuple[List[str], List[RoadBlockGraphEdgeMapObject]]:
```

实际返回顺序是：

```python
return route_roadblocks, route_roadblock_ids
```

也就是说类型注解/文档中的返回说明和实际顺序不完全一致。调用方按实际顺序使用：

```python
route_roadblocks, route_roadblock_ids = remove_route_loops(...)
```

### 变量初始化

```python
roadblock_occupancy_map = None
loop_idx = None
```

| 变量 | 含义 |
| --- | --- |
| `roadblock_occupancy_map` | 已经过的 connector polygon 空间索引 |
| `loop_idx` | 检测到 loop 的位置 |

### 遍历 route roadblocks

```python
for idx, roadblock in enumerate(route_roadblocks):
```

只检查 roadblock connector：

```python
if str(roadblock.__class__.__name__) == "NuPlanRoadBlockConnector":
```

注释解释了原因：

```text
loops only occur at intersection, thus searching for roadblock-connectors.
```

即 route loop 通常发生在路口连接段，所以只检查 connector polygon。

### 第一个 connector：初始化空间索引

```python
if not roadblock_occupancy_map:
    roadblock_occupancy_map = STRTreeOccupancyMapFactory.get_from_geometry(
        [roadblock.polygon], [roadblock.id]
    )
    continue
```

第一次遇到 connector 时，用它的 polygon 初始化 occupancy map。

### 后续 connector：查询是否和已有 connector 重叠

```python
strtree, index_by_id = roadblock_occupancy_map._build_strtree()
indices = strtree.query(roadblock.polygon)
```

这里构建 STRtree 空间索引，并查询当前 connector polygon 可能和哪些已有 polygon 相交。

`index_by_id` 被接收但没有使用。

如果存在候选相交 geometry：

```python
if len(indices) > 0:
    for geom in strtree.geometries.take(indices):
        area = geom.intersection(roadblock.polygon).area
        if area > 1:
            loop_idx = idx
            break
    if loop_idx:
        break
```

分步骤解释：

1. 遍历所有可能相交的旧 connector polygon。
2. 计算旧 polygon 和当前 polygon 的 intersection area。
3. 如果重叠面积大于 1，认为发生 loop。
4. 记录当前索引 `loop_idx` 并停止遍历。

如果没有发现 loop，则把当前 connector 放入 occupancy map：

```python
roadblock_occupancy_map.insert(roadblock.id, roadblock.polygon)
```

### 裁剪 route

```python
if loop_idx:
    route_roadblocks = route_roadblocks[:loop_idx]
    route_roadblock_ids = route_roadblock_ids[:loop_idx]
```

如果检测到 loop，则保留 loop 之前的 route，去掉从 `loop_idx` 开始的后续部分。

注意：这里判断条件是 `if loop_idx:`，如果 `loop_idx == 0` 不会触发。但由于第一个 connector 只用于初始化且会 `continue`，实际 loop_idx 通常不会是 0。

## 一个简化例子

假设原始 route 是：

```text
route_roadblock_ids = [R3, R5, R6]
```

当前 ego 实际在：

```text
R1
```

地图图结构为：

```text
R1 -> R2 -> R3 -> R4 -> R5 -> R6
```

`route_roadblock_correction()` 会做：

1. `get_current_roadblock_candidates()` 判断 ego 在 `R1`。
2. `R1` 不在原始 route `[R3, R5, R6]`，进入 Fix 1。
3. 正向 BFS 从 `R1` 搜到原 route 前三个之一，找到路径 `[R1, R2, R3]`。
4. 把 `[R1, R2, R3]` 接到 route 前面，并去掉重复前缀，得到 `[R1, R2, R3, R5, R6]`。
5. Fix 2 检查 `R3 -> R5` 不连通，于是 BFS 找到 `[R3, R4, R5]`，插入中间 `R4`。
6. 得到 `[R1, R2, R3, R4, R5, R6]`。
7. Fix 3 检查是否有 loop，没有则返回。

最终输出：

```text
[R1, R2, R3, R4, R5, R6]
```

后续 `map_process()` 会用这个修正后的 route 判断哪些局部 lane 属于 route。

## 和 map_process() 的关系

`map_process()` 中，每条 lane 会有一个 `lane_route`，也就是该 lane 所属 roadblock id。

`route_roadblock_correction()` 输出的 `route_roadblock_ids` 会参与：

```python
pruned_lane_roadblock_ids = [route for route in route_roadblock_ids if route in lane_routes]
pruned_route_roadblock_ids = _prune_route_by_connectivity(route_roadblock_ids, pruned_lane_roadblock_ids)
```

然后：

```python
for route in lane_routes:
    lane_on_route.append(route in pruned_route_roadblock_ids)
```

最后 route lane 被填入：

```python
vector_map_route_lanes
route_lanes_speed_limit
route_lanes_has_speed_limit
```

所以 `roadblock_utils.py` 的目的不是直接生成模型输入，而是先把 route id 序列修好，让 `map_process()` 能正确筛选 route 上的 lanes。

## 注意事项

1. `BreadthFirstSearchRoadBlock.search()` 没有 visited set，依赖 `max_depth` 控制搜索规模。
2. `id_to_roadblock()` 使用 nuPlan map API 的私有方法 `_get_roadblock()` 和 `_get_roadblock_connector()`。
3. `route_roadblock_correction()` 假设输入 `route_roadblock_ids` 非空；如果传入空列表，访问 `route_roadblock_ids[0]` 会出错。
4. `remove_route_loops()` 的类型注解返回顺序和实际返回顺序不一致，实际返回是 `(route_roadblocks, route_roadblock_ids)`。
5. `get_current_roadblock_candidates()` 中 `roadblock_heading_errors` 和最近对象查询返回的 `distance` 当前没有用于最终逻辑。
