# 碰撞规避引导代码原理详解

> 面向初学者的阅读文档：从车辆矩形包围盒、分离轴投影、有符号距离，到扩散模型采样阶段的可微分碰撞规避引导。

---

## 0. 先说结论：这份代码是做什么的？

这份代码并不是一个完整的轨迹规划器，也不是一个底层车辆控制器。

它实现的是一个**碰撞规避引导函数**：

```python
collision_guidance_fn(...)
```

它接收扩散模型当前正在处理的一批带噪轨迹，检查自车未来轨迹是否会靠近或碰撞邻居车辆，然后计算一个梯度方向，使扩散模型在后续去噪过程中倾向于生成更安全的轨迹。

可以把整个流程理解为：

```text
扩散模型当前生成的带噪轨迹
        │
        ▼
把自车和邻居车辆表示成矩形包围盒
        │
        ▼
计算自车与邻居车辆之间的有符号距离
        │
        ▼
距离越近，碰撞风险越大，奖励越低
        │
        ▼
对奖励关于自车位置求梯度
        │
        ▼
得到“怎样移动轨迹可以减小碰撞风险”的方向
        │
        ▼
将梯度转换到车辆局部坐标系
        │
        ▼
关闭纵向分量，只保留并平滑横向避让分量
        │
        ▼
重新构造一个便于扩散模型使用的引导奖励
```

在自动驾驶场景中，可以把它理解为：

> 当扩散模型生成的候选轨迹可能撞车时，这个函数会给轨迹施加一个“向侧面避让”的引导信号。

因为初学者先理解“矩形如何构造”，再理解“矩形距离如何计算”，最后理解“整个引导函数如何组合这些模块”，会更加自然。

# 第二部分：为什么要使用矩形包围盒？

## 2. 车辆不能只看作一个点

假设两辆车的中心点没有重合，并不代表它们一定没有碰撞。

车辆具有长度和宽度。如果只使用中心点距离，可能出现以下问题：

```text
车辆 A 中心点 ---------------- 车辆 B 中心点

中心点仍有距离，但车头与车尾已经相撞。
```

因此，代码将每辆车近似为一个带方向的矩形：

```text
                车辆航向
                  ↑
        ┌──────────────────┐
        │                  │
        │        •         │
        │      中心点       │
        └──────────────────┘
```

矩形需要以下信息：

$$
(x,y,	heta,l,w)
$$

其中：

| 符号 | 含义 |
|---|---|
| $x,y$ | 矩形中心坐标 |
| $\theta$ | 航向角 |
| $l$ | 车辆长度 |
| $w$ | 车辆宽度 |

代码没有直接保存 $\theta$，而是保存：

$$
(\cos\theta,\sin\theta)
$$

因此，一个矩形由六个量表示：

$$
(x,y,\cos\theta,\sin\theta,l,w)
$$

---

## 3. 为什么使用包围盒膨胀？

代码设置：

```python
INFLATION = 1.0
```

并执行：

```python
lw.unsqueeze(2).expand(-1, -1, T, -1) + INFLATION
```

这表示车辆长度和宽度都会增加 `1.0` 米。

例如，原始尺寸为：

$$
l=5.0,\qquad w=2.0
$$

膨胀后为：

$$
l'=6.0,\qquad w'=3.0
$$

需要注意：

> 长度增加 `1.0` 米，并不表示车辆前后分别增加 `1.0` 米，而是前后各增加 `0.5` 米。

同理，宽度增加 `1.0` 米，表示左右各增加 `0.5` 米。

这样做会让碰撞检测更加保守：即使车辆尚未真正接触，也会提前产生避让倾向。

## 6. `COG_TO_REAR`

```python
COG_TO_REAR = 1.67
```

模型轨迹中的位置参考点不一定是车辆几何中心。

例如，车辆轨迹可能以**后轴中心**为参考点，但矩形碰撞检测通常更适合使用车辆几何中心附近的位置。

代码执行：

```python
ego_pred[..., 0:1] + cos_h * COG_TO_REAR
ego_pred[..., 1:2] + sin_h * COG_TO_REAR
```

对应公式：

$$
x_{\text{center}}=x_{\text{ref}}+\cos\theta\cdot d
$$

$$
y_{\text{center}}=y_{\text{ref}}+\sin\theta\cdot d
$$

其中：

$$
d=1.67
$$

也就是说，代码沿车辆朝向向前平移 `1.67` 米。

变量名称 `COG_TO_REAR` 的字面含义可能让人困惑。结合实际加法操作，更准确的理解是：

> 当前轨迹参考点可能位于车辆后部附近；为了构造碰撞矩形，需要沿航向向前移动到车辆中心附近。

# 第四部分：将中心形式矩形转换为四个顶点

## 8. `center_rect_to_points()` 的作用

函数定义：

```python
def center_rect_to_points(rect):
```

输入：

```text
rect: [B, 6]
```

其中每一行为：

$$
(x,y,\cos\theta,\sin\theta,l,w)
$$

输出：

```text
[B, 4, 2]
```

表示每个矩形的四个二维顶点。

---

## 9. 拆分输入

```python
xy, cos_h, sin_h, lw = rect[:, :2], rect[:, 2], rect[:, 3], rect[:, 4:]
```

形状如下：

| 变量 | 形状 | 含义 |
|---|---:|---|
| `xy` | `[B, 2]` | 中心坐标 $(x,y)$ |
| `cos_h` | `[B]` | $\cos\theta$ |
| `sin_h` | `[B]` | $\sin\theta$ |
| `lw` | `[B, 2]` | 长度和宽度 $(l,w)$ |

---

## 10. 构造旋转矩阵

```python
rot = torch.stack([cos_h, -sin_h, sin_h, cos_h], dim=1).reshape(-1, 2, 2)
```

每个车辆对应一个旋转矩阵：

$$
R(\theta)
=
\begin{bmatrix}
\cos\theta&-\sin\theta\\
\sin\theta&\cos\theta
\end{bmatrix}
$$

它用于将车辆局部坐标系中的顶点偏移旋转到全局坐标系。

---

## 11. 构造局部坐标系下的四个顶点

```python
lw = torch.einsum(
    'bj,ij->bij',
    lw,
    torch.tensor([[1., 1], [-1, 1], [-1, -1], [1, -1]], device=lw.device) / 2
)
```

对于长度为 $l$、宽度为 $w$ 的矩形，四个局部顶点为：

$$
\left(\frac{l}{2},\frac{w}{2}\right)
$$

$$
\left(-\frac{l}{2},\frac{w}{2}\right)
$$

$$
\left(-\frac{l}{2},-\frac{w}{2}\right)
$$

$$
\left(\frac{l}{2},-\frac{w}{2}\right)
$$

可以想象为：

```text
局部坐标系：

          y_local
             ↑
 (-l/2,w/2)  │  (l/2,w/2)
       ●──────┼──────●
       │      │      │
───────┼──────┼──────┼────→ x_local
       │      │      │
       ●──────┼──────●
(-l/2,-w/2)  │  (l/2,-w/2)
```

---

## 12. 将局部顶点旋转到全局坐标系

```python
lw = torch.einsum('bij,bkj->bik', lw, rot)
```

本质上执行：

$$
p_{\text{rotated}}=R(\theta)p_{\text{local}}
$$

旋转后，矩形会与车辆航向保持一致。

---

## 13. 加上车辆中心坐标

```python
rect = xy[:, None, :] + lw
```

本质上执行：

$$
p_{\text{global}}=p_{\text{center}}+p_{\text{rotated}}
$$

输出形状：

```text
[B, 4, 2]
```

---

## 14. 一个简单例子

假设：

$$
x=10,\qquad y=5
$$

$$
\theta=0
$$

$$
l=4,\qquad w=2
$$

因为：

$$
\cos\theta=1,\qquad\sin\theta=0
$$

矩形没有旋转。

四个局部顶点为：

$$
(2,1),\quad(-2,1),\quad(-2,-1),\quad(2,-1)
$$

加上中心点 $(10,5)$ 后，得到：

$$
(12,6),\quad(8,6),\quad(8,4),\quad(12,4)
$$

# 第五部分：批量计算矩形有符号距离

## 15. `batch_signed_distance_rect()` 的作用

函数定义：

```python
def batch_signed_distance_rect(rect1, rect2):
```

输入：

```text
rect1: [B, 4, 2]
rect2: [B, 4, 2]
```

输出：

```text
[B]
```

每个数值表示一对矩形之间的有符号距离。

符号约定：

| 距离 | 含义 |
|---:|---|
| `distance > 0` | 两个矩形分离 |
| `distance = 0` | 两个矩形边界接触 |
| `distance < 0` | 两个矩形重叠 |

---

## 16. 什么是分离轴定理？

判断两个凸多边形是否相交，可以使用分离轴定理：

> 如果存在至少一条轴，使得两个多边形投影到该轴后的区间完全分离，那么两个多边形不相交。

反过来说：

> 如果在所有候选轴上，两个投影区间都重叠，那么两个矩形相交。

对于二维矩形，只需要检查两个矩形各自的两个局部方向，共四个候选轴。

---

## 17. 构造候选轴

```python
norm_vec = torch.stack([
    rect1[:, 0] - rect1[:, 1],
    rect1[:, 1] - rect1[:, 2],
    rect2[:, 0] - rect2[:, 1],
    rect2[:, 1] - rect2[:, 2]
], dim=1)
```

输出形状：

```text
[B, 4, 2]
```

每个矩形提取两条相邻边：

```text
矩形 1：两条相邻边方向
矩形 2：两条相邻边方向
```

合计四个方向。

变量名称叫作：

```python
norm_vec
```

但这里保存的并不是显式计算的法向量，而是边方向向量。

为什么仍然可用？

因为矩形相邻边互相垂直。某条边方向与另一条相邻边的法向方向平行。因此，两条相邻边方向构成的集合足以完成矩形投影检测。

---

## 18. 将候选轴归一化

```python
norm_vec = norm_vec / torch.norm(norm_vec, dim=2, keepdim=True)
```

如果轴向量为：

$$
a=(a_x,a_y)
$$

归一化后：

$$
\hat{a}
=
\frac{a}{\|a\|}
$$

归一化的原因是：

> 只有使用单位向量，投影区间之间的差值才具有真实空间距离尺度。

---

## 19. 将矩形顶点投影到候选轴

```python
proj1 = torch.einsum('bij,bkj->bik', norm_vec, rect1)
proj2 = torch.einsum('bij,bkj->bik', norm_vec, rect2)
```

投影本质是点积：

$$
\operatorname{projection}(p,\hat{a})
=
\hat{a}^{\mathsf T}p
$$

每个矩形有四个顶点，每一对矩形有四条候选轴，因此输出形状为：

```text
[B, 4, 4]
```

三个维度分别表示：

```text
[批次, 候选轴, 顶点]
```

---

## 20. 获得每条轴上的投影区间

```python
proj1_min, proj1_max = proj1.min(dim=2)[0], proj1.max(dim=2)[0]
proj2_min, proj2_max = proj2.min(dim=2)[0], proj2.max(dim=2)[0]
```

矩形在一条轴上的投影可以用区间表示：

$$
[m_{\min},m_{\max}]
$$

例如：

```text
矩形 1 投影区间：[1, 4]
矩形 2 投影区间：[6, 8]
```

此时两个区间分离，间隔为：

$$
6-4=2
$$

---

## 21. 计算两个方向上的区间差值

```python
overlap = torch.cat([
    proj1_min - proj2_max,
    proj2_min - proj1_max
], dim=1)
```

对于每条候选轴，计算两种方向：

$$
d_1=m_{1,\min}-m_{2,\max}
$$

$$
d_2=m_{2,\min}-m_{1,\max}
$$

如果区间分离，至少有一个值大于或等于零。

如果区间严格重叠，两个值都小于零。

---

## 22. 一个区间投影例子

### 22.1 区间分离

假设：

$$
I_1=[1,4]
$$

$$
I_2=[6,8]
$$

则：

$$
d_1=1-8=-7
$$

$$
d_2=6-4=2
$$

存在正数 `2`，说明两个区间分离，间距为 `2`。

### 22.2 区间重叠

假设：

$$
I_1=[1,5]
$$

$$
I_2=[4,8]
$$

则：

$$
d_1=1-8=-7
$$

$$
d_2=4-5=-1
$$

两个值都为负数，说明两个区间重叠。

其中最接近零的负数为：

$$
-1
$$

它表示最小穿透程度。

---

## 23. 判断矩形是否重叠

```python
is_overlap = (overlap < 0).all(dim=1)
```

只有当所有候选轴上的投影都重叠时，两个矩形才真正重叠。

这正是分离轴定理的应用。

---

## 24. 返回有符号距离

```python
positive_distance = torch.where(overlap < 0, 1e5, overlap)

distance = torch.where(
    is_overlap,
    overlap.max(dim=1).values,
    positive_distance.min(dim=1).values
)
```

### 24.1 两个矩形重叠时

取：

```python
overlap.max(dim=1).values
```

因为所有值都为负数，最大值是最接近零的负数。

它表示最小穿透深度的负值。

### 24.2 两个矩形分离时

将负值替换为大数：

```python
1e5
```

再取最小非负间隔。

---

## 25. 这个距离是否是严格欧氏距离？

不一定。

当矩形沿某个候选轴方向分离时，该结果具有清晰的距离含义。

但当矩形沿对角线方向分离时，代码返回的是候选投影轴上的最小间隔，不一定等于两个矩形之间严格的欧氏最短距离。

因此，更准确的说法是：

> 该函数返回一个适合碰撞检测和梯度引导的、有符号的分离轴距离代理量。

它足以用于判断是否重叠，并构造避碰引导，但不要将它误认为通用几何库中的精确矩形欧氏距离。

# 第六部分：`collision_guidance_fn()` 总体结构

## 26. 函数的用途

```python
def collision_guidance_fn(x, t, cond, inputs, *args, **kwargs) -> torch.Tensor:
```

该函数根据扩散模型正在生成的轨迹，返回一个奖励值。

外部求解器可以继续对这个奖励关于轨迹求梯度，将梯度作为引导信号。

可以将它理解为：

$$
R(x)=\text{轨迹安全程度}
$$

希望轨迹朝着使奖励增大的方向变化：

$$
\nabla_xR(x)
$$

---

## 27. 参数含义

| 参数 | 含义 |
|---|---|
| `x` | 当前扩散状态下的轨迹张量 |
| `t` | 当前扩散时间 |
| `cond` | 为兼容引导接口保留的条件参数；当前函数中没有直接使用 |
| `inputs` | 额外场景信息，例如邻居车辆掩码和历史状态 |
| `*args, **kwargs` | 为兼容不同调用方式保留的额外参数 |

函数文档字符串写道：

```python
x: [B * Pn+1, T + 1, 4]
```

但实际代码执行：

```python
B, P, T, _ = x.shape
```

因此，函数实际期望的输入更接近：

```text
[B, P, T_all, 4]
```

其中：

| 维度 | 含义 |
|---|---|
| `B` | 批次大小 |
| `P` | 车辆总数，通常为 `1 + Pn` |
| `T_all` | 包含当前时刻的轨迹点数量 |
| `4` | 状态维度 $(x,y,\cos\theta,\sin\theta)$ |

第 `0` 辆车是自车，剩余车辆是邻居车辆。

# 第七部分：扩散时间门控

## 28. 只在特定扩散时间范围启用碰撞引导

```python
mask_diffusion_time = (t < 0.1 and t > 0.005)
```

引导只在以下区间生效：

$$
0.005<t<0.1
$$

随后：

```python
x = torch.where(mask_diffusion_time, x, x.detach())
```

### 28.1 `detach()` 是什么意思？

PyTorch 中：

```python
x.detach()
```

不会改变张量数值，但会切断梯度传播路径。

因此：

- 当时间位于目标区间时，梯度正常传播；
- 当时间位于目标区间外时，轨迹数值仍然相同，但引导梯度被关闭。

### 28.2 为什么不是所有时间都引导？

扩散采样早期，轨迹仍然非常嘈杂，过早施加几何约束可能不稳定。

扩散采样末期，轨迹已经接近定型，过强调整也可能破坏结果。

因此，作者只在某一段时间窗口中启用碰撞引导。

# 第八部分：航向归一化与梯度隔离

## 29. 只让梯度直接调整位置

```python
x = torch.cat([
    x[:, :, :, :2],
    x[:, :, :, 2:].detach() / torch.norm(
        x[:, :, :, 2:].detach(),
        dim=-1,
        keepdim=True
    )
], dim=-1)
```

状态最后两个分量表示航向向量：

$$
(\cos\theta,\sin\theta)
$$

代码做了两件事：

1. 使用 `detach()` 切断航向分量的梯度；
2. 将航向向量归一化为单位向量。

归一化公式：

$$
\hat{h}
=
\frac{h}{\|h\|}
$$

这样可以避免航向向量长度偏离 `1`。

为什么切断航向梯度？

> 碰撞引导主要通过移动自车轨迹位置实现横向避让，而不是直接通过碰撞梯度任意改变车辆航向表示。

航向仍参与包围盒构造和坐标变换，但不直接接收该引导路径的梯度。

# 第十二部分：从距离构造碰撞风险

## 40. 风险函数

```python
clip_distances = torch.maximum(
    1 - distances / CLIP_DISTANCE,
    torch.tensor(0.0, device=distances.device)
)
```

数学形式为：

$$
c(d)
=
\max\left(1-\frac{d}{D},0\right)
$$

其中：

$$
D=\text{CLIP\_DISTANCE}=1.0
$$

---

## 41. 不同距离对应什么风险？

当：

$$
D=1
$$

风险函数变成：

$$
c(d)=\max(1-d,0)
$$

| 距离 $d$ | 风险 $c(d)$ | 含义 |
|---:|---:|---|
| $d\geq1$ | $0$ | 距离足够远，不施加惩罚 |
| $0<d<1$ | $0<c(d)<1$ | 尚未碰撞，但距离较近 |
| $d=0$ | $1$ | 刚好接触 |
| $d<0$ | $c(d)>1$ | 已经发生矩形重叠 |

例如：

| 距离 | 风险 |
|---:|---:|
| `2.0` | `0.0` |
| `0.8` | `0.2` |
| `0.2` | `0.8` |
| `0.0` | `1.0` |
| `-0.5` | `1.5` |

---

## 42. 为什么将重叠风险和近距离风险分开统计？

代码将风险分为两组：

```python
clip_distances > 1
```

以及：

```python
clip_distances <= 1
```

其中：

- `> 1` 对应已经发生重叠；
- `<= 1` 对应接触、近距离或远距离。

随后分别求平均，再相加：

```python
reward = - (
    overlap_risk_mean + near_risk_mean
).exp()
```

数学上可近似写为：

$$
R_{\text{raw}}
=
-\exp
\left(
\overline{c}_{\text{overlap}}
+
\overline{c}_{\text{near}}
\right)
$$

这里：

- 风险越大；
- 指数项越大；
- 奖励越负。

因此，安全轨迹的奖励更高。

---

## 43. 为什么使用指数函数？

指数函数会放大较大的风险：

$$
\exp(z)
$$

随着 $z$ 增大增长很快。

这意味着：

> 严重碰撞不会只比轻微接近多一点点惩罚，而会获得明显更强的惩罚梯度。

这里计算：

$$

然后只保留：

```python

```

即：

- 所有时间点；
- 前两个状态分量：全局位置 $(x,y)$。

输出形状近似为：


---

## 45. 梯度的直观含义

假设某个未来时刻，自车轨迹点过于靠近邻车。

对奖励关于自车位置求梯度后，会得到一个二维向量：

$$
\nabla_{(x,y)}R
$$

它指向：

> 让奖励增大的位置变化方向。

由于碰撞越严重奖励越低，所以该方向通常会将自车轨迹从邻居车辆附近推开。

# 第十四部分：为什么转换到车辆局部坐标系？

## 46. 全局坐标系不方便区分纵向和横向

在全局坐标系中，一个二维梯度是：

$$
(g_x,g_y)
$$

但自动驾驶更关心：

- 沿车辆朝向前后移动多少；
- 沿车辆侧向左右移动多少。

也就是：

$$
(g_{\text{longitudinal}},g_{\text{lateral}})
$$

因此，需要将梯度转换到车辆局部坐标系。

---

## 47. 构造全局到局部旋转矩阵

```python
x_mat = torch.einsum(
    "btd,nd->btn",
    x[:, 0, :, 2:],
    torch.tensor([
        [1., 0],
        [0, 1],
        [0, -1],
        [1, 0]
    ], device=x.device)
).reshape(B, T, 2, 2)
```

每个时间点构造矩阵：

$$
R(-\theta)
=
\begin{bmatrix}
\cos\theta&\sin\theta\\
-\sin\theta&\cos\theta
\end{bmatrix}
$$

该矩阵将全局坐标向量转换到车辆局部坐标：

$$
g_{\text{local}}
=
R(-\theta)g_{\text{global}}
$$

---

## 48. 执行坐标转换

```python
x_aux = torch.einsum("btij,btj->bti", x_mat, x_aux)
```

得到：

```text
[B, T, 2]
```

其中：

| 分量 | 含义 |
|---:|---|
| `x_aux[..., 0]` | 局部纵向引导 |
| `x_aux[..., 1]` | 局部横向引导 |

# 第十五部分：只保留横向避让

## 49. 纵向引导被人为关闭

代码中纵向分量最终乘以：

```python
* 0
```

完整片段：

```python
torch.einsum(
    "bt,it->bi",
    x_aux[..., 0],
    torch.tril(
        (-torch.linspace(0, 1, T, device=x.device)).exp()
        .unsqueeze(0)
        .repeat(T, 1)
    )
) * 0
```

无论前面算出什么结果，乘以零后都变为：

$$
g_{\text{longitudinal}}=0
$$

这意味着：

> 当前碰撞引导不会通过减速、加速或纵向移动来避碰，只会提供横向避让方向。

这可能是作者有意做出的设计选择，例如：

- 将纵向速度控制交给其他模块；
- 避免碰撞引导导致轨迹沿纵向剧烈缩短或拉伸；
- 强调变道或侧向绕行行为。

---

## 50. 为什么仍然保留纵向计算代码？

虽然最后乘以零，但代码仍保留了纵向聚合公式。

可能原因包括：

- 方便后续实验重新开启纵向引导；
- 作者曾经测试过该分支；
- 保留完整结构便于调参。

如果未来希望启用纵向引导，可以重点检查这一部分。

# 第十六部分：横向梯度的时间平滑

## 51. 为什么需要平滑？

如果逐时间点独立使用碰撞梯度，可能出现：

```text
时刻 1：向左
时刻 2：向右
时刻 3：向左
时刻 4：向右
```

这样生成的轨迹会出现不自然的高频抖动。

因此，代码使用一维卷积在时间维度上平滑横向梯度。

---

## 52. 横向平滑代码

```python
F.conv1d(
    F.pad(x_aux[:, None, :, 1], (10, 10), mode='replicate'),
    torch.ones(1, 1, 21, device=x.device) * \
    (-torch.linspace(-2, 2, 21, device=x.device) ** 2 / 4).exp()
)[:, 0] * 1.0
```

---

## 53. 增加通道维度

```python
x_aux[:, None, :, 1]
```

原本横向梯度形状为：

```text
[B, T]
```

增加通道维度后：

```text
[B, 1, T]
```

这是 `conv1d()` 所要求的输入格式：

```text
[batch, channel, length]
```

---

## 54. 边缘补充

```python
F.pad(..., (10, 10), mode='replicate')
```

在时间序列左右两侧各补充 `10` 个元素。

使用：

```python
mode='replicate'
```

表示复制边缘值。

例如：

```text
原序列：       [a, b, c]
左右补 2 个：  [a, a, a, b, c, c, c]
```

这样可以使卷积后时间长度保持不变。

---

## 55. 平滑卷积核

卷积核定义为：

```python
(-torch.linspace(-2, 2, 21, device=x.device) ** 2 / 4).exp()
```

数学形式为：

$$
k(z)=\exp\left(-\frac{z^2}{4}\right)
$$

其中 $z$ 在 $[-2,2]$ 上均匀取 `21` 个点。

它类似高斯核：

```text
边缘权重较小
      ↓
▁▂▃▄▅▆▇███▇▆▅▄▃▂▁
          ↑
      中心权重较大
```

因此，相邻时刻的横向引导会相互融合。

---

## 56. 卷积核没有归一化

通常做加权平均时，会除以权重总和：

$$
\tilde{k}_i
=
\frac{k_i}{\sum_jk_j}
$$

但当前代码没有进行该操作。

因此，这里不仅会平滑梯度，也会改变梯度整体尺度。

后面的：

```python
* 1.0
```

可以看作预留的缩放系数，目前不会改变结果。

# 第十七部分：转换回全局坐标系

## 57. 将局部引导转换回全局引导

```python
x_aux = torch.einsum("btji,btj->bti", x_mat, x_aux)
```

前面使用：

$$
R(-\theta)
$$

将全局坐标转换到局部坐标。

现在使用转置矩阵：

$$
R(-\theta)^{\mathsf T}=R(\theta)
$$

将局部引导重新变回全局坐标：

$$
g_{\text{global}}
=
R(\theta)g_{\text{local}}
$$

输出：

```text
[B, T, 2]
```

# 第十八部分：为什么还要重新构造一个奖励？

## 58. 最后的线性奖励

```python
reward = torch.sum(
    x_aux.detach() * x[:, 0, :, :2],
    dim=(1, 2)
)

return 3.0 * reward
```

数学形式为：

$$
R_{\text{final}}(x)
=
3\sum_{t}
\tilde{g}_t^{\mathsf T}p_t
$$

其中：

| 符号 | 含义 |
|---|---|
| $p_t$ | 自车在时刻 $t$ 的二维位置 |
| $\tilde{g}_t$ | 经过局部坐标处理和时间平滑后的引导向量 |

注意：

```python
x_aux.detach()
```

非常关键。

它将处理后的引导向量视为常量。

因此，外部再次对最终奖励关于轨迹求梯度时：

$$
\nabla_{p_t}R_{\text{final}}
=
3\tilde{g}_t
$$

也就是说，外部求导得到的正好是作者希望注入扩散采样器的平滑横向避让方向。

---

## 59. 为什么不直接返回 `x_aux`？

很多 classifier guidance 风格的接口要求引导函数返回一个标量奖励或类似对数概率的值，然后由外层统一执行：

```python
torch.autograd.grad(log_prob.sum(), x)
```

但是这里作者希望对原始碰撞梯度进行额外加工：

- 只保留自车位置梯度；
- 转换到局部坐标系；
- 关闭纵向分量；
- 平滑横向分量；
- 转换回全局坐标系；
- 乘以强度系数。

所以作者使用了一个技巧：

```text
先在函数内部求一次原始碰撞梯度
        ↓
对梯度进行加工
        ↓
将加工后的梯度 detach
        ↓
构造一个线性标量奖励
        ↓
外层再次求梯度时，精确得到加工后的方向
```

这可以称为：

> 使用线性代理奖励重新编码加工后的梯度。

# 第十九部分：它如何接入 DPM-Solver 的引导采样？

## 60. 与 classifier guidance 的关系

在常见 DPM-Solver 包装器中，分类器引导形式类似：

$$
\epsilon_{\text{guided}}
=
\epsilon_{\theta}
-
w\sigma_t\nabla_xR(x_t)
$$

其中：

| 符号 | 含义 |
|---|---|
| $\epsilon_{\theta}$ | 原始扩散模型噪声预测 |
| $R(x_t)$ | 条件奖励或对数概率 |
| $\nabla_xR(x_t)$ | 引导梯度 |
| $w$ | 引导强度 |
| $\sigma_t$ | 当前噪声尺度 |

本文件中的：

```python
collision_guidance_fn(...)
```

可以充当某种奖励函数或 classifier guidance 函数。

它不一定是真正的分类器，但接口思想相同：

> 返回一个可求梯度的标量，使扩散轨迹向安全方向偏移。

```python
def collision_guidance_fn(x, t, inputs):
    # 只在特定扩散时间启用梯度
    x = gate_gradient_by_diffusion_time(x, t)

    # 位置保留梯度，航向只参与数值计算
    x = normalize_heading_and_detach_heading(x)

    # 分离自车与邻居车辆未来轨迹
    ego = x[:, :1, 1:, :]
    neighbors = x[:, 1:, 1:, :]

    # 将自车轨迹参考点移动到车辆中心附近
    ego = shift_ego_reference_point(ego)

    # 构造膨胀后的矩形包围盒
    bbox = build_inflated_vehicle_boxes(ego, neighbors, inputs)

    # 计算自车与邻居车辆距离
    distances = signed_rectangle_distance(bbox)

    # 距离越近，风险越高
    risk = max(1 - distances / clip_distance, 0)

    # 风险越高，奖励越低
    raw_reward = -exp(risk_summary(risk))

    # 第一次求导：获得原始避碰方向
    guide = grad(raw_reward, ego_positions)

    # 将全局梯度转换到自车局部坐标系
    guide_local = global_to_local(guide)

    # 关闭纵向引导，只保留平滑后的横向引导
    guide_local.longitudinal = 0
    guide_local.lateral = temporal_smoothing(guide_local.lateral)

    # 再转回全局坐标系
    guide_global = local_to_global(guide_local)

    # 重新包装成外部可以再次求导的线性奖励
    final_reward = sum(detach(guide_global) * ego_positions)

    return 3.0 * final_reward
```

## 64. 该函数不是直接返回轨迹

# 第二十三部分：值得重点检查的潜在问题

## 69. `t` 使用 Python 的 `and`

代码：

```python
mask_diffusion_time = (t < 0.1 and t > 0.005)
```

如果 `t` 是包含多个元素的 PyTorch 张量，Python 无法直接判断整个张量是真还是假，可能报错：

```text
RuntimeError: Boolean value of Tensor with more than one value is ambiguous
```

如果需要逐元素判断，常见写法是：

```python
mask_diffusion_time = (t < 0.1) & (t > 0.005)
```

但是否应当这样修改，还要结合上游传入的 `t` 形状确认。

当前实现可能假设 `t` 是标量或单元素张量。

---

## 70. 航向归一化存在除零风险

代码：

```python
heading / torch.norm(heading, dim=-1, keepdim=True)
```

如果某个航向向量恰好为：

$$
(0,0)
$$

分母为零，可能出现 `NaN`。

更加稳妥的写法通常会增加一个很小的数：

```python
norm = torch.norm(heading, dim=-1, keepdim=True).clamp_min(1e-6)
heading = heading / norm
```

---

## 71. 矩形轴归一化也存在除零风险

代码：

```python
norm_vec = norm_vec / torch.norm(norm_vec, dim=2, keepdim=True)
```

如果矩形长度或宽度为零，边向量可能变成零向量。

同样可考虑：

```python
axis_norm = torch.norm(norm_vec, dim=2, keepdim=True).clamp_min(1e-6)
```

---

## 72. 没有有效邻居时需要确认行为

如果：

```python
~neighbor_current_mask
```

筛选后没有任何有效邻居，则：

```python
ego_bbox
neighbor_bbox
distances
```

可能成为空张量。

某些后续 `min()`、`max()` 或自动求导操作可能无法按预期工作。

建议检查项目上游是否始终保证至少存在一个有效邻居，或者是否有专门的空邻居处理逻辑。

---

## 73. `allow_unused=True` 不代表一定安全

代码：

```python
torch.autograd.grad(..., allow_unused=True)[0]
```

如果变量完全没有参与计算，返回列表中的对应元素可能是：

```python
None
```

紧接着执行：

```python
[0][:, 0, :, :2]
```

可能报错。

当前正常路径下 `x` 会参与奖励计算，但边界场景仍值得测试。

---

## 74. 距离是代理量，不是严格欧氏距离

如前文所述，分离轴距离适合碰撞判断和引导，但不一定等于严格的矩形欧氏最短距离。

进行指标统计时，不要混淆二者。

---

## 75. 横向平滑核没有归一化

当前卷积核会改变梯度尺度。

这不一定是错误，可能是作者有意调节引导强度。

但调参时应知道：

> `3.0`、卷积核权重总和、`CLIP_DISTANCE` 和 `INFLATION` 会共同影响最终引导强度。

---

## 76. 原始风险在批次之间存在耦合

原始奖励在展平后的所有有效车辆对和时间点上统一求和与平均。

因此，一个批次中的风险统计可能影响另一个批次样本的归一化尺度。

这可能是作者有意设计，也可能需要根据训练或推理方式进一步检查。

---

## 77. 掩码语义需要与数据预处理确认

代码使用：

```python
~neighbor_current_mask
```

选择参与计算的邻居。

应当确认：

```text
True  是否确实表示无效填充？
False 是否确实表示有效车辆？
```

如果上游约定相反，筛选逻辑会完全颠倒。

# 第二十四部分：参数会如何影响行为？

## 78. `INFLATION`

```python
INFLATION = 1.0
```

| 数值变化 | 影响 |
|---|---|
| 增大 | 包围盒更大，更保守，更早避让 |
| 减小 | 包围盒更接近真实尺寸，约束更宽松 |

---

## 79. `CLIP_DISTANCE`

```python
CLIP_DISTANCE = 1.0
```

| 数值变化 | 影响 |
|---|---|
| 增大 | 更远距离就开始产生风险 |
| 减小 | 只有非常靠近时才产生风险 |

---

## 80. 返回值缩放系数

```python
return 3.0 * reward
```

| 数值变化 | 影响 |
|---|---|
| 增大 | 引导更强，避让更积极 |
| 减小 | 引导更弱，更依赖原始扩散模型 |

过强的引导可能导致：

- 轨迹不自然；
- 横向偏移过大；
- 偏离道路结构；
- 与其他规划目标冲突。

---

## 81. 引导生效时间窗口

```python
0.005 < t < 0.1
```

窗口改变会影响：

- 在扩散去噪的哪个阶段施加约束；
- 引导是否稳定；
- 轨迹是否有足够调整空间。

# 第二十八部分：最终总结

## 95. 最值得记住的内容

这份代码的核心目标是：

> 在扩散模型生成轨迹的过程中，利用车辆矩形包围盒距离构造可微分碰撞风险，并将风险梯度加工成平滑的横向避让引导。

最核心的逻辑可以浓缩为：

$$
\text{轨迹}
\rightarrow
\text{矩形包围盒}
\rightarrow
\text{有符号距离}
\rightarrow
\text{碰撞风险}
\rightarrow
\nabla_xR
\rightarrow
\text{横向平滑引导}
$$

最重要的风险函数为：

$$
c(d)
=
\max\left(1-\frac{d}{D},0\right)
$$

最重要的梯度思想为：

$$
g
=
\nabla_xR_{\text{raw}}(x)
$$

经过局部坐标变换和时间平滑后，重新构造：

$$
R_{\text{final}}(x)
=
3\sum_t\tilde{g}_t^{\mathsf T}p_t
$$

这样，外部再次求导即可得到：

$$
\nabla_xR_{\text{final}}(x)
=
3\tilde{g}
$$

一句话概括：

> 它先算出“往哪里移动可以避免碰撞”，再把这个方向处理成平滑的横向避让信号，交给扩散模型采样器使用。

# 附录 A：核心代码骨架

```python
def collision_guidance_fn(x, t, cond, inputs, *args, **kwargs):
    B, P, T, _ = x.shape

    neighbor_current_mask = inputs["neighbor_current_mask"]

    # 只在特定扩散阶段保留梯度
    mask_diffusion_time = (t < 0.1 and t > 0.005)
    x = torch.where(mask_diffusion_time, x, x.detach())

    # 位置保留梯度，航向归一化并 detach
    x = torch.cat([
        x[:, :, :, :2],
        x[:, :, :, 2:].detach() /
        torch.norm(x[:, :, :, 2:].detach(), dim=-1, keepdim=True)
    ], dim=-1)

    # 自车与邻居未来轨迹
    ego_pred = x[:, :1, 1:, :]
    cos_h, sin_h = ego_pred[..., 2:3], ego_pred[..., 3:4]
    ego_pred = torch.cat([
        ego_pred[..., 0:1] + cos_h * COG_TO_REAR,
        ego_pred[..., 1:2] + sin_h * COG_TO_REAR,
        ego_pred[..., 2:]
    ], dim=-1)

    neighbors_pred = x[:, 1:, 1:, :]
    B, Pn, T, _ = neighbors_pred.shape

    predictions = torch.cat([ego_pred, neighbors_pred.detach()], dim=1)

    # 车辆尺寸与膨胀包围盒
    lw = torch.cat([
        torch.tensor(ego_size, device=predictions.device)[None, None, :].repeat(B, 1, 1),
        inputs["neighbor_agents_past"][:, :Pn, -1, [7, 6]]
    ], dim=1)

    bbox = torch.cat([
        predictions,
        lw.unsqueeze(2).expand(-1, -1, T, -1) + INFLATION
    ], dim=-1)

    bbox = center_rect_to_points(
        bbox.reshape(-1, 6)
    ).reshape(B, Pn + 1, T, 4, 2)

    # 自车与邻居有符号距离
    ego_bbox = bbox[:, :1].expand(-1, Pn, -1, -1, -1)[~neighbor_current_mask].reshape(-1, 4, 2)
    neighbor_bbox = bbox[:, 1:][~neighbor_current_mask].reshape(-1, 4, 2)

    distances = batch_signed_distance_rect(ego_bbox, neighbor_bbox)

    # 距离转风险
    clip_distances = torch.maximum(
        1 - distances / CLIP_DISTANCE,
        torch.tensor(0.0, device=distances.device)
    )

    # 原始碰撞奖励
    reward = -(
        torch.sum(clip_distances[clip_distances > 1]) /
        (torch.sum((clip_distances[clip_distances > 1].detach() > 0).float()) + 1e-5)
        +
        torch.sum(clip_distances[clip_distances <= 1]) /
        (torch.sum((clip_distances[clip_distances <= 1].detach() > 0).float()) + 1e-5)
    ).exp()

    # 第一次求梯度
    x_aux = torch.autograd.grad(
        reward.sum(), x,
        retain_graph=True,
        allow_unused=True
    )[0][:, 0, :, :2]

    # 全局 → 局部
    T += 1
    x_mat = torch.einsum(
        "btd,nd->btn",
        x[:, 0, :, 2:],
        torch.tensor([[1., 0], [0, 1], [0, -1], [1, 0]], device=x.device)
    ).reshape(B, T, 2, 2)

    x_aux = torch.einsum("btij,btj->bti", x_mat, x_aux)

    # 纵向关闭，横向平滑
    x_aux = torch.stack([
        torch.einsum(
            "bt,it->bi",
            x_aux[..., 0],
            torch.tril((-torch.linspace(0, 1, T, device=x.device)).exp().unsqueeze(0).repeat(T, 1))
        ) * 0,
        F.conv1d(
            F.pad(x_aux[:, None, :, 1], (10, 10), mode='replicate'),
            torch.ones(1, 1, 21, device=x.device) *
            (-torch.linspace(-2, 2, 21, device=x.device) ** 2 / 4).exp()
        )[:, 0]
    ], dim=2)

    # 局部 → 全局
    x_aux = torch.einsum("btji,btj->bti", x_mat, x_aux)

    # 线性代理奖励
    reward = torch.sum(x_aux.detach() * x[:, 0, :, :2], dim=(1, 2))

    return 3.0 * reward
```
