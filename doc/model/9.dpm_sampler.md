# `dpm_sampler()` 原理详解：从随机噪声到生成轨迹

## 1. 这段代码的作用

这段代码定义了一个扩散模型采样函数：

```python
dpm_sampler(...)
```

它在**推理阶段**使用已经训练好的扩散模型，从随机噪声 `x_T` 出发，通过 DPM-Solver++ 快速执行反向扩散，最终得到生成结果。

如果该项目用于轨迹规划，可以将其理解为：

```text
随机噪声轨迹
    ↓
结合驾驶场景反复去噪
    ↓
逐渐形成合理轨迹
    ↓
输出最终轨迹样本
```

它不负责训练模型，只负责采样。

---

## 2. 原始代码

```python
from typing import Dict

import torch

import diffusion_planner.model.diffusion_utils.dpm_solver_pytorch as dpm


def dpm_sampler(
        model: torch.nn.Module, 
        x_T, 
        other_model_params: Dict={}, 
        diffusion_steps=10,
        noise_schedule_params: Dict = {},
        model_wrapper_params: Dict = {},
        dpm_solver_params: Dict = {},
        sample_params: Dict = {}
    ):

    with torch.no_grad():
        noise_schedule = dpm.NoiseScheduleVP(
            schedule='linear',
            **noise_schedule_params
        )

        model_fn = dpm.model_wrapper(
            model,
            noise_schedule,
            model_type=model.model_type,
            model_kwargs=other_model_params,
            **model_wrapper_params
        )

        dpm_solver = dpm.DPM_Solver(
            model_fn, noise_schedule, algorithm_type="dpmsolver++", **dpm_solver_params)

        sample_dpm = dpm_solver.sample(
            x_T,
            steps=diffusion_steps,
            order=2,
            skip_type="logSNR",
            method="multistep",
            denoise_to_zero=True,
            **sample_params
        )

    return sample_dpm
```

虽然函数本身很短，但它调用了三个关键组件：

```python
NoiseScheduleVP
model_wrapper
DPM_Solver
```

理解这三个组件，就理解了整段代码。

# 第一部分：必要的扩散模型基础

## 3. 前向扩散：如何把真实样本变成噪声？

扩散模型首先定义一个前向加噪公式：

$$
x_t=\alpha_t x_0+\sigma_t\epsilon
$$

其中：

| 符号 | 含义 |
|---|---|
| $x_0$ | 原始干净样本，例如真实轨迹 |
| $x_t$ | 时刻 $t$ 的带噪样本 |
| $\epsilon$ | 标准高斯噪声，$\epsilon\sim\mathcal{N}(0,I)$ |
| $\alpha_t$ | 原始信号的保留比例 |
| $\sigma_t$ | 噪声的注入比例 |

对于常见的 VP 扩散过程：

$$
\alpha_t^2+\sigma_t^2=1
$$

当 $t$ 很小时：

$$
\alpha_t\approx1,\qquad\sigma_t\approx0
$$

所以：

$$
x_t\approx x_0
$$

当 $t$ 很大时：

$$
\alpha_t\approx0,\qquad\sigma_t\approx1
$$

所以：

$$
x_t\approx\epsilon
$$

也就是说，随着时间增大，真实样本逐渐被随机噪声淹没。

---

## 4. 反向扩散：采样时做什么？

采样阶段从高噪声状态开始，反向恢复样本：

$$
x_T\rightarrow x_{t_{N-1}}\rightarrow\cdots\rightarrow x_{t_1}\rightarrow x_0
$$

代码中的：

```python
x_T
```

通常就是随机高斯噪声：

$$
x_T\sim\mathcal{N}(0,I)
$$

如果是轨迹规划任务，`x_T` 可以理解为随机噪声轨迹。

---

## 5. 为什么使用 DPM-Solver？

普通扩散采样可能需要数百次甚至上千次模型前向传播。

轨迹规划通常对实时性要求较高。DPM-Solver 将反向扩散看作一个 ODE 数值求解问题，并利用扩散过程的特殊结构构造高阶公式，从而用较少的模型调用次数完成采样。

这段代码默认：

```python
diffusion_steps=10
```

并且开启：

```python
denoise_to_zero=True
```

如果不考虑特殊引导策略，通常大约需要：

$$
10+1=11
$$

次模型函数评估。

常用术语：

$$
\text{NFE}=\text{Number of Function Evaluations}
$$

即模型函数评估次数。

## 8. 为什么使用 `torch.no_grad()`？


训练时需要保存计算图，以便反向传播。

- 减少显存占用；
- 降低额外开销；
- 加快推理；
- 避免记录无用的计算图。

需要注意：

```python
torch.no_grad()
```

不会自动执行：

```python
model.eval()
```

实际推理前通常还应调用：


# 第三部分：噪声调度器

## 9. 创建 `NoiseScheduleVP`

```python
noise_schedule = dpm.NoiseScheduleVP(
    schedule='linear',
    **noise_schedule_params
)
```

### 9.1 VP 是什么意思？

VP 是：

```text
Variance Preserving
```

即“方差保持”。

常见 VP 扩散过程满足：

$$
\alpha_t^2+\sigma_t^2=1
$$

---

### 9.2 `schedule="linear"` 是什么意思？

它表示连续时间噪声强度按照线性规律变化：

$$
\beta(t)=\beta_0+(\beta_1-\beta_0)t
$$

其中：

- $\beta_0$ 是初始噪声强度；
- $\beta_1$ 是终止噪声强度；
- $t\in[0,1]$。

---

### 9.3 如何得到 $\alpha_t$？

在线性 VP-SDE 中：

$$
\log\alpha_t
=
-\frac{1}{2}\int_0^t\beta(s)\,\mathrm{d}s
$$

代入线性 $\beta(s)$：

$$
\log\alpha_t
=
-\frac{1}{2}\beta_0t
-
\frac{1}{4}(\beta_1-\beta_0)t^2
$$

因此：

$$
\alpha_t
=
\exp
\left(
-\frac{1}{2}\beta_0t
-
\frac{1}{4}(\beta_1-\beta_0)t^2
\right)
$$

---

### 9.4 如何得到 $\sigma_t$？

由：

$$
\alpha_t^2+\sigma_t^2=1
$$

得到：

$$
\sigma_t
=
\sqrt{1-\alpha_t^2}
$$

---

### 9.5 什么是 $\lambda_t$？

DPM-Solver 常使用：

$$
\lambda_t
=
\log\alpha_t-\log\sigma_t
$$

它称为：

```text
half-logSNR
```

因为：

$$
\operatorname{SNR}(t)
=
\frac{\alpha_t^2}{\sigma_t^2}
$$

所以：

$$
\lambda_t
=
\frac{1}{2}
\log\operatorname{SNR}(t)
$$

---

# 第四部分：模型包装器

## 10. 创建统一模型接口

```python
model_fn = dpm.model_wrapper(
    model,
    noise_schedule,
    model_type=model.model_type,
    model_kwargs=other_model_params,
    **model_wrapper_params
)
```

不同模型可能预测不同目标。`model_wrapper()` 将它们统一转换成噪声预测：

$$
\epsilon_\theta(x_t,t)
$$

这样，求解器不需要分别处理四套接口。

---

## 11. 四种模型输出如何转换？

### 11.1 模型直接预测噪声

如果：

```python
model.model_type == "noise"
```

模型输出本身就是：

$$
\epsilon_\theta(x_t,t)
$$

---

### 11.2 模型预测 $x_0$

由：

$$
x_t=\alpha_tx_0+\sigma_t\epsilon
$$

得到：

$$
\epsilon
=
\frac{x_t-\alpha_tx_0}{\sigma_t}
$$

因此：

$$
\epsilon_\theta(x_t,t)
=
\frac{
x_t-\alpha_tx_{0,\theta}(x_t,t)
}{
\sigma_t
}
$$

---

### 11.3 模型预测 velocity

velocity 定义为：

$$
v=\alpha_t\epsilon-\sigma_tx_0
$$

结合前向加噪公式可得到：

$$
\epsilon=\alpha_tv+\sigma_tx_t
$$

因此：

$$
\epsilon_\theta(x_t,t)
=
\alpha_tv_\theta(x_t,t)+\sigma_tx_t
$$

---

### 11.4 模型预测 score

score 定义为：

$$
\operatorname{score}(x_t,t)
=
\nabla_{x_t}\log p_t(x_t)
$$

噪声预测与 score 预测满足：

$$
\epsilon_\theta(x_t,t)
=
-\sigma_t\operatorname{score}_\theta(x_t,t)
$$

---

## 12. `other_model_params` 如何进入底层模型？

包装器内部调用关系近似为：

```text
DPM-Solver
    ↓
model_fn(x_t, t)
    ↓
model_wrapper 内部处理
    ↓
model(x_t, t_input, **other_model_params)
```

因此，求解器不需要知道地图、场景编码或历史轨迹的具体结构。

---

## 13. Classifier-Free Guidance 会改变实际推理次数

如果通过 `model_wrapper_params` 开启 Classifier-Free Guidance，包装器可能需要分别计算：

$$
\epsilon_{\text{uncond}}
$$

以及：

$$
\epsilon_{\text{cond}}
$$

再组合为：

$$
\epsilon_{\text{guided}}
=
\epsilon_{\text{uncond}}
+
w
\left(
\epsilon_{\text{cond}}
-
\epsilon_{\text{uncond}}
\right)
$$

因此，一次包装后的模型调用可能对应两次底层网络前向传播。

这意味着：

> `steps=10` 不一定严格等于底层神经网络只运行 10 次。

# 第五部分：创建 DPM-Solver++

## 14. 创建求解器

```python
dpm_solver = dpm.DPM_Solver(
    model_fn,
    noise_schedule,
    algorithm_type="dpmsolver++",
    **dpm_solver_params
)
```

### 14.1 DPM-Solver 与 DPM-Solver++ 的区别

原始 DPM-Solver 主要围绕噪声预测构造更新：

$$
\epsilon_\theta(x_t,t)
$$

DPM-Solver++ 主要围绕数据预测构造更新：

$$
x_{0,\theta}(x_t,t)
$$

即使底层模型输出噪声，DPM-Solver++ 内部也会转换为：

$$
x_{0,\theta}(x_t,t)
=
\frac{
x_t-\sigma_t\epsilon_\theta(x_t,t)
}{
\alpha_t
}
$$

然后再执行更新。

---

### 14.2 `w.o. dynamic thresholding`

原代码注释中有：

```python
# w.o. dynamic thresholding
```

其中：

```text
w.o.
```

表示：

```text
without
```

即当前未使用动态阈值修正。

动态阈值常用于部分像素空间图像扩散模型。对于轨迹张量，是否适用需要结合轨迹归一化方式判断，不能直接照搬图像任务配置。

# 第六部分：调用 `sample()`

## 15. 采样配置

```python
sample_dpm = dpm_solver.sample(
    x_T,
    steps=diffusion_steps,
    order=2,
    skip_type="logSNR",
    method="multistep",
    denoise_to_zero=True,
    **sample_params
)
```

这是整个函数的核心。

---

## 16. `steps=diffusion_steps`

默认：

```python
diffusion_steps=10
```

表示将主要反向扩散过程划分成 10 个更新区间。

通常会生成：

$$
10+1=11
$$

个时间节点。

---

## 17. `order=2`：二阶方法

```python
order=2
```

一阶方法只使用当前模型预测，可以粗略理解为：

> 假设当前区间内模型输出几乎不变。

二阶方法还会估计模型输出的变化趋势，可以粗略理解为：

> 不仅考虑当前位置，还考虑预测结果正在朝哪个方向变化。

所以在相同步数下，二阶方法通常比一阶方法更加准确。

---

## 18. `skip_type="logSNR"`

```python
skip_type="logSNR"
```

代码不是在普通时间 $t$ 上均匀取点，而是在：

$$
\lambda_t=\log\alpha_t-\log\sigma_t
$$

上均匀取点。

设起点和终点为：

$$
\lambda_T
$$

以及：

$$
\lambda_0
$$

则构造：

$$
\lambda_i
=
\lambda_T
+
\frac{i}{N}
\left(
\lambda_0-\lambda_T
\right)
$$

再使用反函数得到时间：

$$
t_i=\lambda^{-1}(\lambda_i)
$$

这样可以更合理地覆盖高噪声、中噪声和低噪声区域。

---

## 19. `method="multistep"`：二阶多步法

```python
method="multistep"
```

### 19.1 单步法

单步法会在当前区间内部增加中间节点，用额外模型预测估计变化趋势。

例如：

$$
s\rightarrow s_1\rightarrow t
$$

---

### 19.2 多步法

多步法复用前面已经计算过的模型值。

例如，在当前节点之前已经有：

$$
m_{i-1}
$$

以及：

$$
m_i
$$

那么通过：

$$
m_i-m_{i-1}
$$

可以估计模型输出的变化趋势。

类比：

```text
单步法：
在当前路段中间再测量一次方向。

多步法：
利用前两个位置的方向变化，预测接下来道路如何弯曲。
```

---

### 19.3 为什么多步法效率高？

因为历史模型预测可以复用。

完成启动后，每推进一个新区间，通常只需要新增一次模型评估。

---

## 20. 二阶多步 DPM-Solver++ 核心公式

设最近两个模型值为：

$$
m_{s_{\text{prev}}}
$$

以及：

$$
m_s
$$

在 DPM-Solver++ 中，它们是对 $x_0$ 的预测。

令：

$$
h_0
=
\lambda_s-\lambda_{s_{\text{prev}}}
$$

$$
h
=
\lambda_t-\lambda_s
$$

$$
r_0
=
\frac{h_0}{h}
$$

构造变化趋势：

$$
D_1
=
\frac{1}{r_0}
\left(
m_s-m_{s_{\text{prev}}}
\right)
$$

再定义：

$$
\phi_1
=
\exp(-h)-1
$$

二阶多步更新为：

$$
x_t
=
\frac{\sigma_t}{\sigma_s}x_s
-
\alpha_t\phi_1m_s
-
\frac{1}{2}\alpha_t\phi_1D_1
$$

初学阶段不用背公式，只要理解：

1. 第一项传播当前状态；
2. 第二项使用当前 $x_0$ 预测完成主要去噪；
3. 第三项利用历史变化趋势做二阶修正。

---

## 21. 为什么多步法需要启动？

二阶多步法需要最近两个模型值。

但刚开始时只有一个初始模型值，因此历史信息不足。

所以第一次推进使用一阶方法：

```text
节点 0：
计算模型值

节点 0 → 节点 1：
使用一阶方法启动

节点 1：
计算新的模型值

节点 1 → 节点 2：
开始使用二阶多步法

节点 2 → 节点 3：
继续使用二阶多步法
```

---

## 22. `denoise_to_zero=True`

```python
denoise_to_zero=True
```

主要采样过程通常不会直接计算到严格的：

$$
t=0
$$

而是计算到一个较小正数：

$$
t_{\text{end}}>0
$$

最后再额外计算：

$$
x_0
\approx
\frac{
x_t-\sigma_t\epsilon_\theta(x_t,t)
}{
\alpha_t
}
$$

作为最终结果。

它会额外增加一次模型函数评估。

# 第七部分：完整执行流程

## 23. 默认参数下的详细过程

默认配置：

```python
diffusion_steps=10
order=2
skip_type="logSNR"
method="multistep"
denoise_to_zero=True
```

执行过程：

```text
1. 输入随机噪声 x_T
2. 创建线性 VP 噪声调度器
3. 将底层模型统一包装为噪声预测函数
4. 创建 DPM-Solver++ 求解器
5. 在 logSNR 坐标中生成 11 个时间节点
6. 在第一个节点调用模型
7. 用一阶方法完成多步法启动
8. 保存第二个节点的模型预测
9. 使用二阶多步公式持续反向去噪
10. 到达接近 0 的时间
11. 额外执行一次 denoise_to_zero
12. 返回生成样本
```

---

## 24. 伪代码

```python
def dpm_sampler(model, x_T):
    schedule = create_linear_vp_schedule()

    noise_predictor = wrap_model_as_noise_predictor(
        model,
        schedule
    )

    solver = create_dpmsolver_plus_plus(
        noise_predictor,
        schedule
    )

    timesteps = create_logsnr_uniform_timesteps(steps=10)

    x = x_T

    x = first_order_update(x)

    for each_remaining_timestep:
        x = second_order_multistep_update(x)

    x = denoise_to_zero(x)

    return x
```

# 第八部分：轨迹规划视角

## 25. 图像扩散与轨迹扩散的类比

图像生成：

```text
x_0 = 清晰图片
x_T = 随机噪声图片
```

轨迹规划：

```text
x_0 = 合理轨迹
x_T = 随机噪声轨迹
```

模型通过场景条件，将随机轨迹逐步去噪为合理轨迹。

---

## 26. 条件信息为什么重要？

仅从随机噪声出发，模型只能生成“总体上像真实轨迹”的结果。

实际驾驶规划还要考虑：

- 自车历史状态；
- 自车速度；
- 周围车辆；
- 行人；
- 地图；
- 车道线；
- 信号灯；
- 导航目标。

这些信息通常通过：

```python
other_model_params
```

传入模型。

因此，模型可以写成：

$$
\epsilon_\theta
=
\epsilon_\theta
\left(
x_t,
t,
\text{scene context}
\right)
$$

# 第九部分：容易踩坑的细节

## 27. 可变字典作为默认参数

代码中多次写了：

```python
some_params: Dict = {}
```

在 Python 中，默认参数对象只会创建一次。

如果函数内部修改该字典，后续调用可能复用已经被修改的对象。

虽然当前代码没有直接修改这些字典，但更稳妥的写法是：

```python
def func(params=None):
    if params is None:
        params = {}
```

---

## 28. `sample_params` 不能重复传递同名参数

代码已经显式指定：

```python
steps=diffusion_steps
order=2
skip_type="logSNR"
method="multistep"
denoise_to_zero=True
```

因此，不要在 `sample_params` 中再次传入同名参数，否则 Python 会报错：

```text
TypeError: got multiple values for keyword argument
```

`sample_params` 更适合补充：

```python
t_start
t_end
lower_order_final
solver_type
atol
rtol
return_intermediate
```

## 29. `model.model_type` 必须存在

代码访问：

```python
model.model_type
```

因此模型必须定义该属性，例如：

```python
model.model_type = "v"
```

否则会出现：

```text

```

## 30. 噪声调度必须与训练过程匹配

采样阶段使用的噪声调度应与模型训练设定一致。

如果训练时与推理时的 $\alpha_t$、$\sigma_t$ 不匹配，模型预测的含义就会错位，采样质量可能明显下降。

例如：

```python

x_T = x_T.to(device)
```

否则可能出现：

```text
Expected all tensors to be on the same device
```

## 32. 推理前建议调用 `model.eval()`

`torch.no_grad()` 只关闭梯度记录，不会自动切换 Dropout 和 BatchNorm 行为。

因此，推理前通常写：


# 第十部分：常见问题

## 33. `steps=10` 是否意味着只有 10 个节点？

不是。

通常会生成：

$$
10+1=11
$$

个时间节点，对应 10 个更新区间。

---

## 34. 二阶方法是否每一步都调用模型两次？

对于：

```python
method="multistep"
```

不是。

多步法复用历史模型值。启动完成后，每推进一个新区间通常只新增一次模型评估。

但如果包装器内部使用 Classifier-Free Guidance，一次包装调用可能对应两次底层网络前向。

---

## 35. `schedule="linear"` 与 `skip_type="logSNR"` 是否冲突？

不冲突。

```python
schedule="linear"
```

定义整条噪声变化曲线。

```python
skip_type="logSNR"
```

决定在这条曲线上选择哪些离散采样节点。

类比：

```text
schedule：
定义道路的形状。

skip_type：
决定在哪些位置设置路标。
```

---

## 36. 为什么已经有 `model_wrapper()`，DPM-Solver++ 还要转换一次？

`model_wrapper()` 负责将底层模型输出统一成噪声预测：

$$
\epsilon_\theta
$$

DPM-Solver++ 再将噪声预测转换成数据预测：

$$
x_{0,\theta}
=
\frac{
x_t-\sigma_t\epsilon_\theta
}{
\alpha_t
}
$$

完整链路：

```text
底层模型输出
    ↓
model_wrapper
    ↓
统一噪声预测 epsilon_theta
    ↓
DPM-Solver++
    ↓
数据预测 x0_theta
    ↓
二阶多步更新
```

# 第十三部分：总结

这段代码的核心逻辑可以概括为：

1. 使用线性 VP 噪声调度定义 $\alpha_t$、$\sigma_t$ 和 $\lambda_t$。
2. 将不同类型的模型输出统一包装成噪声预测。
3. 使用 DPM-Solver++ 将噪声预测转换为 $x_0$ 预测。
4. 在 logSNR 坐标中使用二阶多步法，从随机噪声快速生成结果。
5. 最后额外执行一次 `denoise_to_zero`，减小残余噪声。

最重要的公式：

$$
x_t=\alpha_tx_0+\sigma_t\epsilon
$$

$$
\lambda_t=\log\alpha_t-\log\sigma_t
$$

$$
x_{0,\theta}
=
\frac{
x_t-\sigma_t\epsilon_\theta(x_t,t)
}{
\alpha_t
}
$$

如果模型预测 velocity：

$$
\epsilon_\theta(x_t,t)
=
\alpha_tv_\theta(x_t,t)+\sigma_tx_t
$$

如果模型预测 score：

$$
\epsilon_\theta(x_t,t)
=
-\sigma_t\operatorname{score}_\theta(x_t,t)
$$

完整流程：

```text
随机噪声 x_T
    ↓
线性 VP 噪声调度
    ↓
统一模型接口
    ↓
DPM-Solver++
    ↓
logSNR 均匀节点
    ↓
二阶 multistep 反向扩散
    ↓
denoise_to_zero
    ↓
生成结果
```

# 附录 A：更加稳妥的写法

下面的代码避免使用可变字典作为默认参数。

```python
from typing import Any, Dict, Optional

import torch

import diffusion_planner.model.diffusion_utils.dpm_solver_pytorch as dpm


def dpm_sampler(
    model: torch.nn.Module,
    x_T: torch.Tensor,
    other_model_params: Optional[Dict[str, Any]] = None,
    diffusion_steps: int = 10,
    noise_schedule_params: Optional[Dict[str, Any]] = None,
    model_wrapper_params: Optional[Dict[str, Any]] = None,
    dpm_solver_params: Optional[Dict[str, Any]] = None,
    sample_params: Optional[Dict[str, Any]] = None,
) -> torch.Tensor:
    if other_model_params is None:
        other_model_params = {}
    if noise_schedule_params is None:
        noise_schedule_params = {}
    if model_wrapper_params is None:
        model_wrapper_params = {}
    if dpm_solver_params is None:
        dpm_solver_params = {}
    if sample_params is None:
        sample_params = {}

    with torch.no_grad():
        noise_schedule = dpm.NoiseScheduleVP(
            schedule="linear",
            **noise_schedule_params,
        )

        model_fn = dpm.model_wrapper(
            model,
            noise_schedule,
            model_type=model.model_type,
            model_kwargs=other_model_params,
            **model_wrapper_params,
        )

        solver = dpm.DPM_Solver(
            model_fn,
            noise_schedule,
            algorithm_type="dpmsolver++",
            **dpm_solver_params,
        )

        sample = solver.sample(
            x_T,
            steps=diffusion_steps,
            order=2,
            skip_type="logSNR",
            method="multistep",
            denoise_to_zero=True,
            **sample_params,
        )

    return sample
```

# 附录 B：术语表

| 术语 | 含义 |
|---|---|
| 扩散模型 | 通过学习反向去噪过程生成数据的模型 |
| 前向扩散 | 从真实样本逐渐加入噪声 |
| 反向扩散 | 从噪声逐步恢复样本 |
| VP | Variance Preserving，方差保持 |
| $\alpha_t$ | 原始信号保留比例 |
| $\sigma_t$ | 噪声注入比例 |
| SNR | Signal-to-Noise Ratio，信噪比 |
| half-logSNR | $\lambda_t=\log\alpha_t-\log\sigma_t$ |
| DPM-Solver | 面向扩散 ODE 的快速数值求解器 |
| DPM-Solver++ | 主要使用数据预测形式构造更新的版本 |
| NFE | Number of Function Evaluations，模型函数评估次数 |
| singlestep | 当前区间内部额外使用中间节点的单步法 |
| multistep | 复用历史模型值的多步法 |
| denoise-to-zero | 在最后额外恢复一次 $x_0$ |
| score | 对数概率密度对输入的梯度 |
| velocity | $v=\alpha_t\epsilon-\sigma_tx_0$ |
