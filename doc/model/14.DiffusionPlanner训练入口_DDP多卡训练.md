# Diffusion Planner 训练入口脚本详解：从命令行参数到 DDP 多卡训练

## 0. 这份代码的作用是什么？

这份代码是 Diffusion Planner 项目的**训练入口脚本**。

它的主要任务不是实现神经网络内部结构，而是负责把训练过程中需要的各个模块组织起来：

```text
读取命令行参数
    ↓
构造归一化器
    ↓
初始化 DDP 多卡训练环境
    ↓
创建训练日志目录并保存 args.json
    ↓
构造数据集与 DataLoader
    ↓
创建 Diffusion Planner 模型
    ↓
创建 EMA 模型
    ↓
创建 AdamW 优化器
    ↓
创建学习率调度器
    ↓
可选：从 checkpoint 恢复训练
    ↓
循环调用 train_epoch()
    ↓
记录日志并定期保存模型
```

可以将这份脚本理解成：

> Diffusion Planner 训练流程的“总导演”。

它负责安排数据、模型、优化器、学习率、日志和多 GPU 进程之间如何协同工作。

# 1. 这份代码与项目中的其他文件如何衔接？

你此前已经阅读过一些推理和仿真代码。它们与当前训练脚本的关系如下：

```text
当前训练脚本
    ↓
```


因此，当前脚本生成的：

```text

```

正是后续 nuPlan 仿真脚本中使用的重要输入。

# 4. `boolean()`：命令行字符串如何变成布尔值？

## 4.1 代码

```python
def boolean(v):
    if isinstance(v, bool):
        return v

    if v.lower() in ('yes', 'true', 't', 'y', '1'):
        return True
    elif v.lower() in ('no', 'false', 'f', 'n', '0'):
        return False
    else:
        raise argparse.ArgumentTypeError('Boolean value expected.')
```

---

## 4.2 为什么需要自己写？

命令行参数本质上通常是字符串。

例如：

```bash
--use_ema false
```

解析器最初看到的是：

```python
"false"
```

而不是 Python 布尔值：

```python
False
```

如果直接使用：

```python
bool("false")
```

结果反而是：

```python
True
```

原因是：Python 中任何非空字符串都会被视为真值。

所以需要自己显式判断。

---

## 4.3 支持哪些写法？

真值：

```text
yes
true
t
y
1
```

假值：

```text
no
false
f
n
0
```

因此下面写法都可以：

```bash
--use_ema true
--use_ema 1
--use_ema yes
```

即使程序不报错，预测结果也可能失效。

# 15. 初始化 DDP

## 15.1 代码

```python
global_rank, rank, _ = ddp.ddp_setup_universal(True, args)
```

---

## 15.2 三个重要概念

### `world_size`

总训练进程数。

如果使用 8 张 GPU，通常：

$$
\text{world\_size}=8
$$

### `global_rank`

当前进程在所有进程中的编号。

例如：

```text
0,1,2,3,4,5,6,7
```

### `rank`

当前进程在本机的设备编号。

单机 8 GPU 时通常同样是：

```text
0,1,2,3,4,5,6,7
```

多机训练时，`global_rank` 与本机 `rank` 可能不同。

---

## 15.3 为什么每张 GPU 一个进程？

DDP 推荐每张 GPU 启动一个训练进程。

例如：

```bash
torchrun --nproc-per-node 8 train_predictor.py ...
```

会启动 8 个 Python 进程。

每个进程：

- 绑定一张 GPU；
- 读取不同训练数据；
- 计算本地梯度；
- 同步梯度；
- 更新相同模型。

---

## 15.4 这里有一个值得检查的细节

代码写的是：

```python
ddp.ddp_setup_universal(True, args)
```

它传入固定值：

```python
True
```

而不是：

```python
args.ddp
```

这意味着：

> 即使命令行中设置 `--ddp false`，DDP 初始化工具仍然会收到 `True`。

是否会导致问题，取决于 `ddp_setup_universal()` 的内部实现。

这是值得进一步检查的地方。

# 16. 只让主进程写日志

```python
if global_rank == 0:
```

DDP 中多个进程会同时执行同一份 Python 脚本。

如果所有进程都创建目录、写日志和保存模型，就可能发生冲突。

因此通常规定：

```text
global_rank == 0
```

的主进程负责：

- 打印日志；
- 创建保存目录；
- 写入 `args.json`；
- 保存 checkpoint。

其他进程只负责训练计算。

# 23. 创建 DataLoader

```python
train_loader = DataLoader(
    train_set,
    sampler=train_sampler,
    batch_size=batch_size // ddp.get_world_size(),
    num_workers=args.num_workers,
    pin_memory=args.pin_mem,
    drop_last=True
)
```

---

## 23.1 单进程 batch size

代码将全局 batch size 除以进程数：

$$
B_{\text{local}}
=
\frac{B_{\text{global}}}{\text{world size}}
$$

例如：

$$
B_{\text{global}}=2048
$$

$$
\text{world size}=8
$$

则：

$$
B_{\text{local}}=256
$$

---

## 23.2 一个值得检查的细节

代码使用整数除法：

```python
batch_size // ddp.get_world_size()
```

如果 batch size 不能整除 world size，会向下取整。

例如：

$$
2050//8=256
$$

实际全局 batch size 会变为：

$$
256\times8=2048
$$

而不是 2050。

因此最好确保：

```python
args.batch_size % world_size == 0
```

---

## 23.3 `drop_last=True`

如果最后剩余样本不足一个完整 batch，则丢弃。

这样可以保持每次训练 batch 形状一致。


DDP 会在反向传播时同步不同 GPU 的梯度。

---

## 27.1 DDP 梯度同步原理

假设有 2 张 GPU。

GPU 0 计算：

$$
g_0
$$

GPU 1 计算：

$$
g_1
$$

DDP 会同步并聚合梯度，通常相当于：

$$
g
=
\frac{g_0+g_1}{2}
$$

然后每个进程使用相同梯度更新模型。

因此，各 GPU 上模型参数保持一致。

# 28. 创建 EMA 模型

```python
if args.use_ema:
    model_ema = ModelEma(
        diffusion_planner,
        decay=0.999,
        device=args.device,
    )
```

---

## 28.1 EMA 公式

设当前模型参数为：

$$
\theta_k
$$

EMA 参数为：

$$
\bar{\theta}_k
$$

更新公式通常类似：

$$
\bar{\theta}_k
=
\gamma\bar{\theta}_{k-1}
+
(1-\gamma)\theta_k
$$

这里：

$$
\gamma=0.999
$$

---

## 28.2 直观理解

普通模型权重可能随训练产生波动。

EMA 相当于做平滑：

```text
旧 EMA 参数 × 0.999
+
当前参数 × 0.001
```

因此推理结果通常更加稳定。

---

## 28.3 代码中一个重要风险

`model_ema` 只在：

```python
if args.use_ema:
```

分支中定义。

但是后面会无条件传入：

```python
resume_model(..., model_ema, ...)
train_epoch(..., model_ema, ...)
save_model(..., model_ema.ema)
```

因此，如果设置：

```bash
--use_ema false
```

当前脚本很可能出现：

```text
UnboundLocalError: local variable 'model_ema' referenced before assignment
```

除非其他代码有特殊处理，但仅从当前脚本看，`use_ema=False` 并不安全。

# 30. 创建 AdamW 优化器

```python
params = [{

        diffusion_planner,
        args.ddp
    ).parameters(),
    'lr': args.learning_rate
}]

optimizer = optim.AdamW(params)
```

---

## 30.1 优化器的作用

神经网络训练目标是降低损失：

$$
L(\theta)
$$

其中：

$$
\theta
$$

表示模型参数。

优化器根据梯度：

$$
\nabla_\theta L
$$

更新参数。

---

## 30.2 AdamW

AdamW 是常用优化器。

它在 Adam 的基础上使用解耦权重衰减。

直观理解：

```text
Adam：
根据梯度历史，自适应调整每个参数的步长。

AdamW：
在 Adam 基础上，更合理地加入权重衰减。
```

---

## 30.3 默认权重衰减

代码没有显式传入：

```python
weight_decay
```

因此会使用当前 PyTorch `AdamW` 的默认值。

如果希望严格控制实验，应显式写入配置。

# 31. 创建学习率调度器

```python
scheduler = CosineAnnealingWarmUpRestarts(
    optimizer,
    train_epochs,
    args.warm_up_epoch
)
```

---

## 31.1 为什么需要学习率调度？

学习率太大：

- 训练不稳定；
- 损失震荡；
- 可能无法收敛。

学习率太小：

- 训练速度慢；
- 容易停留在较差位置。

---

## 31.2 warm-up

训练初期逐步增大学习率：

```text
较小学习率
    ↓
逐渐升高
    ↓
进入正常训练
```

---

## 31.3 余弦退火

后续学习率可能按照余弦曲线逐渐下降：

$$
\eta_t
=
\eta_{\min}
+
\frac{1}{2}
\left(
\eta_{\max}-\eta_{\min}
\right)
\left(
1+\cos
\left(
\frac{\pi t}{T}
\right)
\right)
$$

准确公式和是否真正重启，需要查看项目中：

```python
CosineAnnealingWarmUpRestarts
```

的实现。

| $x_0$ | 干净轨迹或原始样本 |

# 47. 初学者最需要记住的十件事

1. 当前文件是训练入口，不是网络内部实现。
2. `get_args()` 集中管理训练配置。
3. `args.json` 会保存完整训练参数，后续推理可以复用。
4. `DiffusionPlannerData` 负责读取训练数据。
5. `DistributedSampler` 让不同 GPU 读取不同样本。
6. `DDP` 会同步各 GPU 的梯度。
7. `batch_size=2048` 是全局 batch size，单卡 batch size 还要除以 GPU 数量。
8. EMA 是一份平滑后的模型权重，常用于推理。
9. `train_epoch()` 才是前向传播、损失计算和反向传播的核心位置。
10. rank 0 主进程负责写日志和保存 checkpoint，避免多进程写文件冲突。

# 48. 一句话总结

这份代码的本质是：

> 解析 Diffusion Planner 的训练参数，初始化归一化器和 DDP 多卡环境，构造数据集、模型、EMA、AdamW 优化器与学习率调度器，并在多个 GPU 进程之间同步梯度，循环执行 `train_epoch()`，最后由主进程记录日志并定期保存模型。
