# 1. 先用一句话概括这份代码

这份代码的任务是：

> 把扩散模型的“逐步去噪过程”看成一个常微分方程（ODE）的数值求解问题，然后使用专门为扩散模型设计的一阶、二阶、三阶公式，在较少的模型调用次数下，从高斯噪声逐步得到较干净的样本。

普通 DDPM 采样可能需要数百到上千次模型推理。DPM-Solver 的目标是使用更高效的数学更新公式，将采样步数显著减少。

需要特别注意：

- 这份代码不是一个完整的扩散模型。
- 它不包含 U-Net、Transformer 或其他神经网络结构。
- 它假设你已经有一个训练好的扩散模型。
- 它负责调用模型，并根据模型预测结果更新当前样本。

可以把它类比成：

- 训练好的神经网络是一个“导航员”，负责告诉你当前应该往哪个方向去噪。
- DPM-Solver 是一个“高效驾驶员”，负责决定如何用较少的转向次数抵达终点。

# 2. 理解代码前必须知道的基本概念

## 2.1 扩散模型在做什么？

扩散模型通常包含两个方向相反的过程：

1. **前向扩散过程**：不断向真实数据中加入噪声。
2. **反向生成过程**：从随机噪声出发，逐渐恢复出干净样本。

假设原始干净数据为 $x_0$，例如一张真实图片。加入一定程度的噪声后，得到 $x_t$。

在 VP（Variance Preserving，方差保持）类型的扩散过程中，常见表达式为：

$$
x_t=\alpha_t x_0+\sigma_t\epsilon
$$

其中：

| 符号 | 含义 |
|---|---|
| $x_0$ | 原始干净数据 |
| $x_t$ | 时间 $t$ 时的带噪数据 |
| $\epsilon$ | 标准高斯噪声，通常满足 $\epsilon\sim\mathcal{N}(0,I)$ |
| $\alpha_t$ | 信号保留系数 |
| $\sigma_t$ | 噪声强度 |

在 VP 类型扩散模型中，通常满足：

$$
\alpha_t^2+\sigma_t^2=1
$$

随着时间 $t$ 增大：

- $\alpha_t$ 逐渐减小，原始信号逐渐变弱。
- $\sigma_t$ 逐渐增大，噪声逐渐增强。
- 当 $t$ 接近扩散终点时，$x_t$ 已经接近随机噪声。

---

## 2.2 采样过程为什么要从大时间走向小时间？

前向过程是：

$$
x_0\longrightarrow x_t\longrightarrow x_T
$$

其中 $x_T$ 接近纯噪声。

生成图片时要反过来：

$$
x_T\longrightarrow x_t\longrightarrow x_0
$$

因此，代码中的 `sample()` 默认从：

```python
t_start = T = 1.0
```

走到：

```python
t_end = 1 / total_N
```

例如训练扩散模型时共有 1000 个时间步，则默认终点约为：

$$
t_{\text{end}}=\frac{1}{1000}=0.001
$$

为什么不直接走到 $t=0$？

因为在某些公式中，$t=0$ 附近可能出现数值不稳定问题。代码通常先走到一个很小的正数，再根据需要执行额外的 `denoise_to_zero` 操作。

---

## 2.3 神经网络通常预测什么？

扩散模型中的神经网络接收当前带噪样本 $x_t$ 和时间 $t$，输出一个预测值。

不同模型可能预测不同的量：

1. 预测噪声 $\epsilon$。
2. 预测原始干净数据 $x_0$。
3. 预测 velocity，即 $v$。
4. 预测 score 函数。

这份代码通过 `model_wrapper()` 将这些形式统一转换成“预测噪声”的接口。

---

## 2.4 什么是 half-logSNR？

代码中反复出现：

$$
\lambda_t=\log(\alpha_t)-\log(\sigma_t)
$$

它被称为 **half-logSNR**，也就是信噪比对数的一半。

由于：

$$
\text{SNR}(t)=\frac{\alpha_t^2}{\sigma_t^2}
$$

所以：

$$
\frac{1}{2}\log\text{SNR}(t)
=\frac{1}{2}\log\frac{\alpha_t^2}{\sigma_t^2}
=\log(\alpha_t)-\log(\sigma_t)
=\lambda_t
$$

直观理解：

- $\lambda_t$ 越大，信号越强，噪声越弱。
- $\lambda_t$ 越小，噪声越强，信号越弱。

前向加噪时，时间 $t$ 增大，$\lambda_t$ 通常减小。

反向采样时，时间 $t$ 减小，$\lambda_t$ 通常增大。

DPM-Solver 的许多公式不是直接在 $t$ 空间中写，而是在 $\lambda$ 空间中写。这样更容易得到适合扩散模型的高效更新公式。

---

## 2.5 为什么需要数值求解器？

生成样本时，可以把反向过程理解为求解一个 ODE：

$$
\frac{dx}{dt}=f(x,t)
$$

这里：

- $x$ 是当前样本。
- $t$ 是时间。
- $f(x,t)$ 与扩散模型预测结果有关。

如果时间是连续的，就不可能真的计算无限多个时间点。因此只能选取有限个时间点：

$$
t_0,t_1,t_2,\ldots,t_N
$$

然后逐步更新：

$$
x_{t_0}\longrightarrow x_{t_1}\longrightarrow x_{t_2}\longrightarrow\cdots\longrightarrow x_{t_N}
$$

不同数值求解器的区别在于：

> 在每一步中，如何利用当前点、历史点或中间点的信息，更准确地估计下一步结果。

# 3. 这份代码的整体结构

代码可以分成四部分：

```text
NoiseScheduleVP
    ↓
model_wrapper
    ↓
DPM_Solver
    ↓
辅助函数 interpolate_fn / expand_dims
```

对应作用如下：

| 部分 | 作用 |
|---|---|
| `NoiseScheduleVP` | 管理噪声调度，计算 $\alpha_t$、$\sigma_t$、$\lambda_t$ 以及 $\lambda\mapsto t$ 的反函数 |
| `model_wrapper` | 将不同类型扩散模型统一包装成“输入 $x_t,t$，输出预测噪声”的函数 |
| `DPM_Solver` | 执行真正的采样，包含一阶、二阶、三阶、单步、多步、自适应求解器 |
| `interpolate_fn` | 对离散噪声调度做分段线性插值 |
| `expand_dims` | 给一维时间系数增加维度，以便与图片张量广播运算 |

---

## 3.1 最重要的调用链

最常见的调用过程如下：

```python
noise_schedule = NoiseScheduleVP(...)
model_fn = model_wrapper(model, noise_schedule, ...)
solver = DPM_Solver(model_fn, noise_schedule, algorithm_type="dpmsolver++")
x_sample = solver.sample(x_noise, steps=20, order=2, method="multistep")
```

将其翻译成自然语言：

1. 创建噪声调度器。
2. 将原始神经网络包装成统一接口。
3. 创建 DPM-Solver 求解器。
4. 输入初始噪声。
5. 调用 `sample()` 逐步去噪。
6. 得到生成结果。

# 4. 第一部分：`NoiseScheduleVP`

源代码位置：`class NoiseScheduleVP`。

它的核心任务是回答以下问题：

> 给定任意连续时间 $t$，当前应该保留多少信号？应该加入多少噪声？当前 half-logSNR 是多少？给定 half-logSNR 时，时间又是多少？

---

## 4.1 构造函数 `__init__()`

函数定义：

```python
class NoiseScheduleVP:
    def __init__(
            self,
            schedule='discrete',
            betas=None,
            alphas_cumprod=None,
            continuous_beta_0=0.1,
            continuous_beta_1=20.,
            dtype=torch.float32,
        ):
```

代码支持两类噪声调度：

```python
if schedule not in ['discrete', 'linear']:
    raise ValueError(...)
```

也就是说：

| `schedule` | 含义 |
|---|---|
| `'discrete'` | 离散时间扩散模型，例如常见 DDPM |
| `'linear'` | 连续时间线性 VP-SDE |

---

## 4.2 离散调度：`schedule='discrete'`

很多扩散模型在训练时使用离散时间步：

$$
n=0,1,2,\ldots,N-1
$$

每一步加入一定量噪声 $\beta_n$。

DDPM 中常见定义为：

$$
\hat{\alpha}_n=\prod_{i=0}^{n}(1-\beta_i)
$$

于是：

$$
x_n=\sqrt{\hat{\alpha}_n}x_0+\sqrt{1-\hat{\alpha}_n}\epsilon
$$

而 DPM-Solver 使用的符号是：

$$
\alpha_{t_n}=\sqrt{\hat{\alpha}_n}
$$

因此：

$$
\log\alpha_{t_n}=\frac{1}{2}\log\hat{\alpha}_n
$$

代码中的实现：

```python
if betas is not None:
    log_alphas = 0.5 * torch.log(1 - betas).cumsum(dim=0)
else:
    assert alphas_cumprod is not None
    log_alphas = 0.5 * torch.log(alphas_cumprod)
```

### 为什么 `cumsum(log(...))` 等价于 `log(cumprod(...))`？

因为：

$$
\log(a_1a_2\cdots a_n)=\log a_1+\log a_2+\cdots+\log a_n
$$

所以：

```python
torch.log(1 - betas).cumsum(dim=0)
```

等价于：

```python
torch.log(torch.cumprod(1 - betas, dim=0))
```

前一种写法通常更加直接，也有利于数值处理。

---

## 4.3 为什么离散训练步要映射到连续时间？

DPM-Solver 是连续时间 ODE 求解器，但很多模型是在离散时间标签上训练的。

因此，代码将离散索引：

$$
i=0,1,2,\ldots,N-1
$$

映射成连续时间：

$$
t_i=\frac{i+1}{N}
$$

代码：

```python
self.t_array = torch.linspace(0., 1., self.total_N + 1)[1:].reshape((1, -1)).to(dtype=dtype)
```

例如 $N=1000$：

```text
第 0 个训练步  → t = 0.001
第 1 个训练步  → t = 0.002
...
第 999 个训练步 → t = 1.000
```

注意：这里不包含 $t=0$。

---

## 4.4 连续线性调度：`schedule='linear'`

连续时间 VP-SDE 中，噪声强度可以设置为线性变化：

$$
\beta(t)=\beta_0+(\beta_1-\beta_0)t
$$

代码保存：

```python
self.beta_0 = continuous_beta_0
self.beta_1 = continuous_beta_1
```

对于这种线性调度，可以直接推导：

$$
\log\alpha_t
=-\frac{1}{2}\int_0^t\beta(s)\,ds
$$

积分后得到：

$$
\log\alpha_t
=-\frac{1}{4}t^2(\beta_1-\beta_0)-\frac{1}{2}t\beta_0
$$

对应代码：

```python
return -0.25 * t ** 2 * (self.beta_1 - self.beta_0) - 0.5 * t * self.beta_0
```

---

## 4.5 `numerical_clip_alpha()`：为什么要裁剪？

函数定义：

```python
def numerical_clip_alpha(self, log_alphas, clipped_lambda=-5.1):
```

某些噪声调度在扩散终点附近可能非常极端：

- $\alpha_t$ 非常接近 0。
- $\sigma_t$ 非常接近 1。
- $\lambda_t$ 非常小。
- 浮点运算容易出现不稳定。

代码先根据 VP 关系计算：

$$
\sigma_t=\sqrt{1-\alpha_t^2}
$$

在对数空间中：

$$
\log\sigma_t=\frac{1}{2}\log(1-\exp(2\log\alpha_t))
$$

对应代码：

```python
log_sigmas = 0.5 * torch.log(1. - torch.exp(2. * log_alphas))
lambs = log_alphas - log_sigmas
```

随后删除扩散末端过于极端的点：

```python
idx = torch.searchsorted(torch.flip(lambs, [0]), clipped_lambda)
if idx > 0:
    log_alphas = log_alphas[:-idx]
```

直观理解：

> 如果末端噪声过强，已经强到容易造成数值问题，就舍弃极少量最极端的尾部点，以提升稳定性。

---

## 4.6 `marginal_log_mean_coeff(t)`：计算 $\log\alpha_t$

函数定义：

```python
def marginal_log_mean_coeff(self, t):
```

### 离散调度

离散调度只有一组已知关键点，因此使用分段线性插值：

```python
return interpolate_fn(
    t.reshape((-1, 1)),
    self.t_array.to(t.device),
    self.log_alpha_array.to(t.device)
).reshape((-1))
```

### 连续线性调度

直接使用闭式公式：

```python
return -0.25 * t ** 2 * (self.beta_1 - self.beta_0) - 0.5 * t * self.beta_0
```

---

## 4.7 `marginal_alpha(t)`：计算 $\alpha_t$

因为前一个函数返回 $\log\alpha_t$，所以这里只需要取指数：

```python
return torch.exp(self.marginal_log_mean_coeff(t))
```

数学上：

$$
\alpha_t=\exp(\log\alpha_t)
$$

---

## 4.8 `marginal_std(t)`：计算 $\sigma_t$

VP 类型扩散过程满足：

$$
\alpha_t^2+\sigma_t^2=1
$$

因此：

$$
\sigma_t=\sqrt{1-\alpha_t^2}
$$

代码：

```python
return torch.sqrt(1. - torch.exp(2. * self.marginal_log_mean_coeff(t)))
```

---

## 4.9 `marginal_lambda(t)`：计算 half-logSNR

函数定义：

```python
def marginal_lambda(self, t):
```

代码：

```python
log_mean_coeff = self.marginal_log_mean_coeff(t)
log_std = 0.5 * torch.log(1. - torch.exp(2. * log_mean_coeff))
return log_mean_coeff - log_std
```

对应公式：

$$
\lambda_t=\log\alpha_t-\log\sigma_t
$$

DPM-Solver 中很多步长都定义在 $\lambda$ 空间：

$$
h=\lambda_t-\lambda_s
$$

---

## 4.10 `inverse_lambda(lamb)`：从 $\lambda$ 反解时间 $t$

函数定义：

```python
def inverse_lambda(self, lamb):
```

为什么需要这个函数？

因为代码经常先在 $\lambda$ 空间中选择中间位置：

$$
\lambda_{s_1}=\lambda_s+r_1h
$$

然后需要知道真实时间：

$$
s_1=\lambda^{-1}(\lambda_{s_1})
$$

### 连续线性调度

可以解析求解，因此代码直接使用数学公式反解。

### 离散调度

无法直接写出简单闭式公式。代码先根据：

$$
\alpha_t^2=\operatorname{sigmoid}(2\lambda_t)
$$

得到：

$$
\log\alpha_t=-\frac{1}{2}\log(1+e^{-2\lambda_t})
$$

对应代码：

```python
log_alpha = -0.5 * torch.logaddexp(
    torch.zeros((1,)).to(lamb.device),
    -2. * lamb
)
```

再通过插值求出时间 $t$：

```python
t = interpolate_fn(
    log_alpha.reshape((-1, 1)),
    torch.flip(self.log_alpha_array.to(lamb.device), [1]),
    torch.flip(self.t_array.to(lamb.device), [1])
)
```

# 5. 第二部分：`model_wrapper`

函数定义：

```python
def model_wrapper(
    model,
    noise_schedule,
    model_type="noise",
    model_kwargs={},
    guidance_type="uncond",
    condition=None,
    unconditional_condition=None,
    guidance_scale=1.,
    classifier_fn=None,
    classifier_kwargs={},
):
```

它是一个非常重要的“适配器”。

它将各种不同格式的扩散模型统一包装为：

```python
model_fn(x, t_continuous) -> predicted_noise
```

也就是说，无论原模型预测的是噪声、$x_0$、velocity 还是 score，DPM-Solver 外部看到的接口都一致。

---

## 5.1 为什么必须统一接口？

不同扩散模型可能来自不同项目：

- 某个模型预测噪声。
- 某个模型预测 $x_0$。
- 某个模型预测 velocity。
- 某个模型的时间标签是 $0$ 到 $999$。
- 某个模型使用连续时间。
- 某个模型是无条件生成。
- 某个模型使用文本条件。

如果求解器内部直接处理所有差异，代码会非常混乱。

因此代码先统一包装，后面求解器只调用：

```python
noise = model_fn(x, t)
```

---

## 5.2 `get_model_input_time()`：转换时间标签

DPM-Solver 使用连续时间：

$$
t\in[1/N,1]
$$

但是离散扩散模型通常在类似 $0$ 到 $999$ 的标签上训练。

代码：

```python
if noise_schedule.schedule == 'discrete':
    return (t_continuous - 1. / noise_schedule.total_N) * 1000.
else:
    return t_continuous
```

例如 $N=1000$：

| 连续时间 | 模型输入标签 |
|---:|---:|
| $0.001$ | $0$ |
| $0.500$ | $499$ |
| $1.000$ | $999$ |

这里的 `1000.` 是特定扩散模型时间标签约定。使用其他项目的模型时，应确认模型是否也采用这一约定。

---

## 5.3 `noise_pred_fn()`：统一转换成噪声预测

函数定义：

```python
def noise_pred_fn(x, t_continuous, cond=None):
```

先调用原始模型：

```python
if cond is None:
    output = model(x, t_input, **model_kwargs)
else:
    output = model(x, t_input, cond, **model_kwargs)
```

然后根据 `model_type` 做转换。

---

## 5.4 `model_type='noise'`

如果模型直接预测噪声 $\epsilon$，不需要转换：

```python
if model_type == "noise":
    return output
```

即：

$$
\epsilon_\theta(x_t,t)=\text{model}(x_t,t)
$$

---

## 5.5 `model_type='x_start'`

如果模型预测 $x_0$，根据：

$$
x_t=\alpha_tx_0+\sigma_t\epsilon
$$

反解：

$$
\epsilon=\frac{x_t-\alpha_tx_0}{\sigma_t}
$$

代码：

```python
alpha_t, sigma_t = noise_schedule.marginal_alpha(t_continuous), noise_schedule.marginal_std(t_continuous)
return (x - expand_dims(alpha_t, x.dim()) * output) / expand_dims(sigma_t, x.dim())
```

---

## 5.6 `model_type='v'`

velocity 参数化常定义为：

$$
v=\alpha_t\epsilon-\sigma_tx_0
$$

结合：

$$
x_t=\alpha_tx_0+\sigma_t\epsilon
$$

可以得到：

$$
\epsilon=\alpha_tv+\sigma_tx_t
$$

代码：

```python
return expand_dims(alpha_t, x.dim()) * output + expand_dims(sigma_t, x.dim()) * x
```

---

## 5.7 `model_type='score'`

score 函数与噪声预测之间常见关系为：

$$
\epsilon_\theta(x_t,t)=-\sigma_t\operatorname{score}_\theta(x_t,t)
$$

代码：

```python
return -expand_dims(sigma_t, x.dim()) * output
```

---

## 5.8 三种 guidance 类型

代码支持：

```python
guidance_type in ["uncond", "classifier", "classifier-free"]
```

---

### 5.8.1 无条件采样：`'uncond'`

代码：

```python
if guidance_type == "uncond":
    return noise_pred_fn(x, t_continuous)
```

没有额外条件，直接使用模型预测噪声。

---

### 5.8.2 分类器引导：`'classifier'`

分类器引导额外使用一个分类器，计算：

$$
\nabla_x\log p_t(c\mid x_t)
$$

它表示：

> 为了让当前样本更符合条件 $c$，应该沿哪个方向调整 $x_t$？

代码中先启用梯度：

```python
with torch.enable_grad():
    x_in = x.detach().requires_grad_(True)
    log_prob = classifier_fn(x_in, t_input, condition, **classifier_kwargs)
    return torch.autograd.grad(log_prob.sum(), x_in)[0]
```

随后修正噪声预测：

```python
return noise - guidance_scale * expand_dims(sigma_t, x.dim()) * cond_grad
```

即：

$$
\epsilon_{\text{guided}}
=
\epsilon_{\text{model}}
-w\sigma_t\nabla_x\log p_t(c\mid x_t)
$$

其中 $w$ 是 `guidance_scale`。

---

### 5.8.3 无分类器引导：`'classifier-free'`

Classifier-Free Guidance，简称 CFG。

同一个扩散模型分别计算：

1. 无条件预测：$\epsilon_{\text{uncond}}$。
2. 有条件预测：$\epsilon_{\text{cond}}$。

然后做外推：

$$
\epsilon_{\text{CFG}}
=
\epsilon_{\text{uncond}}
+w(\epsilon_{\text{cond}}-\epsilon_{\text{uncond}})
$$

代码：

```python
noise_uncond = noise_pred_fn(x, t_continuous, cond=unconditional_condition)
noise = noise_pred_fn(x, t_continuous, cond=condition)
return noise_uncond + guidance_scale * (noise - noise_uncond)
```

直观理解：

- $\epsilon_{\text{cond}}-\epsilon_{\text{uncond}}$ 表示条件带来的方向变化。
- `guidance_scale` 越大，条件影响通常越强。
- 但引导过强也可能降低样本自然度，甚至造成数值不稳定。

---

# 6. 第三部分：`DPM_Solver`

类定义：

```python
class DPM_Solver:
```

这是整份代码的核心。

它负责：

- 选择使用 DPM-Solver 还是 DPM-Solver++。
- 生成时间节点。
- 执行一阶、二阶、三阶更新。
- 执行单步、多步或自适应采样。
- 必要时执行动态阈值处理。

---

## 6.1 构造函数 `__init__()`

重要参数：

```python
def __init__(
    self,
    model_fn,
    noise_schedule,
    algorithm_type="dpmsolver++",
    correcting_x0_fn=None,
    correcting_xt_fn=None,
    thresholding_max_val=1.,
    dynamic_thresholding_ratio=0.995,
):
```

### `algorithm_type`

支持：

```python
"dpmsolver"
"dpmsolver++"
```

区别：

| 算法 | 内部主要使用什么模型值？ |
|---|---|
| `dpmsolver` | 噪声预测 $\epsilon_\theta$ |
| `dpmsolver++` | 数据预测 $x_{0,\theta}$ |

DPM-Solver++ 会先将噪声预测转换成 $x_0$ 预测。

---

## 6.2 为什么 `self.model` 要扩展时间维度？

代码：

```python
self.model = lambda x, t: model_fn(x, t.expand((x.shape[0])))
```

很多内部函数传入的时间 `t` 只有一个元素，例如形状为：

```text
[1]
```

但一个 batch 中可能有多张图片：

```text
x.shape[0] = batch_size
```

模型通常希望每个样本对应一个时间标签，因此扩展成：

```text
[batch_size]
```

例如：

```text
t = [0.5]
```

扩展后：

```text
[0.5, 0.5, 0.5, 0.5]
```

---

## 6.3 动态阈值：`dynamic_thresholding_fn()`

函数定义：

```python
def dynamic_thresholding_fn(self, x0, t):
```

它用于限制过大的 $x_0$ 预测值。

代码：

```python
s = torch.quantile(torch.abs(x0).reshape((x0.shape[0], -1)), p, dim=1)
s = expand_dims(torch.maximum(s, self.thresholding_max_val * torch.ones_like(s).to(s.device)), dims)
x0 = torch.clamp(x0, -s, s) / s
```

处理过程：

1. 对每个样本取 $|x_0|$ 的高分位数。
2. 将该分位数作为样本自适应阈值 $s$。
3. 将值裁剪到 $[-s,s]$。
4. 再除以 $s$，缩放到 $[-1,1]$。

可写成：

$$
x_0\leftarrow\frac{\operatorname{clip}(x_0,-s,s)}{s}
$$

注意：

> 动态阈值常用于像素空间扩散模型，不适合直接用于 Stable Diffusion 一类潜空间模型。

---

## 6.4 `noise_prediction_fn()` 与 `data_prediction_fn()`

### 噪声预测

```python
def noise_prediction_fn(self, x, t):
    return self.model(x, t)
```

### 数据预测

根据：

$$
x_t=\alpha_tx_0+\sigma_t\epsilon
$$

反解：

$$
x_0=\frac{x_t-\sigma_t\epsilon}{\alpha_t}
$$

代码：

```python
noise = self.noise_prediction_fn(x, t)
alpha_t, sigma_t = self.noise_schedule.marginal_alpha(t), self.noise_schedule.marginal_std(t)
x0 = (x - sigma_t * noise) / alpha_t
```

然后按需修正：

```python
if self.correcting_x0_fn is not None:
    x0 = self.correcting_x0_fn(x0, t)
```

---

## 6.5 类内部的 `model_fn()`

代码：

```python
def model_fn(self, x, t):
    if self.algorithm_type == "dpmsolver++":
        return self.data_prediction_fn(x, t)
    else:
        return self.noise_prediction_fn(x, t)
```

这一步很关键。

从此以后，后面的高阶公式不需要反复判断神经网络原始预测类型，而只需要根据算法类型决定：

- DPM-Solver++ 使用 $x_0$ 预测。
- DPM-Solver 使用 $\epsilon$ 预测。

## 6.6 `get_time_steps()`：如何分配采样时间点？

函数定义：

```python
def get_time_steps(self, skip_type, t_T, t_0, N, device):
```

支持三种时间步分配方法。

---

### 6.6.1 `skip_type='logSNR'`

代码先在 $\lambda$ 空间均匀取点：

```python
logSNR_steps = torch.linspace(lambda_T.cpu().item(), lambda_0.cpu().item(), N + 1).to(device)
return self.noise_schedule.inverse_lambda(logSNR_steps)
```

也就是：

$$
\lambda_0,\lambda_1,\ldots,\lambda_N
$$

等间距，再映射回时间 $t$。

特点：

- 在信噪比变化角度上较均匀。
- 常用于低分辨率图像。

---

### 6.6.2 `skip_type='time_uniform'`

直接在时间空间均匀取点：

```python
return torch.linspace(t_T, t_0, N + 1).to(device)
```

特点：

- 简单。
- 常推荐用于高分辨率数据。

---

### 6.6.3 `skip_type='time_quadratic'`

代码：

```python
t_order = 2
t = torch.linspace(t_T**(1. / t_order), t_0**(1. / t_order), N + 1).pow(t_order).to(device)
```

先对 $\sqrt{t}$ 均匀取点，再平方。

特点：

- 时间节点密度与均匀时间不同。
- DDIM 在部分低分辨率任务中使用类似方案。

---

## 6.7 `denoise_to_zero_fn()`

代码：

```python
def denoise_to_zero_fn(self, x, s):
    return self.data_prediction_fn(x, s)
```

它在最后额外进行一次 $x_0$ 预测。

作用：

> 将接近 $t=0$ 的样本进一步直接映射为估计的干净样本。

代价：

- 额外调用一次神经网络。
- 因此 NFE 增加 1。

# 7. 一阶、二阶、三阶求解器到底在做什么

这一部分是理解 DPM-Solver 的核心。

---

## 7.1 什么是 NFE？

NFE 是 **Number of Function Evaluations**，即模型函数调用次数。

对于扩散模型，模型通常很大，因此模型推理是最耗时的部分。

例如：

- 一阶单步方法：每个区间通常调用模型 1 次。
- 二阶单步方法：每个区间通常调用模型 2 次。
- 三阶单步方法：每个区间通常调用模型 3 次。

高阶公式单次更贵，但单步更准确，因此可以使用更少的外层区间。

---

## 7.2 一阶更新：`dpm_solver_first_update()`

函数定义：

```python
def dpm_solver_first_update(self, x, s, t, model_s=None, return_intermediate=False):
```

它从时间 $s$ 更新到时间 $t$。

先定义：

$$
h=\lambda_t-\lambda_s
$$

由于反向采样通常从噪声较强的位置走向噪声较弱的位置，$\lambda$ 通常逐渐增大，因此通常有：

$$
h>0
$$

---

### 7.2.1 DPM-Solver++ 的一阶公式

代码：

```python
phi_1 = torch.expm1(-h)
x_t = (
    sigma_t / sigma_s * x
    - alpha_t * phi_1 * model_s
)
```

因为：

$$
\operatorname{expm1}(-h)=e^{-h}-1
$$

所以：

$$
-\phi_1=1-e^{-h}
$$

公式可写成：

$$
x_t
=
\frac{\sigma_t}{\sigma_s}x_s
+
\alpha_t(1-e^{-h})x_{0,\theta}(x_s,s)
$$
![alt text](image-2.png)
其中 `model_s` 是模型在起点 $s$ 处对 $x_0$ 的预测。

直观理解：

1. 先根据噪声尺度变化传播原状态。
2. 再利用模型预测的干净数据修正结果。

---

### 7.2.2 原始 DPM-Solver 的一阶公式

代码：

```python
phi_1 = torch.expm1(h)
x_t = (
    torch.exp(log_alpha_t - log_alpha_s) * x
    - (sigma_t * phi_1) * model_s
)
```

对应：

$$
x_t
=
\frac{\alpha_t}{\alpha_s}x_s
-
\sigma_t(e^h-1)\epsilon_\theta(x_s,s)
$$

其中 `model_s` 是噪声预测。

推导思路：
![alt text](image-3.png)

---

## 7.3 为什么使用 `torch.expm1()`？

`torch.expm1(z)` 计算：

$$
e^z-1
$$

为什么不直接写：

```python
torch.exp(z) - 1
```

因为当 $z$ 非常小时：

$$
e^z\approx 1+z
$$

此时先计算两个非常接近的数再相减，容易损失精度。

`expm1()` 对小数值情况做了专门优化，数值更加稳定。

---

## 7.4 二阶单步更新：增加一个中间点

函数定义：

```python
def singlestep_dpm_solver_second_update(self, x, s, t, r1=0.5, ...):
```

一阶方法只在起点 $s$ 评估模型。

二阶方法在区间内部再选择一个中间点：

$$
\lambda_{s_1}=\lambda_s+r_1h
$$

默认：

$$
r_1=0.5
$$

也就是 $\lambda$ 区间中点。

代码：

```python
lambda_s1 = lambda_s + r1 * h
s1 = ns.inverse_lambda(lambda_s1)
```

注意：中点是在 $\lambda$ 空间中选择，不一定是普通时间 $t$ 的算术中点。

---

### 7.4.1 二阶方法的思路

1. 在起点 $s$ 调用模型，得到 `model_s`。
2. 使用一阶公式预测中间状态 $x_{s_1}$。
3. 在中间状态调用模型，得到 `model_s1`。
4. 利用差值：

$$
\text{model}_{s_1}-\text{model}_s
$$

估计模型输出在区间内如何变化。
5. 使用该变化量修正终点结果。

例如 DPM-Solver++ 的中间预测：

```python
x_s1 = (
    (sigma_s1 / sigma_s) * x
    - (alpha_s1 * phi_11) * model_s
)
model_s1 = self.model_fn(x_s1, s1)
```

终点更新中增加修正项：

```python
- (0.5 / r1) * (alpha_t * phi_1) * (model_s1 - model_s)
```

直观理解：

> 一阶方法假设模型输出在整个小区间内近似不变。二阶方法检查区间中点，估计模型输出变化趋势，因此更加准确。

---

## 7.5 三阶单步更新：增加两个中间点

函数定义：

```python
def singlestep_dpm_solver_third_update(
    self, x, s, t,
    r1=1./3.,
    r2=2./3.,
    ...
):
```

默认中间位置：

$$
\lambda_{s_1}=\lambda_s+\frac{1}{3}h
$$

$$
\lambda_{s_2}=\lambda_s+\frac{2}{3}h
$$

三阶方法的思路：

1. 在起点计算模型值。
2. 在第一个中间点计算模型值。
3. 根据已有信息构造第二个中间状态。
4. 在第二个中间点计算模型值。
5. 利用多个差分项，更准确地估计模型输出的变化。

Taylor 形式中，代码显式构造：

```python
D1_0 = (1. / r1) * (model_s1 - model_s)
D1_1 = (1. / r2) * (model_s2 - model_s)
D1 = (r2 * D1_0 - r1 * D1_1) / (r2 - r1)
D2 = 2. * (D1_1 - D1_0) / (r2 - r1)
```

可以粗略理解为：

- `D1`：近似一阶变化趋势。
- `D2`：近似二阶变化趋势，也就是变化趋势本身如何变化。

直观类比：

- 一阶方法只知道当前位置。
- 二阶方法额外估计速度。
- 三阶方法进一步估计“速度的变化”。

这个类比并不等同于严格数学推导，但有助于初学者理解高阶信息为什么能提高精度。

---

## 7.6 `solver_type='dpmsolver'` 与 `'taylor'`

部分高阶函数支持：

```python
solver_type in ['dpmsolver', 'taylor']
```

两者区别在于高阶修正项的离散化形式。

通常代码注释建议优先使用：

```python
solver_type='dpmsolver'
```

原因是它往往表现较好，也是常见推荐配置。

---

## 7.7 单步方法与多步方法的区别

这是非常重要的概念。

### 单步方法 `singlestep`

每个大区间内部自己构造中间点。

例如二阶单步法：

```text
起点 s
  ↓ 调用模型
中间点 s1
  ↓ 调用模型
终点 t
```

特点：

- 每个外层区间内部独立完成。
- 容易理解。
- 高阶时需要在区间内增加模型调用。

### 多步方法 `multistep`

多步法复用前面已经计算过的历史模型值。

例如二阶多步法使用最近两个历史点：

```text
历史点 t_(n-1) 的模型值
历史点 t_n     的模型值
            ↓
预测 t_(n+1)
```

特点：

- 不必在当前区间额外插入中间模型调用。
- 可以复用历史信息。
- 对固定 NFE 通常更高效。
- 启动阶段历史不足，因此前几步必须先用低阶方法。

---

## 7.8 二阶多步更新

函数定义：

```python
def multistep_dpm_solver_second_update(self, x, model_prev_list, t_prev_list, t, solver_type="dpmsolver"):
```

取最近两个模型值：

```python
model_prev_1, model_prev_0 = model_prev_list[-2], model_prev_list[-1]
```

计算历史步长与当前步长：

```python
h_0 = lambda_prev_0 - lambda_prev_1
h = lambda_t - lambda_prev_0
r0 = h_0 / h
```

构造一阶差分：

```python
D1_0 = (1. / r0) * (model_prev_0 - model_prev_1)
```

其意义是：

> 利用前两个点的模型输出变化，估计当前区间中的变化趋势。

---

## 7.9 三阶多步更新

函数定义：

```python
def multistep_dpm_solver_third_update(self, x, model_prev_list, t_prev_list, t, solver_type='dpmsolver'):
```

使用最近三个历史点：

```python
model_prev_2, model_prev_1, model_prev_0 = model_prev_list
```

计算两个一阶差分：

```python
D1_0 = (1. / r0) * (model_prev_0 - model_prev_1)
D1_1 = (1. / r1) * (model_prev_1 - model_prev_2)
```

再组合得到：

```python
D1 = D1_0 + (r0 / (r0 + r1)) * (D1_0 - D1_1)
D2 = (1. / (r0 + r1)) * (D1_0 - D1_1)
```

直观理解：

- `D1_0`：最近一次变化。
- `D1_1`：上一次变化。
- `D1_0 - D1_1`：变化趋势是否正在改变。
- `D2`：用于刻画更高阶变化。

---

## 7.10 自适应步长：`dpm_solver_adaptive()`

固定步长方法提前决定所有时间节点。

自适应方法则根据当前误差动态决定下一步走多远。

函数定义：

```python
def dpm_solver_adaptive(self, x, order, t_T, t_0, h_init=0.05, atol=0.0078, rtol=0.05, theta=0.9, t_err=1e-5, solver_type='dpmsolver'):
```

核心思路：

1. 同时计算一个低阶结果 `x_lower`。
2. 再计算一个高阶结果 `x_higher`。
3. 用二者差异估计误差。
4. 如果误差可接受，就接受本次更新。
5. 如果误差太大，就缩小步长重算。

代码：

```python
E = norm_fn((x_higher - x_lower) / delta).max()
if torch.all(E <= 1.):
    x = x_higher
    s = t
```

其中：

```python
delta = torch.max(
    torch.ones_like(x).to(x) * atol,
    rtol * torch.max(torch.abs(x_lower), torch.abs(x_prev))
)
```

表示允许误差尺度综合考虑：

- 绝对误差容忍度 `atol`。
- 相对误差容忍度 `rtol`。

下一步步长调整：

```python
h = torch.min(theta * h * torch.float_power(E, -1. / order).float(), lambda_0 - lambda_s)
```

直观理解：

- 误差小：下一步可以走得更远。
- 误差大：下一步必须走得更短。

# 8. `sample()`：整份代码真正的主入口

函数定义：

```python
def sample(
    self,
    x,
    steps=20,
    t_start=None,
    t_end=None,
    order=2,
    skip_type='time_uniform',
    method='multistep',
    lower_order_final=True,
    denoise_to_zero=False,
    solver_type='dpmsolver',
    atol=0.0078,
    rtol=0.05,
    return_intermediate=False,
):
```

它接收初始噪声 `x`，输出去噪后的样本。

---

## 8.1 参数解释

| 参数 | 含义 |
|---|---|
| `x` | 初始样本，通常为随机高斯噪声 |
| `steps` | 允许的模型函数调用次数，即 NFE |
| `t_start` | 起始时间，默认是扩散终点 `T=1.0` |
| `t_end` | 结束时间，默认是 `1 / total_N` |
| `order` | 求解器最高阶数，可选 1、2、3 |
| `skip_type` | 时间节点分配方式 |
| `method` | 采样方法：单步、多步、固定阶单步、自适应 |
| `lower_order_final` | 少步采样时，最后几步是否降低阶数以增强稳定性 |
| `denoise_to_zero` | 最后是否额外做一次 $x_0$ 预测 |
| `solver_type` | 高阶修正形式，通常使用 `'dpmsolver'` |
| `atol` | 自适应求解器绝对误差容忍度 |
| `rtol` | 自适应求解器相对误差容忍度 |
| `return_intermediate` | 是否返回每一步中间结果 |

---

## 8.2 默认时间范围

代码：

```python
t_0 = 1. / self.noise_schedule.total_N if t_end is None else t_end
t_T = self.noise_schedule.T if t_start is None else t_start
```

默认：

$$
t_T=1
$$

$$
t_0=\frac{1}{N}
$$

注意变量名：

- `t_T` 表示噪声较强的起点。
- `t_0` 表示噪声较弱的终点。

采样方向是：

$$
t_T\longrightarrow t_0
$$

---

## 8.3 为什么使用 `torch.no_grad()`？

代码：

```python
with torch.no_grad():
```

采样阶段不是训练阶段，不需要反向传播。

关闭 autograd 可以：

- 减少显存占用。
- 减少额外计算。
- 提高推理速度。

但分类器引导中需要梯度，因此 `cond_grad_fn()` 内部会临时重新开启梯度。

---

## 8.4 `method='multistep'`

这是常用模式之一。

代码先生成：

```python
timesteps = self.get_time_steps(..., N=steps, ...)
```

得到 `steps + 1` 个时间节点，对应 `steps` 个区间。

### 启动阶段

高阶多步法需要历史模型值。

例如三阶多步法需要三个历史点，但刚开始只有一个点。因此代码先使用低阶方法填充历史缓存：

```python
for step in range(1, order):
    x = self.multistep_dpm_solver_update(..., order=step, ...)
```

例如 `order=3`：

```text
第 1 步：使用一阶方法
第 2 步：使用二阶方法
后续步骤：使用三阶方法
```

### 常规阶段

缓存足够后：

```python
for step in range(order, steps + 1):
```

执行正式的 `order` 阶多步更新。

### 滑动窗口

每完成一步，删除最旧历史信息，加入最新历史信息：

```python
for i in range(order - 1):
    t_prev_list[i] = t_prev_list[i + 1]
    model_prev_list[i] = model_prev_list[i + 1]
```

这类似一个长度固定的队列。

---

## 8.5 为什么最后几步可能降低阶数？

代码：

```python
if lower_order_final and steps < 10:
    step_order = min(order, steps + 1 - step)
else:
    step_order = order
```

在采样步数非常少时，高阶方法在最后阶段有时可能不稳定。

因此最后几步主动降低阶数，通常能提升稳定性。

例如：

```text
原本希望一直用三阶方法
最后可能改成：三阶 → 二阶 → 一阶
```

---

## 8.6 `method='singlestep'`

`singlestep` 会自动组合一阶、二阶、三阶方法，用满指定 NFE。

代码首先调用：

```python
timesteps_outer, orders = self.get_orders_and_timesteps_for_singlestep_solver(...)
```

例如：

```text
steps = 7
order = 3
```

可能安排为：

```text
三阶 + 三阶 + 一阶
```

总 NFE：

$$
3+3+1=7
$$

每个外层区间再根据当前阶数生成内部节点：

```python
timesteps_inner = self.get_time_steps(..., N=order, ...)
lambda_inner = self.noise_schedule.marginal_lambda(timesteps_inner)
```

随后计算 $r_1$、$r_2$：

```python
r1 = None if order <= 1 else (lambda_inner[1] - lambda_inner[0]) / h
r2 = None if order <= 2 else (lambda_inner[2] - lambda_inner[0]) / h
```

---

## 8.7 `method='singlestep_fixed'`

固定使用同一阶数：

```python
K = steps // order
orders = [order,] * K
```

例如：

```text
steps = 10
order = 3
```

则：

```text
K = 10 // 3 = 3
```

实际使用：

```text
三阶 + 三阶 + 三阶
```

实际 NFE 为：

$$
3\times 3=9
$$

剩余的 1 次不会使用。

---

## 8.8 `method='adaptive'`

代码：

```python
x = self.dpm_solver_adaptive(...)
```

特点：

- 忽略固定 `steps`。
- 根据误差动态决定步长。
- 不支持保存预定义时间序列形式的所有中间状态。
- 不支持 `correcting_xt_fn`。

---

## 8.9 `return_intermediate=True`

设置后会保存中间状态：

```python
intermediates.append(x)
```

最终返回：

```python
return x, intermediates
```

用途：

- 可视化每一步去噪结果。
- 调试采样过程。
- 分析模型在哪些时间段变化最大。

代价：

- 占用更多内存或显存。

---

# 9. 辅助函数：`interpolate_fn` 与 `expand_dims`

---

## 9.1 `interpolate_fn()`：分段线性插值

函数定义：

```python
def interpolate_fn(x, xp, yp):
```

作用：

> 已知若干关键点 $(x_i,y_i)$，输入一个查询值 $x$，估计对应的 $y$。

基本公式：

$$
y
=
y_0+
\frac{x-x_0}{x_1-x_0}(y_1-y_0)
$$

例如已知：

```text
x = 0.2 时，y = 10
x = 0.4 时，y = 20
```

查询：

```text
x = 0.3
```

则：

```text
y = 15
```

### 代码为什么这么复杂？

因为它不仅处理一个标量，还需要：

- 支持 batch。
- 支持多个通道。
- 支持 PyTorch 张量。
- 保持可微分。
- 支持查询点落在已知范围外时进行线性外推。

它先把查询点与关键点放到一起排序：

```python
all_x = torch.cat([x.unsqueeze(2), xp.unsqueeze(0).repeat((N, 1, 1))], dim=2)
sorted_all_x, x_indices = torch.sort(all_x, dim=2)
```

再确定查询点左右邻居，最后应用线性插值公式：

```python
cand = start_y + (x - start_x) * (end_y - start_y) / (end_x - start_x)
```

---

## 9.2 `expand_dims()`：为广播运算增加维度

函数定义：

```python
def expand_dims(v, dims):
    return v[(...,) + (None,)*(dims - 1)]
```

假设：

```python
v.shape == [batch_size]
```

图片张量：

```python
x.shape == [batch_size, channels, height, width]
```

为了让 `v` 与 `x` 相乘，需要将 `v` 变成：

```text
[batch_size, 1, 1, 1]
```

例如：

```python
expand_dims(v, 4)
```

就会得到可广播形状。

### 为什么可以广播？

因为 PyTorch 会自动把大小为 1 的维度扩展到匹配目标张量。

例如：

```text
[4, 1, 1, 1]
×
[4, 3, 256, 256]
```

可以自动广播为：

```text
[4, 3, 256, 256]
```

# 10. 完整调用流程

下面以常见的 DPM-Solver++ 二阶多步采样为例。

---

## 10.1 第一步：创建噪声调度

假设已有 DDPM 训练时使用的 `betas`：

```python
noise_schedule = NoiseScheduleVP(
    schedule='discrete',
    betas=betas,
)
```

此时调度器会准备：

- `log_alpha_array`
- `t_array`
- `total_N`
- `marginal_alpha(t)`
- `marginal_std(t)`
- `marginal_lambda(t)`
- `inverse_lambda(lamb)`

---

## 10.2 第二步：包装模型

假设原模型预测噪声，并使用 CFG：

```python
model_fn = model_wrapper(
    model=model,
    noise_schedule=noise_schedule,
    model_type='noise',
    guidance_type='classifier-free',
    condition=condition,
    unconditional_condition=unconditional_condition,
    guidance_scale=7.5,
)
```

包装后：

```python
model_fn(x, t_continuous) -> predicted_noise
```

---

## 10.3 第三步：创建求解器

```python
solver = DPM_Solver(
    model_fn=model_fn,
    noise_schedule=noise_schedule,
    algorithm_type='dpmsolver++',
)
```

虽然外部包装函数输出噪声，但 DPM-Solver++ 内部会通过：

```python
self.data_prediction_fn(x, t)
```

将噪声转换成 $x_0$ 预测。

---

## 10.4 第四步：生成初始噪声

```python
x = torch.randn(batch_size, channels, height, width, device=device)
```

这相当于起点 $x_T$。

---

## 10.5 第五步：调用 `sample()`

```python
x_sample = solver.sample(
    x=x,
    steps=20,
    order=2,
    skip_type='time_uniform',
    method='multistep',
    lower_order_final=True,
)
```

内部过程大致如下：

```text
随机噪声 x_T
    ↓
生成 21 个时间点，对应 20 个区间
    ↓
第 1 步使用一阶公式启动
    ↓
后续步骤复用最近两个模型值，使用二阶多步更新
    ↓
逐渐降低噪声
    ↓
得到接近 x_0 的样本
```

# 11. 参数应该怎么选

以下是适合入门的经验性说明。实际最优配置仍取决于模型、数据、分辨率与 guidance scale。

---

## 11.1 `algorithm_type`

| 场景 | 可优先尝试 |
|---|---|
| 一般情况 | `'dpmsolver++'` |
| 想对比原始公式 | `'dpmsolver'` |
| 较强 guidance | 通常优先尝试 `'dpmsolver++'` |

---

## 11.2 `method`

| 场景 | 推荐起点 |
|---|---|
| 常规推理 | `'multistep'` |
| 想使用 DPM-Solver-fast 的混合阶数方案 | `'singlestep'` |
| 想固定每段阶数做实验 | `'singlestep_fixed'` |
| 想根据误差自动调步长 | `'adaptive'` |

---

## 11.3 `order`

| 阶数 | 特点 |
|---:|---|
| 1 | 最简单，类似 DDIM 一阶更新 |
| 2 | 精度、稳定性、速度之间较平衡 |
| 3 | 单步近似能力更强，适合部分低引导或实验场景 |

常见起点：

```python
order=2
method='multistep'
algorithm_type='dpmsolver++'
```

---

## 11.4 `steps`

`steps` 是模型评估次数 NFE，而不仅仅是外层循环次数。

入门实验可尝试：

```text
10
15
20
30
```

通常：

- 步数越多，计算越慢。
- 步数增加到一定程度后，质量收益会逐渐减小。
- 极少步数下，应重视 `lower_order_final=True`。

---

## 11.5 `skip_type`

| 数据类型 | 可优先尝试 |
|---|---|
| 高分辨率图片 | `'time_uniform'` |
| 低分辨率图片 | `'logSNR'` |
| 想复现实验或对比 DDIM 风格时间分布 | `'time_quadratic'` |

---

## 11.6 `guidance_scale`

CFG 中：

```python
guidance_scale=1.0
```

相当于直接使用条件预测。

更大的数值通常增强条件一致性，但可能导致：

- 画面过度饱和。
- 细节不自然。
- 数值稳定性下降。
- 采样器对参数更加敏感。

# 12. 容易混淆的概念与常见问题

---

## 12.1 `alpha_t` 与 DDPM 中的 `alphas_cumprod` 是同一个东西吗？

不是。

DDPM 常使用：

$$
\hat{\alpha}_n=\prod_{i=0}^{n}(1-\beta_i)
$$

DPM-Solver 中：

$$
\alpha_{t_n}=\sqrt{\hat{\alpha}_n}
$$

因此：

$$
\log\alpha_{t_n}=\frac{1}{2}\log\hat{\alpha}_n
$$

这就是代码中乘以 `0.5` 的原因。

---

## 12.2 `sigma_t` 是方差还是标准差？

`sigma_t` 是标准差。

噪声项写成：

$$
\sigma_t\epsilon
$$

其中：

$$
\epsilon\sim\mathcal{N}(0,I)
$$

因此噪声项方差是：

$$
\sigma_t^2I
$$

---

## 12.3 为什么 DPM-Solver++ 还要调用噪声预测模型？

因为外部模型通常预测噪声。

DPM-Solver++ 内部需要 $x_0$ 预测，于是通过：

$$
x_0=\frac{x_t-\sigma_t\epsilon_\theta(x_t,t)}{\alpha_t}
$$

完成转换。

---

## 12.4 `singlestep` 与 `multistep` 哪个更像 Runge-Kutta？

从直观上看，`singlestep` 更像 Runge-Kutta：

- 在当前区间内选择中间点。
- 在中间点重新计算模型。
- 使用中间信息提高精度。

`multistep` 更像 Adams-Bashforth 类方法：

- 复用过去多个时间点的信息。
- 当前区间不一定额外插入中间点。

这里只是帮助理解的类比，不代表两者与经典方法完全相同。

---

## 12.5 为什么采样时 `h` 通常为正？

代码定义：

$$
h=\lambda_t-\lambda_s
$$

反向采样从噪声强的位置走向噪声弱的位置：

$$
t:s\longrightarrow t,\quad t<s
$$

而 $\lambda$ 通常随着噪声减弱而增大，所以：

$$
\lambda_t>\lambda_s
$$

因此：

$$
h>0
$$

---

## 12.6 `inverse()` 是什么？

函数定义：

```python
def inverse(self, x, steps=20, t_start=None, t_end=None, ...):
```

它复用 `sample()`，但交换时间方向：

```python
return self.sample(x, steps=steps, t_start=t_0, t_end=t_T, ...)
```

作用：

> 将较干净的样本沿正向时间方向推进到噪声更强的状态。

这可用于部分图像编辑、反演或分析任务。

需要注意：由于数值误差、模型误差与有限步数影响，它通常不是严格意义上的完美可逆变换。

---

## 12.7 `add_noise()` 与 `inverse()` 有什么区别？

### `add_noise()`

直接根据公式：

$$
x_t=\alpha_tx_0+\sigma_t\epsilon
$$

一次性加噪。

### `inverse()`

沿着求解器流程逐步向噪声更强的方向积分。

二者用途不同。

---

## 12.8 代码中有哪些值得注意的实现细节？

### 细节 1：默认字典参数

`model_wrapper()` 使用：

```python
model_kwargs={}
classifier_kwargs={}
```

Python 中通常更稳妥的写法是使用 `None`，再在函数内部创建空字典，以避免可变默认参数被意外修改。

不过本代码没有主动修改这些字典，因此风险相对有限。

### 细节 2：离散时间映射中的 `1000.`

```python
return (t_continuous - 1. / noise_schedule.total_N) * 1000.
```

这里隐含了模型时间标签的尺度约定。迁移到其他项目时需要核对。

### 细节 3：多步三阶函数中的 `solver_type`

`multistep_dpm_solver_third_update()` 接收 `solver_type` 参数，但函数体没有根据该参数分支选择不同公式。阅读时不要误以为它与二阶多步函数的行为完全对称。

### 细节 4：变量名中的 `t_0` 与 `t_T`

在采样函数中：

- `t_T` 是起点，噪声较强。
- `t_0` 是终点，噪声较弱。

这与数组下标顺序容易混淆。

### 细节 5：动态阈值不适用于潜空间模型

代码注释已经特别提示：Stable Diffusion 一类 latent-space 模型通常不应直接使用该动态阈值方案。

# 15. 总结

这份代码可以概括为三层：

## 第一层：定义噪声随时间如何变化

由 `NoiseScheduleVP` 负责。

它提供：

$$
\alpha_t,\quad \sigma_t,\quad \lambda_t,\quad \lambda^{-1}
$$

---

## 第二层：把各种神经网络统一包装成噪声预测器

由 `model_wrapper` 负责。

无论原模型预测：

```text
noise
x_start
v
score
```

都转换为：

```python
model_fn(x, t) -> noise
```

并统一处理：

```text
无条件采样
分类器引导
无分类器引导 CFG
```

---

## 第三层：用高效数值方法完成采样

由 `DPM_Solver` 负责。

它可以使用：

```text
一阶方法
二阶方法
三阶方法
单步方法
多步方法
固定阶数单步方法
自适应步长方法
```

最核心思想是：

> 不要把神经网络当作只能机械调用上千次的黑箱，而是利用扩散 ODE 的特殊数学结构，以更高效的方式逼近反向生成轨迹。

对于第一次运行这份代码，适合作为起点的配置是：

```python
solver = DPM_Solver(
    model_fn=model_fn,
    noise_schedule=noise_schedule,
    algorithm_type='dpmsolver++',
)

x_sample = solver.sample(
    x=x_noise,
    steps=20,
    order=2,
    skip_type='time_uniform',
    method='multistep',
    lower_order_final=True,
)
```

先理解这条最常见路径，再逐步研究三阶单步、自适应步长、动态阈值和反演功能，会更加高效。
