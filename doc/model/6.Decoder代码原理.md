# 扩散轨迹解码器代码原理：面向初学者的完整讲解

> 本文解释一个用于自动驾驶轨迹预测的扩散模型解码器。  
> 代码的核心目标是：**根据场景上下文、规划路线和车辆当前状态，从随机噪声中逐步生成未来轨迹。**

---

# 1. 先用一句话概括这段代码

这段代码实现了一个 **基于扩散模型的多目标轨迹解码器**：

- 输入：自车状态、邻居车辆状态、场景编码、规划路线；
- 训练时：给定带噪轨迹和扩散时间，让神经网络学习如何恢复轨迹；
- 推理时：从随机噪声轨迹出发，使用 DPM-Solver 逐步去噪；
- 输出：自车和若干邻居车辆的未来轨迹。

可以把它理解为：

$$
\text{场景信息}
+
\text{路线信息}
+
\text{随机噪声轨迹}
\longrightarrow
\text{合理的未来轨迹}
$$

---

# 2. 这段代码包含哪些类？

代码中主要定义了三个类：

| 类名 | 作用 |
|---|---|
| `Decoder` | 整个扩散轨迹解码器的入口，区分训练和推理流程 |
| `RouteEncoder` | 将规划路线上的离散车道点压缩成一个路线条件向量 |
| `DiT` | 使用 Diffusion Transformer 对带噪轨迹进行预测 |

此外，代码还调用了其他文件中定义的模块：

| 模块 | 作用 |
|---|---|
| `VPSDE_linear` | 定义线性 VP-SDE 噪声调度 |
| `dpm_sampler` | 使用 DPM-Solver 执行反向扩散采样 |
| `MixerBlock` | 使用 MLP-Mixer 融合 token 信息和通道信息 |
| `TimestepEmbedder` | 将标量扩散时间转换成高维向量 |
| `DiTBlock` | 执行自注意力、交叉注意力和条件调制 |
| `FinalLayer` | 将隐藏特征映射回轨迹状态 |

---

# 3. 需要先理解的张量维度

代码中频繁出现以下符号。

| 符号 | 含义 |
|---|---|
| $B$ | batch size，一次处理多少个场景 |
| $P$ | 联合预测的目标数量 |
| $V$ | 时间点数量或路线点数量 |
| $D$ | 每个 token 的特征维度 |
| $H$ | 隐藏特征维度，代码中通常对应 `hidden_dim` |
| $N$ | 场景上下文 token 数量 |

代码中联合预测：

$$
P=1+\texttt{predicted\_neighbor\_num}
$$

其中：

- 第 $0$ 个目标是自车；
- 后续目标是需要联合预测的邻居车辆。

每个轨迹时间点包含四个状态量：

$$
[x,y,\cos\theta,\sin\theta]
$$

其中：

- $x,y$ 表示二维位置；
- $\cos\theta,\sin\theta$ 表示车辆朝向；
- 使用余弦和正弦表示朝向，可以避免角度在 $-\pi$ 和 $\pi$ 附近发生不连续跳变。

如果未来长度为：

$$
V_{\text{future}}
$$

那么代码会同时保留当前时刻，所以每个目标总共有：

$$
1+V_{\text{future}}
$$

个时间点。

因此，每个目标轨迹压平后的维度为：

$$
\texttt{output\_dim}
=
(1+V_{\text{future}})\times4
$$

---

# 4. 什么是扩散轨迹预测？

## 4.1 前向扩散：逐渐给轨迹加噪声

扩散模型通常定义一个前向过程：

$$
x_t=\alpha_t x_0+\sigma_t\varepsilon
$$

其中：

- $x_0$ 是真实轨迹；
- $x_t$ 是时间 $t$ 的带噪轨迹；
- $\varepsilon\sim\mathcal{N}(0,I)$ 是高斯噪声；
- $\alpha_t$ 控制保留多少真实信号；
- $\sigma_t$ 控制加入多少噪声。

随着 $t$ 增大：

$$
\alpha_t\downarrow
$$

$$
\sigma_t\uparrow
$$

轨迹逐渐被噪声淹没。

---

## 4.2 反向扩散：从噪声恢复轨迹

生成轨迹时，希望执行相反过程：

$$
\text{随机噪声}
\longrightarrow
\text{粗略轨迹}
\longrightarrow
\text{平滑合理轨迹}
$$

代码使用：

```python
from diffusion_planner.model.diffusion_utils.sampling import dpm_sampler
```

调用 DPM-Solver 完成这个过程。

DPM-Solver 是一种数值求解器。它使用神经网络多次预测，在较少的采样步数下逐渐将噪声轨迹修正为合理轨迹。

---

# 5. `Decoder`：整个解码器的入口

`Decoder` 是最外层模块。

它负责：

1. 提取自车和邻居车辆的当前状态；
2. 构造邻居车辆掩码；
3. 获取编码器输出的场景上下文；
4. 训练时直接调用 `DiT`；
5. 推理时从随机噪声开始，调用 DPM-Solver；
6. 将预测结果恢复到真实物理尺度。

---

# 6. `Decoder.__init__()` 逐步解释

## 6.1 保存预测目标数量

代码：

```python
self._predicted_neighbor_num = config.predicted_neighbor_num
```

总预测目标数量为：

$$
P=1+\texttt{predicted\_neighbor\_num}
$$

因为除了邻居车辆，还要预测自车。

---

## 6.2 保存未来轨迹长度

代码：

```python
self._future_len = config.future_len
```

如果：

```python
config.future_len = 80
```

那么模型会预测未来 $80$ 个时间点。

由于代码还保留当前状态，因此内部轨迹总长度为：

$$
81
$$

---

## 6.3 创建 VP-SDE

代码：

```python
self._sde = VPSDE_linear()
```

VP-SDE 是 Variance Preserving SDE，即**方差保持型随机微分方程**。

常见形式为：

$$
\mathrm{d}x_t
=
-\frac{1}{2}\beta(t)x_t\,\mathrm{d}t
+
\sqrt{\beta(t)}\,\mathrm{d}W_t
$$

它一边衰减原始信号，一边加入高斯噪声。

线性调度通常表示：

$$
\beta(t)
=
\beta_0+(\beta_1-\beta_0)t
$$

---

## 6.4 创建 `DiT`

代码：

```python
self.dit = DiT(
    sde=self._sde,
    route_encoder=RouteEncoder(...),
    depth=config.decoder_depth,
    output_dim=(config.future_len + 1) * 4,
    hidden_dim=config.hidden_dim,
    heads=config.num_heads,
    dropout=dpr,
    model_type=config.diffusion_model_type
)
```

`DiT` 是 Diffusion Transformer。

它接收：

- 带噪轨迹；
- 扩散时间；
- 场景上下文；
- 路线信息；
- 无效邻居车辆掩码。

它输出：

- score；
- 或原始轨迹预测 $x_0$。

具体输出类型由：

```python
config.diffusion_model_type
```

决定。

---

## 6.5 保存归一化器

代码：

```python
self._state_normalizer = config.state_normalizer
self._observation_normalizer = config.observation_normalizer
```

神经网络通常更容易处理尺度比较稳定的数据。

例如，真实坐标可能是：

$$
x=35.2\text{ m}
$$

$$
y=-17.6\text{ m}
$$

训练前可以将其映射到较小范围。

推理完成后，需要调用：

```python
self._state_normalizer.inverse(...)
```

恢复到真实尺度。

---

## 6.6 保存 guidance 函数

代码：

```python
self._guidance_fn = config.guidance_fn
```

guidance 可以理解为：

> 在生成轨迹时额外施加约束，引导采样结果更符合某些目标。

例如：

- 避免碰撞；
- 尽量靠近路线；
- 保持平滑；
- 满足交通规则。

如果：

```python
self._guidance_fn is None
```

则执行普通无条件采样。

如果不为 `None`，则执行带 classifier guidance 的采样。

---

# 7. `Decoder.forward()`：训练与推理的总流程

`forward()` 中最重要的判断是：

```python
if self.training:
    ...
else:
    ...
```

PyTorch 中：

- `model.train()` 会设置 `self.training=True`；
- `model.eval()` 会设置 `self.training=False`。

因此，同一个 `Decoder` 在训练和推理时会走不同流程。

---

# 8. 第一步：提取自车和邻居车辆当前状态

## 8.1 提取自车当前状态

代码：

```python
ego_current = inputs['ego_current_state'][:, None, :4]
```

假设原始形状为：

$$
[B,D]
$$

取前四个状态量后：

$$
[B,4]
$$

使用：

```python
[:, None, :]
```

增加一个目标维度，得到：

$$
[B,1,4]
$$

这个 `1` 表示自车只有一个。

---

## 8.2 提取邻居车辆当前状态

代码：

```python
neighbors_current = inputs["neighbor_agents_past"][
    :, :self._predicted_neighbor_num, -1, :4
]
```

假设邻居历史轨迹形状为：

$$
[B,P_{\text{neighbor}},V_{\text{history}},D]
$$

代码做了三件事：

1. 只取前 `predicted_neighbor_num` 个邻居；
2. 只取最后一个历史时刻；
3. 只取前四个状态量。

得到：

$$
[B,\texttt{predicted\_neighbor\_num},4]
$$

---

## 8.3 判断邻居车辆是否有效

代码：

```python
neighbor_current_mask = (
    torch.sum(torch.ne(neighbors_current[..., :4], 0), dim=-1) == 0
)
```

解释：

```python
torch.ne(neighbors_current[..., :4], 0)
```

检查四个状态量是否不等于零。

如果四个状态量全部为零，则：

```python
torch.sum(..., dim=-1) == 0
```

结果为 `True`。

因此：

| `neighbor_current_mask` 值 | 含义 |
|---|---|
| `True` | 邻居车辆无效，是 padding |
| `False` | 邻居车辆有效 |

---

## 8.4 拼接自车和邻居车辆

代码：

```python
current_states = torch.cat([ego_current, neighbors_current], dim=1)
```

得到：

$$
[B,P,4]
$$

其中：

$$
P=1+\texttt{predicted\_neighbor\_num}
$$

拼接顺序为：

$$
[\text{自车},\text{邻居 1},\text{邻居 2},\ldots]
$$

---

# 9. 第二步：读取场景上下文和路线

代码：

```python
ego_neighbor_encoding = encoder_outputs['encoding']
route_lanes = inputs['route_lanes']
```

`encoder_outputs['encoding']` 来自前面的场景编码器，通常包含：

- 动态交通参与者；
- 静态障碍物；
- 道路车道。

常见形状为：

$$
[B,N_{\text{context}},H]
$$

其中：

- $N_{\text{context}}$ 是上下文 token 数；
- $H$ 是隐藏维度。

`route_lanes` 表示规划路线上的车道点。

---

# 10. 训练阶段流程

训练分支：

```python
if self.training:
    sampled_trajectories = inputs['sampled_trajectories'].reshape(B, P, -1)
    diffusion_time = inputs['diffusion_time']

    return {
        "score": self.dit(
            sampled_trajectories,
            diffusion_time,
            ego_neighbor_encoding,
            route_lanes,
            neighbor_current_mask
        ).reshape(B, P, -1, 4)
    }
```

---

## 10.1 `sampled_trajectories` 是什么？

形状通常为：

$$
[B,P,1+V_{\text{future}},4]
$$

压平后：

$$
[B,P,(1+V_{\text{future}})\times4]
$$

代码：

```python
.reshape(B, P, -1)
```

将每个目标的完整轨迹视为一个长向量。

需要注意：

> 这个 `Decoder` 本身没有在训练分支中显式加噪声。  
> 因此，`sampled_trajectories` 应当由上游训练代码提前构造好。

通常上游会执行类似：

$$
x_t=\alpha_t x_0+\sigma_t\varepsilon
$$

然后把 $x_t$ 作为 `sampled_trajectories` 输入。

---

## 10.2 `diffusion_time` 是什么？

代码：

```python
diffusion_time = inputs['diffusion_time']
```

形状通常为：

$$
[B]
$$

每个 batch 样本可以使用不同的扩散时间：

$$
t\in[0,1]
$$

时间越大，轨迹通常越接近噪声。

---

## 10.3 训练时输出是什么？

代码统一使用键名：

```python
"score"
```

但是，需要注意：

> 键名 `"score"` 不一定表示模型实际输出一定是 score。

因为 `DiT` 支持：

```python
model_type="score"
```

或：

```python
model_type="x_start"
```

如果配置为 `"x_start"`，返回值实际上是原始无噪轨迹预测。

---

# 11. 推理阶段流程

推理分支的目标是：

$$
\text{随机噪声轨迹}
\longrightarrow
\text{预测未来轨迹}
$$

---

## 11.1 构造初始噪声轨迹 `xT`

代码：

```python
xT = torch.cat(
    [
        current_states[:, :, None],
        torch.randn(B, P, self._future_len, 4).to(current_states.device) * 0.5
    ],
    dim=2
).reshape(B, P, -1)
```

第一部分：

```python
current_states[:, :, None]
```

形状为：

$$
[B,P,1,4]
$$

表示真实当前状态。

第二部分：

```python
torch.randn(B, P, self._future_len, 4) * 0.5
```

形状为：

$$
[B,P,V_{\text{future}},4]
$$

表示未来轨迹的随机噪声。

拼接后：

$$
[B,P,1+V_{\text{future}},4]
$$

再压平：

$$
[B,P,(1+V_{\text{future}})\times4]
$$

---

## 11.2 为什么当前状态不能随机生成？

轨迹预测问题中，当前状态是已知的。

因此，模型只需要预测未来，不应该修改当前状态。

初始轨迹可以理解为：

$$
[
\underbrace{x_{\text{current}}}_{\text{已知，固定}},
\underbrace{\varepsilon_1,\varepsilon_2,\ldots,\varepsilon_V}_{\text{随机初始化，等待去噪}}
]
$$

---

## 11.3 为什么随机噪声乘以 `0.5`？

代码使用：

```python
torch.randn(...) * 0.5
```

而不是直接使用标准高斯噪声。

这表示未来状态的初始噪声标准差为：

$$
0.5
$$

而不是：

$$
1
$$

这是当前项目中的实现选择。

它是否最合适，需要结合：

- 状态归一化尺度；
- SDE 的终点分布；
- 训练时使用的噪声幅值；
- 项目实验设置。

进行确认。

从标准扩散模型理论看，终点通常接近：

$$
\mathcal{N}(0,I)
$$

因此，这个 `0.5` 是值得在调试或复现实验时特别关注的细节。

---

# 12. `initial_state_constraint()`：固定当前状态

代码：

```python
def initial_state_constraint(xt, t, step):
    xt = xt.reshape(B, P, -1, 4)
    xt[:, :, 0, :] = current_states
    return xt.reshape(B, P, -1)
```

它在每次 DPM-Solver 更新后执行。

作用是：

$$
x_t[:,:,0,:]
=
x_{\text{current}}
$$

也就是说，第 $0$ 个轨迹时间点始终被强制覆盖为真实当前状态。

---

## 12.1 为什么需要每一步都覆盖？

反向扩散更新通常会修改整个输入张量。

如果不加约束，当前状态也可能在采样过程中被改变。

但实际任务中，当前状态已知，所以必须保持不变。

可以把它理解为：

> 只允许神经网络生成未来，不允许它改写历史事实。

---

# 13. 使用 DPM-Solver 采样

代码：

```python
x0 = dpm_sampler(
    self.dit,
    xT,
    other_model_params={...},
    dpm_solver_params={...},
    model_wrapper_params={...},
)
```

---

## 13.1 `self.dit`

它是轨迹去噪模型。

DPM-Solver 会在不同扩散时间多次调用：

```python
self.dit(x_t, t, ...)
```

逐步修正轨迹。

---

## 13.2 `other_model_params`

代码：

```python
other_model_params={
    "cross_c": ego_neighbor_encoding,
    "route_lanes": route_lanes,
    "neighbor_current_mask": neighbor_current_mask
}
```

这些参数不会随着采样步骤改变。

它们是固定条件：

- 场景上下文；
- 路线；
- 邻居有效性掩码。

---

## 13.3 `correcting_xt_fn`

代码：

```python
dpm_solver_params={
    "correcting_xt_fn": initial_state_constraint,
}
```

DPM-Solver 每更新一次 $x_t$ 后，就调用：

```python
initial_state_constraint(...)
```

固定当前状态。

---

## 13.4 guidance 参数

代码：

```python
"guidance_type": "classifier" if self._guidance_fn is not None else "uncond"
```

如果存在 guidance 函数：

```python
self._guidance_fn is not None
```

则使用：

```python
"classifier"
```

否则使用：

```python
"uncond"
```

---

## 13.5 guidance 强度

代码：

```python
"guidance_scale": 0.5
```

该参数控制 guidance 修正的强度。

数值越大，额外约束对生成过程的影响通常越强。

# 14. 推理结果恢复到真实尺度

代码：

```python
x0 = self._state_normalizer.inverse(
    x0.reshape(B, P, -1, 4)
)[:, :, 1:]
```

步骤如下。

第一步，恢复轨迹结构：

$$
[B,P,(1+V_{\text{future}})\times4]
\longrightarrow
[B,P,1+V_{\text{future}},4]
$$

第二步，执行逆归一化：

$$
\text{归一化状态}
\longrightarrow
\text{真实物理状态}
$$

第三步，删除当前时刻：

```python
[:, :, 1:]
```

最终只返回未来轨迹：

$$
[B,P,V_{\text{future}},4]
$$

---

# 15. `RouteEncoder`：如何编码路线？

`RouteEncoder` 的目标是：

> 将规划路线上的大量离散点压缩成一个固定长度向量。

输入形状：

$$
[B,P_{\text{route}},V_{\text{lane}},D]
$$

其中：

- $P_{\text{route}}$：路线包含多少段车道；
- $V_{\text{lane}}$：每段车道包含多少个离散点；
- $D$：每个点的特征维度。

---

## 15.1 只保留前四个几何特征

代码：

```python
x = x[..., :4]
```

保留：

$$
[x,y,x'-x,y'-y]
$$

其中：

- $x,y$：路线点位置；
- $x'-x,y'-y$：路线方向向量。

---

## 15.2 构造路线掩码

代码：

```python
mask_v = torch.sum(torch.ne(x[..., :4], 0), dim=-1).to(x.device) == 0
mask_p = torch.sum(~mask_v, dim=-1) == 0
mask_b = torch.sum(~mask_p, dim=-1) == 0
```

三个掩码的意义：

| 掩码 | 形状 | 含义 |
|---|---|---|
| `mask_v` | $[B,P,V]$ | 某个路线点是否为空 |
| `mask_p` | $[B,P]$ | 某段车道是否完全为空 |
| `mask_b` | $[B]$ | 某个 batch 的整条路线是否为空 |

---

## 15.3 将整条路线展平

代码：

```python
x = x.view(B, P * V, -1)
```

形状变化：

$$
[B,P,V,4]
\longrightarrow
[B,P\times V,4]
$$

也就是说，将多段车道拼成一条长 token 序列。

---

## 15.4 只处理有效路线

代码：

```python
valid_indices = ~mask_b.view(-1)
x = x[valid_indices]
```

无效路线不会进入后续 MLP。

---

## 15.5 点特征投影

代码：

```python
x = self.channel_pre_project(x)
```

其中：

```python
self.channel_pre_project = Mlp(
    in_features=4,
    hidden_features=channels_mlp_dim,
    out_features=channels_mlp_dim,
    ...
)
```

对每个路线点执行：

$$
\mathbb{R}^{4}
\longrightarrow
\mathbb{R}^{C}
$$

形状变化：

$$
[B_{\text{valid}},P\times V,4]
\longrightarrow
[B_{\text{valid}},P\times V,C]
$$

---

## 15.6 token 预投影

代码：

```python
x = x.permute(0, 2, 1)
x = self.token_pre_project(x)
x = x.permute(0, 2, 1)
```

先变换形状：

$$
[B_{\text{valid}},P\times V,C]
\longrightarrow
[B_{\text{valid}},C,P\times V]
$$

此时最后一个维度是路线点数量。

`token_pre_project` 会沿路线点维度做 MLP：

$$
P\times V
\longrightarrow
T_{\text{mixer}}
$$

得到：

$$
[B_{\text{valid}},C,T_{\text{mixer}}]
$$

再换回：

$$
[B_{\text{valid}},T_{\text{mixer}},C]
$$

---

## 15.7 `MixerBlock`

代码：

```python
x = self.Mixer(x)
```

`MixerBlock` 同时做两件事：

1. Token Mixing：让不同路线位置之间交换信息；
2. Channel Mixing：让不同隐藏通道之间交换信息。

---

## 15.8 平均池化

代码：

```python
x = torch.mean(x, dim=1)
```

形状：

$$
[B_{\text{valid}},T_{\text{mixer}},C]
\longrightarrow
[B_{\text{valid}},C]
$$

所有路线 token 被压缩成一个向量。

---

## 15.9 最终投影

代码：

```python
x = self.emb_project(self.norm(x))
```

将路线向量投影到：

$$
[B_{\text{valid}},H]
$$

最后写回所有 batch：

```python
x_result[valid_indices] = x
```

无效路线保持全零向量。

最终输出：

$$
[B,H]
$$

---

# 16. `DiT`：扩散 Transformer

`DiT` 的目标是：

> 根据带噪轨迹、扩散时间、路线信息和场景上下文，预测去噪方向或原始轨迹。

---

# 17. `DiT.__init__()` 中的组件

## 17.1 模型类型

代码：

```python
assert model_type in ["score", "x_start"]
```

支持两种输出。

### score 参数化

网络输出：

$$
s_\theta(x_t,t)
\approx
\nabla_{x_t}\log q_t(x_t)
$$

score 可以理解为：

> 当前带噪轨迹应该向哪个方向移动，才能回到更高概率区域？

### `x_start` 参数化

网络直接预测：

$$
\hat{x}_0
$$

也就是无噪轨迹。

---

## 17.2 目标类型嵌入

代码：

```python
self.agent_embedding = nn.Embedding(2, hidden_dim)
```

保存两个可学习向量：

| 索引 | 含义 |
|---|---|
| `0` | 自车 embedding |
| `1` | 邻居车辆 embedding |

这样模型可以区分：

- 第一个 token 是自车；
- 后续 token 是邻居车辆。

---

## 17.3 输入轨迹投影

代码：

```python
self.preproj = Mlp(
    in_features=output_dim,
    hidden_features=512,
    out_features=hidden_dim,
    act_layer=nn.GELU,
    drop=0.
)
```

将每个目标压平后的完整轨迹：

$$
\mathbb{R}^{(1+V_{\text{future}})\times4}
$$

映射为隐藏向量：

$$
\mathbb{R}^{H}
$$

---

## 17.4 时间步嵌入

代码：

```python
self.t_embedder = TimestepEmbedder(hidden_dim)
```

扩散时间 $t$ 是一个标量，但神经网络需要高维向量。

因此，将：

$$
t
$$

转换为：

$$
e_t\in\mathbb{R}^{H}
$$

该模块通常使用正弦余弦编码加 MLP。

---

## 17.5 多个 `DiTBlock`

代码：

```python
self.blocks = nn.ModuleList([
    DiTBlock(hidden_dim, heads, dropout, mlp_ratio)
    for i in range(depth)
])
```

每一个 `DiTBlock` 会执行：

1. 条件调制；
2. 轨迹 token 之间的自注意力；
3. MLP；
4. 从场景上下文读取信息的交叉注意力；
5. 第二个 MLP。

---

## 17.6 最终输出层

代码：

```python
self.final_layer = FinalLayer(hidden_dim, output_dim)
```

将：

$$
[B,P,H]
$$

重新映射为：

$$
[B,P,(1+V_{\text{future}})\times4]
$$

---

# 18. `DiT.forward()` 逐步解释

输入：

```python
x
t
cross_c
route_lanes
neighbor_current_mask
```

对应：

| 参数 | 常见形状 | 含义 |
|---|---|---|
| `x` | $[B,P,\texttt{output\_dim}]$ | 当前带噪轨迹 |
| `t` | $[B]$ | 扩散时间 |
| `cross_c` | $[B,N,H]$ | 场景上下文 |
| `route_lanes` | $[B,P_{\text{route}},V_{\text{lane}},D]$ | 路线车道 |
| `neighbor_current_mask` | $[B,P-1]$ | 无效邻居掩码 |

---

## 18.1 轨迹投影

代码：

```python
x = self.preproj(x)
```

形状变化：

$$
[B,P,\texttt{output\_dim}]
\longrightarrow
[B,P,H]
$$

---

## 18.2 添加目标类型嵌入

代码：

```python
x_embedding = torch.cat([
    self.agent_embedding.weight[0][None, :],
    self.agent_embedding.weight[1][None, :].expand(P - 1, -1)
], dim=0)

x_embedding = x_embedding[None, :, :].expand(B, -1, -1)
x = x + x_embedding
```

得到：

$$
[\text{自车 embedding},\text{邻居 embedding},\ldots]
$$

并加到轨迹特征上。

---

## 18.3 构造条件向量 `y`

代码：

```python
route_encoding = self.route_encoder(route_lanes)
y = route_encoding
y = y + self.t_embedder(t)
```

即：

$$
y
=
e_{\text{route}}
+
e_t
$$

其中：

- $e_{\text{route}}$ 是路线编码；
- $e_t$ 是扩散时间编码。

最终：

$$
y\in\mathbb{R}^{B\times H}
$$

这个向量会用于调制各个 `DiTBlock`。

---

## 18.4 构造注意力掩码

代码：

```python
attn_mask = torch.zeros((B, P), dtype=torch.bool, device=x.device)
attn_mask[:, 1:] = neighbor_current_mask
```

第 $0$ 个 token 是自车，所以始终有效。

后续 token 是邻居车辆，根据 `neighbor_current_mask` 屏蔽无效项。

---

## 18.5 执行多个 `DiTBlock`

代码：

```python
for block in self.blocks:
    x = block(x, cross_c, y, attn_mask)
```

每一层都让：

- 自车和邻居轨迹 token 相互交流；
- 轨迹 token 从场景上下文读取道路和障碍物信息；
- 路线和扩散时间影响当前特征变换方式。

---

## 18.6 最终输出

代码：

```python
x = self.final_layer(x, y)
```

输出：

$$
[B,P,\texttt{output\_dim}]
$$

---

# 19. score 输出为何要除以标准差？

代码：

```python
if self._model_type == "score":
    return x / (self.marginal_prob_std(t)[:, None, None] + 1e-6)
```

即：

$$
s_\theta(x_t,t)
=
\frac{f_\theta(x_t,t)}
{\sigma_t+\varepsilon}
$$

其中：

- $f_\theta$ 是网络原始输出；
- $\sigma_t$ 是边缘分布标准差；
- `1e-6` 用于避免除零。

这种写法让网络原始输出更接近一个经过尺度归一化的量。

扩散模型中常见关系为：

$$
\varepsilon_\theta(x_t,t)
=
-\sigma_t s_\theta(x_t,t)
$$

也就是说：

$$
s_\theta(x_t,t)
=
-\frac{\varepsilon_\theta(x_t,t)}{\sigma_t}
$$

因此，score 的典型尺度通常与：

$$
\frac{1}{\sigma_t}
$$

有关。

# 21. 训练和推理的差异

| 项目 | 训练阶段 | 推理阶段 |
|---|---|---|
| 输入轨迹 | 上游提供的带噪轨迹 | 当前状态 + 随机未来噪声 |
| 扩散时间 | 上游随机采样 | DPM-Solver 自动选择 |
| 调用模型次数 | 通常一次 | 多次 |
| 是否调用 DPM-Solver | 否 | 是 |
| 是否固定当前状态 | 由上游数据决定 | 每一步显式强制固定 |
| 输出 | score 或 $x_0$ 预测 | 最终未来轨迹 |

# 22. 代码中值得特别注意的细节

## 22.1 `math` 和 `DropPath` 在当前文件中没有使用

代码导入：

```python
import math
from timm.layers import DropPath
```

但当前文件没有直接调用它们。

这不会影响运行，但可以视为冗余导入。

---

## 22.2 训练分支不负责显式加噪

训练分支直接读取：

```python
inputs['sampled_trajectories']
```

所以，加噪逻辑应该位于数据处理或训练循环中。

---

## 22.3 输出字典键名 `"score"` 可能不够精确

即使：

```python
model_type="x_start"
```

训练分支仍然返回：

```python
{"score": ...}
```

这可能使阅读者误以为输出始终是 score。

调试时应根据：

```python
self.dit.model_type
```

确认真实语义。

---

## 22.4 初始噪声乘以 `0.5`

推理代码：

```python
torch.randn(...) * 0.5
```

这不是最标准的单位高斯初始化写法。

应结合项目训练设置验证是否有意为之。

---

## 22.5 无效邻居 mask 只传给轨迹自注意力

`neighbor_current_mask` 用于 DiT 内部的目标 token 自注意力。

场景上下文 `cross_c` 在当前文件中没有额外传入上下文 mask。

是否安全，需要结合场景编码器和 `DiTBlock` 中交叉注意力的实现检查。

---

## 22.6 当前状态通过硬约束固定

推理时：

```python
xt[:, :, 0, :] = current_states
```

这是硬约束，而不是软约束。

含义是：当前状态必须严格保持不变。

# 26. 总结

这段代码实现了一个用于自动驾驶轨迹预测的扩散解码器。

核心流程为：

$$
\boxed{
\text{随机未来轨迹}
+
\text{已知当前状态}
+
\text{场景上下文}
+
\text{路线条件}
\longrightarrow
\text{未来轨迹预测}
}
$$

最关键的三个模块是：

1. `RouteEncoder`：把路线压缩成条件向量；
2. `DiT`：根据条件预测 score 或原始轨迹；
3. `Decoder`：组织训练流程，并在推理时调用 DPM-Solver 逐步去噪。

推理阶段最重要的约束是：

$$
\boxed{
x_t[:,:,0,:]
=
x_{\text{current}}
}
$$

也就是说，当前状态始终固定，模型只生成未来轨迹。
