# Diffusion Planner 接入 nuPlan 的规划器代码详解

## 0. 这份代码在整个项目中扮演什么角色？

这份代码定义了一个名为：

```python
DiffusionPlanner
```

的规划器类。

它的核心作用是：

> 将 Diffusion Planner 神经网络接入 nuPlan 仿真框架，使 nuPlan 可以在每一个规划周期调用扩散模型，并获得一条可以执行和评测的未来轨迹。

这份代码不是扩散模型内部的网络实现，也不是 DPM-Solver 的数学实现。

它更像一个“翻译器”和“总调度员”：

```text
nuPlan 仿真器提供的原始场景
    ↓
DataProcessor：转换成模型可以理解的张量
    ↓
Normalizer：按照训练时的规则归一化
    ↓
Diffusion_Planner：调用 Encoder、Decoder 和扩散采样器
    ↓
模型输出局部坐标系中的未来轨迹
    ↓
转换为 nuPlan 标准状态序列
    ↓
InterpolatedTrajectory：构造可插值轨迹
    ↓
返回给 nuPlan 仿真器
```

如果将整个系统类比为一名驾驶员：

| 模块 | 类比 |
|---|---|
| nuPlan 仿真器 | 驾驶环境 |
| `PlannerInput` | 驾驶员此刻看到的道路、车辆和红绿灯 |
| `DataProcessor` | 将复杂场景整理成结构化信息 |
| `Diffusion_Planner` | 驾驶员的大脑 |
| 模型输出 | 未来几秒准备怎么走 |
| `InterpolatedTrajectory` | 一条可供车辆跟踪的连续参考轨迹 |

# 1. 去掉注释后的代码骨架

这份文件虽然注释很多，但核心结构并不复杂：

```python
import warnings

import torch
import numpy as np

from typing import Deque, Dict, List, Type

from nuplan.common.actor_state.ego_state import EgoState
from nuplan.common.utils.interpolatable_state import InterpolatableState
from nuplan.planning.simulation.trajectory.trajectory_sampling import TrajectorySampling
from nuplan.planning.simulation.trajectory.abstract_trajectory import AbstractTrajectory
from nuplan.planning.simulation.trajectory.interpolated_trajectory import InterpolatedTrajectory
from nuplan.planning.simulation.observation.observation_type import Observation, DetectionsTracks
from nuplan.planning.simulation.planner.ml_planner.transform_utils import transform_predictions_to_states
from nuplan.planning.simulation.planner.abstract_planner import (
    AbstractPlanner, PlannerInitialization, PlannerInput
)

from diffusion_planner.model.diffusion_planner import Diffusion_Planner
from diffusion_planner.data_process.data_processor import DataProcessor
from diffusion_planner.utils.config import Config


def identity(ego_state, predictions):
    return predictions


class DiffusionPlanner(AbstractPlanner):
    def __init__(
            self,
            config: Config,
            ckpt_path: str,
            past_trajectory_sampling: TrajectorySampling, 
            future_trajectory_sampling: TrajectorySampling,
            enable_ema: bool = True,
            device: str = "cpu",
        ):
        assert device in ["cpu", "cuda"], f"device {device} not supported"

        if device == "cuda":
            assert torch.cuda.is_available(), "cuda is not available"

        self._future_horizon = future_trajectory_sampling.time_horizon
        self._step_interval = (
            future_trajectory_sampling.time_horizon
            / future_trajectory_sampling.num_poses
        )

        self._config = config
        self._ckpt_path = ckpt_path
        self._past_trajectory_sampling = past_trajectory_sampling
        self._future_trajectory_sampling = future_trajectory_sampling
        self._ema_enabled = enable_ema
        self._device = device

        self._planner = Diffusion_Planner(config)
        self.data_processor = DataProcessor(config)
        self.observation_normalizer = config.observation_normalizer

    def name(self) -> str:
        return "diffusion_planner"

    def observation_type(self) -> Type[Observation]:
        return DetectionsTracks

    def initialize(self, initialization: PlannerInitialization) -> None:
        self._map_api = initialization.map_api
        self._route_roadblock_ids = initialization.route_roadblock_ids

        if self._ckpt_path is not None:
            state_dict: Dict = torch.load(
                self._ckpt_path,
                map_location=self._device
            )

            if self._ema_enabled:
                state_dict = state_dict["ema_state_dict"]
            else:
                if "model" in state_dict.keys():
                    state_dict = state_dict["model"]

            model_state_dict = {
                k[len("module."):]: v
                for k, v in state_dict.items()
                if k.startswith("module.")
            }

            self._planner.load_state_dict(model_state_dict)
        else:
            print("load random model")

        self._planner.eval()
        self._planner = self._planner.to(self._device)
        self._initialization = initialization

    def planner_input_to_model_inputs(
        self,
        planner_input: PlannerInput
    ) -> Dict[str, torch.Tensor]:
        history = planner_input.history
        traffic_light_data = list(planner_input.traffic_light_data)

        model_inputs = self.data_processor.observation_adapter(
            history,
            traffic_light_data,
            self._map_api,
            self._route_roadblock_ids,
            self._device
        )

        return model_inputs

    def outputs_to_trajectory(
        self,
        outputs: Dict[str, torch.Tensor],
        ego_state_history: Deque[EgoState]
    ) -> List[InterpolatableState]:
        predictions = (
            outputs["prediction"][0, 0]
            .detach()
            .cpu()
            .numpy()
            .astype(np.float64)
        )

        heading = np.arctan2(
            predictions[:, 3],
            predictions[:, 2]
        )[..., None]

        predictions = np.concatenate(
            [predictions[..., :2], heading],
            axis=-1
        )

        states = transform_predictions_to_states(
            predictions,
            ego_state_history,
            self._future_horizon,
            self._step_interval
        )

        return states

    def compute_planner_trajectory(
        self,
        current_input: PlannerInput
    ) -> AbstractTrajectory:
        inputs = self.planner_input_to_model_inputs(current_input)
        inputs = self.observation_normalizer(inputs)        

        _, outputs = self._planner(inputs)

        trajectory = InterpolatedTrajectory(
            trajectory=self.outputs_to_trajectory(
                outputs,
                current_input.history.ego_states
            )
        )

        return trajectory
```

整份代码可以拆成五个阶段：

```text
1. 创建规划器对象
2. 初始化地图、路线和神经网络权重
3. 将 nuPlan 原始输入转换为模型输入
4. 调用 Diffusion Planner 神经网络预测轨迹
5. 将模型轨迹转换为 nuPlan 可以使用的轨迹对象
```

# 2. 先理解 nuPlan 中的 Planner 是什么

## 2.1 Planner 的职责

在闭环自动驾驶仿真中，规划器需要周期性完成以下任务：

```text
读取当前环境
    ↓
理解自车、邻车、道路和红绿灯
    ↓
规划未来几秒的参考轨迹
    ↓
将轨迹返回给仿真器
    ↓
车辆执行一小段
    ↓
进入下一个规划周期
```

因此，规划器不是只运行一次。

在闭环仿真中，nuPlan 会反复调用：

```python
compute_planner_trajectory(...)
```

例如：

```text
时刻 0.0 s：规划一次
时刻 0.5 s：重新规划
时刻 1.0 s：重新规划
……
```

实际调用频率取决于仿真配置。

---

## 2.2 为什么继承 `AbstractPlanner`？

代码中写道：

```python
class DiffusionPlanner(AbstractPlanner):
```

`AbstractPlanner` 是 nuPlan 规定的统一规划器接口。

只要实现 nuPlan 要求的方法，仿真框架就可以使用不同规划算法，而不需要关心内部细节。

例如，可以替换为：

```text
基于规则的规划器
机器学习规划器
优化规划器
Diffusion Planner
```

对于 nuPlan 来说，它们都通过相同接口返回轨迹。

这种设计称为：

```text
面向接口编程
```

# 7. 未来轨迹时间参数

## 7.1 保存预测时域

```python
self._future_horizon = future_trajectory_sampling.time_horizon
```

它表示未来轨迹覆盖多长时间。

例如：

```python
self._future_horizon = 8.0
```

表示预测未来 8 秒。

---

## 7.2 计算相邻轨迹点间隔

```python
self._step_interval = (
    future_trajectory_sampling.time_horizon
    / future_trajectory_sampling.num_poses
)
```

公式为：

$$
\Delta t
=
\frac{T_{\text{horizon}}}{N_{\text{poses}}}
$$

例如：

$$
T_{\text{horizon}}=8\text{ s}
$$

$$
N_{\text{poses}}=16
$$

则：

$$
\Delta t
=
\frac{8}{16}
=
0.5\text{ s}
$$

注意：

> 这里的计算方式必须与训练数据和 nuPlan 轨迹工具的约定保持一致。不要仅凭直觉随意改成除以 `num_poses - 1`。

归一化可以将不同变量缩放到更加适合训练的范围。

推理阶段必须使用与训练阶段一致的归一化方式。

## 12.2 什么是 `state_dict`？

在 PyTorch 中，模型权重通常保存在一个字典中：

```python

    "encoder.layer1.weight": tensor(...),

```

键是参数名称，值是参数张量。

# 13. EMA 权重是什么？

## 13.1 代码

```python
if self._ema_enabled:
    state_dict = state_dict["ema_state_dict"]
```

EMA 是参数的指数滑动平均。

设训练第 $k$ 步的模型参数为：

$$
\theta_k
$$

EMA 参数为：

$$
\bar{\theta}_k
$$

更新形式通常类似：

$$
\bar{\theta}_k
=
\gamma\bar{\theta}_{k-1}
+
(1-\gamma)\theta_k
$$

其中：

$$
0<\gamma<1
$$

通常非常接近 1。

---

## 13.2 直观理解

普通参数：

```text
只看训练最后一步的权重。
```

EMA 参数：

```text
综合最近很多训练步骤的权重，并对较新的权重赋予更高权重。
```

这样可以减少训练波动，使推理结果更加稳定。

---

## 13.3 不使用 EMA 时

```python
else:
    if "model" in state_dict.keys():
        state_dict = state_dict["model"]
```

部分检查点将普通模型参数保存在：

```python
state_dict["model"]
```

中。

# 14. DDP 参数前缀处理

## 14.1 代码

```python
model_state_dict = {
    k[len("module."):]: v
    for k, v in state_dict.items()
    if k.startswith("module.")
}
```

---

## 14.2 什么是 DDP？

DDP 是：

```text
Distributed Data Parallel
```

即分布式数据并行训练。

使用 DDP 时，模型参数名称常带有：

```text
module.
```

前缀。

例如：

```text
module.encoder.layer1.weight
```

但单卡推理模型可能期待：

```text
encoder.layer1.weight
```

因此需要删除前缀。

---

## 14.3 这段字典推导式做什么？

设原始键为：

```text
module.encoder.layer1.weight
```

代码执行：

```python
k[len("module."):]
```

得到：

```text
encoder.layer1.weight
```

---

## 14.4 这里存在一个值得检查的假设

当前代码只保留：

```python
if k.startswith("module.")
```

的参数。

如果检查点中的键原本不带：

```text
module.
```

前缀，那么：

```python
model_state_dict
```

会变成空字典。

随后：

```python
self._planner.load_state_dict(model_state_dict)
```

通常会因为缺少参数而报错。

更加稳妥的写法是：

```python
model_state_dict = {
    k[len("module."):] if k.startswith("module.") else k: v
    for k, v in state_dict.items()
}
```

这样无论是否带有 `module.` 前缀都可以处理。

# 23. 为什么模型预测 `cos` 和 `sin`，而不是直接预测航向角？

模型输出每个轨迹点的 4 个值。

根据后续处理可以推断：

```text
[x, y, cos(heading), sin(heading)]
```

代码：

```python
heading = np.arctan2(
    predictions[:, 3],
    predictions[:, 2]
)[..., None]
```

数学形式：

$$
\theta
=
\operatorname{atan2}
\left(
\sin\theta,
\cos\theta
\right)
$$

---

## 23.1 直接预测角度的问题

角度具有周期性。

例如：

$$
-\pi
$$

和：

$$
\pi
$$

实际上代表几乎相同方向。

但从数值上看，它们差了：

$$
2\pi
$$

这会给神经网络训练带来不连续问题。

---

## 23.2 使用正弦和余弦的好处

改为预测：

$$
(\cos\theta,\sin\theta)
$$

可以避免角度边界跳变。

例如：

$$
\theta\approx\pi
$$

和：

$$
\theta\approx-\pi
$$

对应的正弦余弦向量仍然非常接近。

---

## 23.3 `atan2()` 为什么比 `arctan()` 更合适？

`atan2(y,x)` 会同时利用：

- 正弦；
- 余弦。

因此可以判断向量位于哪个象限。

如果只使用：

$$
\arctan\left(\frac{y}{x}\right)
$$

则无法可靠区分不同象限。

推理路径可考虑显式使用：

```python
with torch.inference_mode():
    _, outputs = self._planner(inputs)
```

但如果模型内部需要 guidance 梯度，则不能简单地把全部路径放入 `inference_mode()`。

这一点需要结合扩散采样和碰撞 guidance 的实现判断。

# 34. 一个更稳妥的 checkpoint 前缀处理参考写法

state_dict = torch.load(

if self._ema_enabled:
    state_dict = state_dict["ema_state_dict"]
elif "model" in state_dict:
    state_dict = state_dict["model"]

model_state_dict = {

区别在于：

# 35. 一个便于理解的简化版本

下面的伪代码忽略细节，只保留最核心逻辑：

```python
class DiffusionPlanner(AbstractPlanner):
    def __init__(self, config, checkpoint, device):
        self.model = Diffusion_Planner(config)
        self.processor = DataProcessor(config)
        self.normalizer = config.observation_normalizer
        self.checkpoint = checkpoint
        self.device = device

    def initialize(self, initialization):
        self.map = initialization.map_api
        self.route = initialization.route_roadblock_ids

        weights = load_checkpoint(self.checkpoint)
        self.model.load_state_dict(weights)

        self.model.eval()
        self.model.to(self.device)

    def compute_planner_trajectory(self, planner_input):
        model_inputs = self.processor.observation_adapter(
            history=planner_input.history,
            traffic_lights=planner_input.traffic_light_data,
            map_api=self.map,
            route=self.route,
            device=self.device,
        )

        model_inputs = self.normalizer(model_inputs)

        _, outputs = self.model(model_inputs)

        local_trajectory = outputs["prediction"][0, 0]

        global_states = convert_local_trajectory_to_nuplan_states(
            local_trajectory,
            planner_input.history.ego_states,
        )

        return InterpolatedTrajectory(global_states)
```

# 36. 初学者最需要记住的十个结论

1. 当前文件不是扩散模型内部实现，而是 nuPlan 适配层。
2. `DiffusionPlanner` 继承 `AbstractPlanner`，因此可以被 nuPlan 调用。
3. `initialize()` 通常在仿真开始前运行一次。
4. `compute_planner_trajectory()` 会在闭环仿真中反复运行。
5. `DataProcessor` 将 nuPlan 原始场景翻译成神经网络张量。
6. `observation_normalizer` 确保推理数据尺度与训练阶段一致。
7. 真正的神经网络是 `Diffusion_Planner`。
8. 模型输出使用 `[x, y, cos_h, sin_h]`，再通过 `atan2()` 恢复航向角。
9. `transform_predictions_to_states()` 将局部轨迹转换成 nuPlan 标准状态。
10. `InterpolatedTrajectory` 将离散预测点封装成可供仿真器查询的轨迹。

# 38. 最终总结

这份代码是 Diffusion Planner 与 nuPlan 仿真框架之间的桥梁。

它完成了四次关键“翻译”：

```text
nuPlan 场景对象
    ↓
模型张量字典
```

```text
原始物理量
    ↓
归一化后的模型输入
```

```text
扩散模型轨迹输出
    ↓
[x, y, heading] 局部轨迹
```

```text
局部轨迹
    ↓
nuPlan 可插值轨迹对象
```

一句话总结：

> nuPlan 每次把当前驾驶场景交给 `DiffusionPlanner`，它先利用 `DataProcessor` 和归一化器构造模型输入，再调用扩散模型生成未来轨迹，最后将预测转换为 `InterpolatedTrajectory` 返回给仿真器，从而完成一次闭环规划。
