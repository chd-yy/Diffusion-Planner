# 场景编码器代码原理：面向初学者的完整讲解

## 0. 这段代码解决什么问题？

这段代码实现了一个用于自动驾驶轨迹规划的**场景编码器**。

自动驾驶车辆在做轨迹规划时，不能只看自己的状态，还需要理解周围环境，例如：

- 周围车辆和行人的历史运动轨迹；
- 路障、锥桶等静态物体；
- 道路中的车道几何形状；
- 每条车道的限速；
- 交通信号灯状态；
- 不同目标之间的相互关系。

原始输入中，不同类型的数据结构并不相同：

- 一个动态交通参与者包含多个历史时刻；
- 一个静态物体只需要一个状态向量；
- 一条车道由多个离散采样点组成。

这段代码先用三种专门的编码器分别处理它们，再将每个对象压缩为一个长度相同的向量，也就是一个 **token**。最后，代码使用多头自注意力，让所有 token 互相交换信息。

整体流程可以概括为：

```text
动态交通参与者历史轨迹 ──→ AgentFusionEncoder ──→ 动态目标 token
静态物体状态           ──→ StaticFusionEncoder ─→ 静态物体 token
车道离散点与道路属性    ──→ LaneFusionEncoder ───→ 车道 token

三类 token + 位置与类型嵌入
              ↓
        FusionEncoder
              ↓
    融合后的场景表示 encoding
```

最终输出中的每一个 token 不再只包含自身信息，还融合了场景中其他对象的信息。

# 1. 阅读代码前需要掌握的基础概念

## 1.1 什么是张量？

张量可以理解为多维数组。

例如，一个一维向量为：

$$
[1,2,3]
$$

一个二维矩阵为：

$$
\begin{bmatrix}
1&2&3\\
4&5&6
\end{bmatrix}
$$

神经网络通常一次处理多个样本，因此还需要额外增加 batch 维度。

在这段代码中，经常看到如下符号：

| 符号 | 含义 |
|---|---|
| $B$ | batch size，一次处理的场景数量 |
| $P$ | 某类对象的数量，例如车辆数或车道数 |
| $V$ | 序列长度，例如历史时间点数量或车道采样点数量 |
| $D$ | 原始输入特征维度 |
| $H$ | 统一隐藏维度，即 `hidden_dim` |
| $C$ | MLP-Mixer 中的中间通道维度 |
| $T$ | token 数量，具体含义取决于上下文 |

例如：

$$
[B,P,V,D]
$$

表示：

- 一共有 $B$ 个场景；
- 每个场景有 $P$ 个对象；
- 每个对象有 $V$ 个序列点；
- 每个序列点使用 $D$ 个数描述。

---

## 1.2 什么是 token？

一个 token 是神经网络处理的一个信息单元。

在自然语言处理中，一个 token 可能是一个词或子词。

在这段自动驾驶代码中，一个 token 可以表示：

- 一辆周围车辆；
- 一个静态障碍物；
- 一条车道。

每个 token 最终都被编码成一个 $H$ 维向量：

$$
\text{token}\in\mathbb{R}^{H}
$$

如果一个场景共有 $P_{agent}$ 个动态目标、$P_{static}$ 个静态物体和 $P_{lane}$ 条车道，则 token 总数为：

$$
P_{total}=P_{agent}+P_{static}+P_{lane}
$$

拼接后的张量形状为：

$$
[B,P_{total},H]
$$

---

## 1.3 什么是 MLP？

MLP 是多层感知机，可以把输入向量变换为新的向量。

一个简单的两层 MLP 可以写成：

$$
\operatorname{MLP}(z)=W_2\operatorname{GELU}(W_1z+b_1)+b_2
$$

其中：

- $z$ 是输入向量；
- $W_1$ 和 $W_2$ 是可训练矩阵；
- $b_1$ 和 $b_2$ 是可训练偏置；
- GELU 是非线性激活函数。

`timm.models.layers.Mlp` 通常还包含 Dropout。

直观上，MLP 的作用是：

> 将原始特征重新组合，提取更适合后续任务使用的信息。

---

## 1.4 什么是 LayerNorm？

`nn.LayerNorm(dim)` 会沿最后一个维度执行归一化。

假设一个 token 的特征为：

$$
z=[z_1,z_2,\ldots,z_H]
$$

LayerNorm 首先计算均值：

$$
\mu=\frac{1}{H}\sum_{i=1}^{H}z_i
$$

再计算方差：

$$
\operatorname{Var}(z)=\frac{1}{H}\sum_{i=1}^{H}(z_i-\mu)^2
$$

然后归一化：

$$
\hat z_i=\frac{z_i-\mu}{\sqrt{\operatorname{Var}(z)+\varepsilon}}
$$

最后再乘以可学习缩放参数并加上可学习偏置。

LayerNorm 的作用是让特征尺度更加稳定，从而帮助训练。

---

## 1.5 什么是残差连接？

残差连接的形式为：

$$
x_{out}=x+F(x)
$$

其中，$F(x)$ 是某个神经网络模块输出的新信息。

它不是完全替换原始信息，而是在原始信息的基础上增加修正量。

直观上，可以理解为：

> 保留原始答案，再让网络学习需要补充或修改的部分。

残差连接有助于缓解深层网络中的梯度消失问题，提高训练稳定性。

---

## 1.6 什么是 Dropout 和 DropPath？

### Dropout

Dropout 会在训练时随机将部分元素置零，从而降低网络对某些特征的过度依赖。

### DropPath

DropPath 也叫 Stochastic Depth。它不是随机丢弃某几个元素，而是可能随机丢弃整个残差分支：

$$
x_{out}=x+\operatorname{DropPath}(F(x))
$$

在推理阶段，Dropout 和 DropPath 通常都会关闭。

---

## 1.7 什么是 mask？

真实场景中的对象数量经常不同。

例如：

- 场景 A 有 10 辆周围车辆；
- 场景 B 只有 3 辆周围车辆。

为了将它们放入同一个 batch，通常会预留固定数量的位置，并用全零向量填充不存在的对象。

mask 用于标记哪些位置有效，哪些位置只是占位符。

在这段代码中通常约定：

| mask 值 | 含义 |
|---|---|
| `False` | 有效对象，可以参与注意力计算 |
| `True` | 无效占位符，需要屏蔽 |

这一点非常重要，因为 `nn.MultiheadAttention` 的 `key_padding_mask` 也是使用 `True` 表示屏蔽。

# 2. 代码的总体结构

文件中定义了以下类：

| 类名 | 作用 |
|---|---|
| `Encoder` | 总入口，组织整个场景编码流程 |
| `AgentFusionEncoder` | 将每个动态交通参与者的历史轨迹编码为一个 token |


`MixerBlock` 用于融合一个序列内部的 token 信息和通道信息。

# 3. 总入口：`Encoder`

## 3.1 初始化过程

核心代码：

```python
self.hidden_dim = config.hidden_dim
self.token_num = config.agent_num + config.static_objects_num + config.lane_num
```

其中：

$$
P_{total}=P_{agent}+P_{static}+P_{lane}
$$

`self.token_num` 表示场景中预留的 token 总数。

随后，代码创建三个局部编码器：

```python
self.neighbor_encoder = AgentFusionEncoder(...)
self.static_encoder = StaticFusionEncoder(...)
self.lane_encoder = LaneFusionEncoder(...)
```

以及一个全局融合编码器：

```python
self.fusion = FusionEncoder(...)
```

最后，代码定义位置嵌入层：

```python
self.pos_emb = nn.Linear(7, config.hidden_dim)
```

它将 7 维位置与类型特征映射到统一隐藏维度 $H$：

$$
\operatorname{PosEmb}:\mathbb{R}^{7}\rightarrow\mathbb{R}^{H}
$$

---

## 3.2 为什么位置嵌入输入是 7 维？

位置嵌入使用如下结构：

$$
[x,y,\cos(\theta),\sin(\theta),\text{type}_0,\text{type}_1,\text{type}_2]
$$

其中：

- $x,y$ 表示位置；
- $\cos(\theta),\sin(\theta)$ 表示方向；
- 最后三个分量表示对象属于哪一类。

代码使用以下三种类别标记：

| 对象类型 | 类别向量 |
|---|---|
| 动态交通参与者 | $[1,0,0]$ |
| 静态物体 | $[0,1,0]$ |
| 车道 | $[0,0,1]$ |

为什么方向不直接使用角度 $\theta$？

因为角度存在周期跳变。例如：

$$
179^\circ
$$

和：

$$
-179^\circ
$$

实际上非常接近，但数值相差很大。

使用：

$$
[\cos(\theta),\sin(\theta)]
$$

可以避免这个问题。

---

## 3.3 前向传播过程

`Encoder.forward()` 首先读取输入：

```python
neighbors = inputs['neighbor_agents_past']
static = inputs['static_objects']
lanes = inputs['lanes']
lanes_speed_limit = inputs['lanes_speed_limit']
lanes_has_speed_limit = inputs['lanes_has_speed_limit']
```

然后，三个专门编码器分别产生：

1. token 内容特征；
2. 无效对象 mask；
3. 位置、方向与类别信息。

动态目标编码：

```python
encoding_neighbors, neighbors_mask, neighbor_pos = self.neighbor_encoder(neighbors)
```

静态物体编码：

```python
encoding_static, static_mask, static_pos = self.static_encoder(static)
```

车道编码：

```python
encoding_lanes, lanes_mask, lane_pos = self.lane_encoder(
    lanes,
    lanes_speed_limit,
    lanes_has_speed_limit
)
```

三类 token 沿对象维度拼接：

```python
encoding_input = torch.cat(
    [encoding_neighbors, encoding_static, encoding_lanes],
    dim=1
)
```

因此：

$$
[B,P_{agent},H]
$$

$$
[B,P_{static},H]
$$

$$
[B,P_{lane},H]
$$

拼接后变为：

$$
[B,P_{total},H]
$$

其中：

$$
P_{total}=P_{agent}+P_{static}+P_{lane}
$$

---

## 3.4 为什么只对有效 token 计算位置嵌入？

代码为：

```python
encoding_mask = torch.cat(
    [neighbors_mask, static_mask, lanes_mask],
    dim=1
).view(-1)

encoding_pos = self.pos_emb(encoding_pos[~encoding_mask])
```

这里：

```python
~encoding_mask
```

表示 mask 取反，因此只留下有效 token。

之后，代码创建全零结果张量：

```python
encoding_pos_result = torch.zeros(
    (B * self.token_num, self.hidden_dim),
    device=encoding_pos.device
)
```

再将有效对象的位置嵌入填回原位置：

```python
encoding_pos_result[~encoding_mask] = encoding_pos
```

这样，无效占位 token 的位置嵌入仍为零。

最后，将位置嵌入加到内容 token 上：

```python
encoding_input = encoding_input + encoding_pos_result.view(
    B,
    self.token_num,
    -1
)
```

数学上可以写成：

$$
h_i^{(0)}=h_i^{content}+h_i^{position}
$$

其中：

- $h_i^{content}$ 是对象自身内容特征；
- $h_i^{position}$ 是位置、方向和对象类别嵌入。

---

## 3.5 `Encoder` 的最终输出

代码为：

```python
encoder_outputs['encoding'] = self.fusion(
    encoding_input,
    encoding_mask.view(B, self.token_num)
)
```

最终输出：

$$
\texttt{encoder\_outputs['encoding']}
\in
\mathbb{R}^{B\times P_{total}\times H}
$$

每个 token 已经融合了场景中的其他对象信息。

# 4. 动态交通参与者编码器：`AgentFusionEncoder`

## 4.1 输入是什么？

文档字符串写道：

```python
x: B, P, V, D (x, y, cos, sin, vx, vy, w, l, type(3))
```

因此，每个历史状态通常包含：

| 索引范围 | 含义 |
|---|---|
| `0:2` | 位置 $x,y$ |
| `2:4` | 航向方向 $\cos(\theta),\sin(\theta)$ |
| `4:6` | 速度 $v_x,v_y$ |
| `6:8` | 目标宽度与长度 $w,l$ |
| `8:` | 目标类别特征，通常为 3 维 |

输入形状为：

$$
[B,P_{agent},V_{time},D_{agent}]
$$

其中，每一个动态目标包含多个历史时间点。

---

## 4.2 为什么单独读取最后一个时刻的类型？

代码为：

```python
neighbor_type = x[:, :, -1, 8:]
```

含义是：

> 对每一个动态交通参与者，只读取最后一个历史时刻中的类型特征。

结果形状通常为：

$$
[B,P_{agent},3]
$$

接下来，只保留前 8 个连续状态量：

```python
x = x[..., :8]
```

---

## 4.3 如何构造位置与对象大类信息？

代码为：

```python
pos = x[:, :, -1, :7].clone()
pos[..., -3:] = 0.0
pos[..., -3] = 1.0
```

最终，`pos` 被改造成：

$$
[x,y,\cos(\theta),\sin(\theta),1,0,0]
$$

最后三维表示：这是一个动态交通参与者。

结果形状为：

$$
[B,P_{agent},7]
$$

---

## 4.4 如何判断历史时间点是否有效？

代码为：

```python
mask_v = torch.sum(torch.ne(x[..., :8], 0), dim=-1).to(x.device) == 0
```

拆开理解：

```python
torch.ne(x[..., :8], 0)
```

会判断每一个特征是否不等于零。

若某个历史时刻的 8 个连续特征全部为零，则：

$$
\sum_{k=1}^{8}\mathbf{1}[x_k\neq0]=0
$$

于是该时间点被认为无效。

`mask_v` 的形状为：

$$
[B,P_{agent},V_{time}]
$$

并且：

| `mask_v` 值 | 含义 |
|---|---|
| `True` | 当前历史点无效 |
| `False` | 当前历史点有效 |

---

## 4.5 如何判断整个目标是否无效？

代码为：

```python
mask_p = torch.sum(~mask_v, dim=-1) == 0
```

其中：

```python
~mask_v
```

表示有效时间点。

如果一个交通参与者的所有历史时间点都无效，则：

$$
\sum_{v=1}^{V_{time}}\mathbf{1}[\text{第 }v\text{ 个时间点有效}]=0
$$

此时，整个参与者被标为无效。

`mask_p` 的形状为：

$$
[B,P_{agent}]
$$

---

## 4.6 为什么要增加一个有效性特征？

代码为：

```python
x = torch.cat(
    [x, (~mask_v).float().unsqueeze(-1)],
    dim=-1
)
```

原本每个历史点有 8 个连续特征：

$$
[x,y,\cos(\theta),\sin(\theta),v_x,v_y,w,l]
$$

现在额外添加一个有效性标志：

$$
\text{valid}\in\{0,1\}
$$

因此每个历史点变成 9 维：

$$
[x,y,\cos(\theta),\sin(\theta),v_x,v_y,w,l,\text{valid}]
$$

为什么这样做？

因为一个历史序列中可能只有部分时间点有效。有效性特征可以明确告诉网络：

> 这个全零历史点是真实状态，还是为了补齐长度而添加的占位符？

---

## 4.7 为什么要合并 batch 维和对象维？

代码为：

```python
x = x.view(B * P, V, -1)
valid_indices = ~mask_p.view(-1)
x = x[valid_indices]
```

原始形状：

$$
[B,P_{agent},V_{time},9]
$$

合并后：

$$
[B\cdot P_{agent},V_{time},9]
$$

这样，每个动态交通参与者都可以被视为一个独立样本，送入同一个局部轨迹编码器。

筛选有效目标后，形状变为：

$$
[P_{valid},V_{time},9]
$$

其中，$P_{valid}$ 表示当前 batch 中有效动态目标的总数。

---

## 4.8 通道预投影在做什么？

代码为：

```python
self.channel_pre_project = Mlp(
    in_features=8+1,
    hidden_features=channels_mlp_dim,
    out_features=channels_mlp_dim,
    act_layer=nn.GELU,
    drop=0.
)
```

前向传播中：

```python
x = self.channel_pre_project(x)
```

它会独立处理每一个历史时间点：

$$
\mathbb{R}^{9}\rightarrow\mathbb{R}^{C}
$$

因此：

$$
[P_{valid},V_{time},9]
\longrightarrow
[P_{valid},V_{time},C]
$$

直观上，它将原始状态转换为更丰富的隐藏特征。

---

## 4.9 token 预投影在做什么？

代码先交换维度：

```python
x = x.permute(0, 2, 1)
```

于是：

$$
[P_{valid},V_{time},C]
\longrightarrow
[P_{valid},C,V_{time}]
$$

随后：

```python
x = self.token_pre_project(x)
```

`token_pre_project` 沿最后一个维度工作：

$$
\mathbb{R}^{V_{time}}\rightarrow\mathbb{R}^{T_{mixer}}
$$

其中：

$$
T_{mixer}=\texttt{tokens\_mlp\_dim}
$$

因此：

$$
[P_{valid},C,V_{time}]
\longrightarrow
[P_{valid},C,T_{mixer}]
$$

再交换回来：

```python
x = x.permute(0, 2, 1)
```

得到：

$$
[P_{valid},T_{mixer},C]
$$

为什么要做 token 预投影？

> 它将原始历史时间序列映射到统一的中间 token 空间，使后面的 `MixerBlock` 可以使用固定结构处理不同历史信息。

---

## 4.10 `MixerBlock` 在做什么？

代码为：

```python
for block in self.blocks:
    x = block(x)
```

输入形状为：

$$
[P_{valid},T_{mixer},C]
$$

`MixerBlock` 通常包括两个步骤。

### Token Mixing

沿 token 维度混合信息：

$$
[T_{mixer}]
$$

它让不同历史模式之间交换信息。

### Channel Mixing

沿通道维度混合信息：

$$
[C]
$$

它让同一个 token 内的不同特征互相组合。

一个典型的 MLP-Mixer 模块可以写成：

$$
Y=X+\operatorname{TokenMLP}(\operatorname{LayerNorm}(X))
$$

$$
Z=Y+\operatorname{ChannelMLP}(\operatorname{LayerNorm}(Y))
$$

其中，Token MLP 通常需要在维度置换后执行。

---

## 4.11 为什么最后要做平均池化？

代码为：

```python
x = torch.mean(x, dim=1)
```

输入形状为：

$$
[P_{valid},T_{mixer},C]
$$

沿 token 维度求平均后：

$$
[P_{valid},C]
$$

数学上：

$$
h_p=\frac{1}{T_{mixer}}\sum_{i=1}^{T_{mixer}}z_{p,i}
$$

每一个动态目标最终只保留一个向量，用于概括它的历史运动轨迹。

---

## 4.12 为什么还要加入类型嵌入？

代码为：

```python
neighbor_type = neighbor_type.view(B * P, -1)
neighbor_type = neighbor_type[valid_indices]
type_embedding = self.type_emb(neighbor_type)
x = x + type_embedding
```

交通参与者可能是：

- 汽车；
- 行人；
- 自行车；
- 其他类别。

类型嵌入将类别特征映射为一个 $C$ 维向量：

$$
\operatorname{TypeEmb}:\mathbb{R}^{3}\rightarrow\mathbb{R}^{C}
$$

再加到运动轨迹特征上：

$$
h_p^{agent}=h_p^{trajectory}+h_p^{type}
$$

这样，网络可以区分不同交通参与者的运动规律。

---

## 4.13 为什么最后还要投影到 `hidden_dim`？

代码为：

```python
x = self.emb_project(self.norm(x))
```

局部编码器内部使用的通道维度为 $C$，但是全局融合编码器要求所有对象使用统一维度 $H$。

因此，需要执行：

$$
\mathbb{R}^{C}\rightarrow\mathbb{R}^{H}
$$

最终动态目标 token 形状为：

$$
[B,P_{agent},H]
$$

---

## 4.14 为什么无效对象仍然需要填回去？

代码为：

```python
x_result = torch.zeros((B * P, x.shape[-1]), device=x.device)
x_result[valid_indices] = x
return x_result.view(B, P, -1), mask_p.reshape(B, -1), pos.view(B, P, -1)
```

虽然无效目标在局部编码时被剔除，但是全局拼接时需要维度固定。

因此，代码重新创建完整形状，并把有效目标结果填回原位置。

无效目标保持全零向量，并通过 mask 在注意力中被屏蔽。

---

# 5. 静态物体编码器：`StaticFusionEncoder`

## 5.1 为什么静态物体的结构更简单？

静态物体没有历史时间序列，因此不需要使用时间混合模块。

输入形状通常为：

$$
[B,P_{static},D_{static}]
$$

文档字符串写道：

```python
x: B, P, D (x, y, cos, sin, w, l, type(4))
```

每个静态物体包含：

- 位置；
- 朝向；
- 尺寸；
- 类型。

---

## 5.2 如何构造静态物体的位置嵌入信息？

代码为：

```python
pos = x[:, :, :7].clone()
pos[..., -3:] = 0.0
pos[..., -2] = 1.0
```

最终得到：

$$
[x,y,\cos(\theta),\sin(\theta),0,1,0]
$$

最后三维表示：这是静态物体。

---

## 5.3 如何判断静态物体是否无效？

代码为：

```python
mask_p = torch.sum(torch.ne(x[..., :10], 0), dim=-1).to(x.device) == 0
```

如果一个静态物体前 10 个特征全部为零，则它被视为无效占位符。

---

## 5.4 静态物体如何编码？

核心代码：

```python
x = x.view(B * P, -1)
x = x[valid_indices]
x = self.projection(x)
```

投影层为：

```python
self.projection = Mlp(
    in_features=dim,
    hidden_features=hidden_dim,
    out_features=hidden_dim,
    act_layer=nn.GELU,
    drop=drop_path_rate
)
```

数学上：

$$
h_p^{static}=\operatorname{MLP}(x_p)
$$

输出形状为：

$$
[B,P_{static},H]
$$

# 6. 车道编码器：`LaneFusionEncoder`

## 6.1 输入是什么？

文档字符串写道：

```python
x: B, P, V, D (
    x, y,
    x'-x, y'-y,
    x_left-x, y_left-y,
    x_right-x, y_right-y,
    traffic(4)
)
```

其中，每条车道由多个离散采样点表示。

输入形状通常为：

$$
[B,P_{lane},V_{lane},D_{lane}]
$$

每个车道点前 8 个几何特征可以理解为：

| 特征 | 含义 |
|---|---|
| $x,y$ | 当前车道点位置 |
| $x'-x,y'-y$ | 局部前进方向 |
| $x_{left}-x,y_{left}-y$ | 指向左边界的相对向量 |
| $x_{right}-x,y_{right}-y$ | 指向右边界的相对向量 |

后 4 维通常表示交通信号灯状态。

此外，编码器还单独接收：

```python
speed_limit
has_speed_limit
```

---

## 6.2 为什么从第 0 个采样点读取交通信号灯？

代码为：

```python
traffic = x[:, :, 0, 8:]
```

这表示：

> 对于一条车道，只使用第 0 个采样点中保存的交通信号灯状态。

通常意味着同一条车道的信号灯状态已经被复制到每一个采样点，或者项目约定将其存储在第 0 个点。

---

## 6.3 为什么使用车道中间点构造位置特征？

代码为：

```python
pos = x[:, :, int(self._lane_len / 2), :7].clone()
```

每条车道包含多个离散点。为了给整条车道指定一个代表位置，代码选择中间采样点。

随后，代码从局部方向向量计算角度：

```python
heading = torch.atan2(pos[..., 3], pos[..., 2])
```

数学上：

$$
\theta=\operatorname{atan2}(d_y,d_x)
$$

再将方向改写为：

```python
pos[..., 2] = torch.cos(heading)
pos[..., 3] = torch.sin(heading)
```

即：

$$
[\cos(\theta),\sin(\theta)]
$$

最后，代码设置车道类别：

```python
pos[..., -3:] = 0.0
pos[..., -1] = 1.0
```

得到：

$$
[x,y,\cos(\theta),\sin(\theta),0,0,1]
$$

---

## 6.4 如何判断车道是否无效？

代码为：

```python
mask_v = torch.sum(torch.ne(x[..., :8], 0), dim=-1).to(x.device) == 0
mask_p = torch.sum(~mask_v, dim=-1) == 0
```

含义与动态目标类似：

- 如果某个车道点的前 8 个几何特征全部为零，则这个点无效；
- 如果一条车道的所有采样点都无效，则整条车道无效。

---

## 6.5 车道几何特征如何融合？

流程与动态目标类似。

先将每个车道点从 8 维投影到 $C$ 维：

$$
[B\cdot P_{lane},V_{lane},8]
\longrightarrow
[P_{valid},V_{lane},C]
$$

然后沿采样点序列做 token 预投影：

$$
[P_{valid},V_{lane},C]
\longrightarrow
[P_{valid},T_{mixer},C]
$$

再通过多个 `MixerBlock` 融合不同车道点和不同通道的信息。

最后执行平均池化：

$$
h_p^{geometry}=\frac{1}{T_{mixer}}\sum_{i=1}^{T_{mixer}}z_{p,i}
$$

每条车道被压缩为一个 $C$ 维几何向量。

---

## 6.6 已知限速和未知限速如何处理？

代码先创建一个限速嵌入占位张量：

```python
speed_limit_embedding = torch.zeros(
    (speed_limit.shape[0], self._channel),
    device=x.device
)
```

### 已知限速

如果车道有限速信息：

```python
speed_limit_with_limit = self.speed_limit_emb(
    speed_limit[has_speed_limit].unsqueeze(-1)
)
```

则使用线性层映射：

$$
\operatorname{SpeedEmb}:\mathbb{R}^{1}\rightarrow\mathbb{R}^{C}
$$

### 未知限速

如果没有已知限速：

```python
speed_limit_no_limit = self.unknown_speed_emb.weight.expand(
    (~has_speed_limit).sum().item(),
    -1
)
```

则使用一个可学习的默认向量。

为什么不能直接使用速度值 0 表示未知？

因为：

> 限速未知和限速确实为 0 并不是同一个含义。

使用独立可学习嵌入可以让模型区分这两种情况。

---

## 6.7 信号灯状态如何处理？

代码为：

```python
traffic_light_embedding = self.traffic_emb(traffic)
```

其中：

```python
self.traffic_emb = nn.Linear(4, channels_mlp_dim)
```

因此：

$$
\operatorname{TrafficEmb}:\mathbb{R}^{4}\rightarrow\mathbb{R}^{C}
$$

4 维输入可能表示不同信号灯状态，例如红灯、黄灯、绿灯和未知状态。具体语义需要结合数据预处理代码确认。

---

## 6.8 三类车道信息如何融合？

代码为：

```python
x = x + speed_limit_embedding + traffic_light_embedding
```

数学上：

$$
h_p^{lane}
=
h_p^{geometry}
+
h_p^{speed}
+
h_p^{traffic}
$$

随后经过 LayerNorm 和 MLP：

```python
x = self.emb_project(self.norm(x))
```

得到统一的 $H$ 维车道 token：

$$
[B,P_{lane},H]
$$

# 7. 全局融合前的三类 token

三个局部编码器分别输出：

$$
H_{agent}\in\mathbb{R}^{B\times P_{agent}\times H}
$$

$$
H_{static}\in\mathbb{R}^{B\times P_{static}\times H}
$$

$$
H_{lane}\in\mathbb{R}^{B\times P_{lane}\times H}
$$

拼接后：

$$
H_{all}
=
\operatorname{Concat}
\left(
H_{agent},H_{static},H_{lane}
\right)
$$

$$
H_{all}\in\mathbb{R}^{B\times P_{total}\times H}
$$

再加入位置与类别嵌入：

$$
H_{all}^{(0)}=H_{all}+E_{pos}
$$

这一步之后，每个 token 包含两类信息：

1. 对象自身内容信息；
2. 对象在场景中的位置、方向和大类信息。

---

# 8. 自注意力模块：`SelfAttentionBlock`

## 8.1 为什么还需要全局自注意力？

局部编码器只负责压缩单个对象的信息。

但是轨迹规划需要理解对象之间的关系。例如：

- 某辆车是否位于自车前方；
- 行人是否接近斑马线；
- 某辆车正在使用哪一条车道；
- 交通灯是否会影响当前可行车道；
- 障碍物是否阻塞道路。

自注意力机制可以让每一个 token 主动读取其他 token 的信息。

---

## 8.2 自注意力的基本公式

对于输入矩阵：

$$
X\in\mathbb{R}^{P_{total}\times H}
$$

通常会构造：

$$
Q=XW_Q
$$

$$
K=XW_K
$$

$$
V=XW_V
$$

然后计算注意力权重：

$$
A
=
\operatorname{softmax}
\left(
\frac{QK^\mathsf{T}}{\sqrt{d}}
\right)
$$

最后：

$$
\operatorname{Attention}(X)=AV
$$

直观上：

- Query 表示“我想寻找什么信息”；
- Key 表示“我拥有什么信息”；
- Value 表示“如果你关注我，我可以提供什么内容”。

---

## 8.3 什么是多头注意力？

代码为：

```python
self.attn = nn.MultiheadAttention(
    dim,
    heads,
    dropout,
    batch_first=True
)
```

多头注意力会将隐藏维度拆成多个子空间。

若：

$$
H=192
$$

且：

$$
\text{heads}=6
$$

则每个注意力头的维度为：

$$
d_{head}=\frac{192}{6}=32
$$

不同注意力头可以学习不同关系，例如：

- 一个头关注车辆之间的相对距离；
- 一个头关注车道和车辆的对应关系；
- 一个头关注交通信号灯；
- 一个头关注静态障碍物。

---

## 8.4 这段代码的注意力调用有什么特点？

核心代码：

```python
x = x + self.drop_path(
    self.attn(
        self.norm1(x),
        x,
        x,
        key_padding_mask=mask
    )[0]
)
```

`nn.MultiheadAttention` 的前三个位置参数依次是：

```python
query, key, value
```

因此，这段代码实际传入：

$$
Q_{input}=\operatorname{LayerNorm}(x)
$$

$$
K_{input}=x
$$

$$
V_{input}=x
$$

需要注意：

> 只有 Query 在进入注意力层之前显式经过了 `LayerNorm`，Key 和 Value 使用原始 `x`。

这与常见的标准 Pre-Norm Transformer 写法略有差异。常见写法通常是：

$$
Q_{input}=K_{input}=V_{input}=\operatorname{LayerNorm}(x)
$$

但当前代码的行为需要以实际实现为准，不能自动理解为标准写法。

---

## 8.5 `key_padding_mask` 在做什么？

代码为：

```python
key_padding_mask=mask
```

假设一共有 $P_{total}$ 个 token，其中部分位置只是补零占位符。

mask 会阻止其他 token 从这些无效 token 中读取信息。

需要特别注意：

> `key_padding_mask` 屏蔽的是 Key 和 Value 位置，而不是自动将无效 Query 的输出清零。

因此，无效 token 自身仍然可能产生输出，只是其他 token 不会读取它们。后续模块若需要严格忽略无效 token，仍应继续保留 mask。

---

## 8.6 注意力后的 MLP 有什么作用？

代码为：

```python
x = x + self.drop_path(self.mlp(self.norm2(x)))
```

完整的 `SelfAttentionBlock` 可以写成：

$$
X'=
X+
\operatorname{DropPath}
\left[
\operatorname{MHA}
\left(
\operatorname{LN}(X),X,X;M
\right)
\right]
$$

$$
X''=
X'+
\operatorname{DropPath}
\left[
\operatorname{MLP}
\left(
\operatorname{LN}(X')
\right)
\right]
$$

注意力负责 token 之间的信息交换。

MLP 则负责对每一个 token 内部的通道特征做进一步非线性变换。

---

# 9. 全局融合编码器：`FusionEncoder`

## 9.1 初始化过程

代码为：

```python
self.blocks = nn.ModuleList(
    [SelfAttentionBlock(hidden_dim, num_heads, dropout=dpr)
     for i in range(depth)]
)

self.norm = nn.LayerNorm(hidden_dim)
```

这表示会连续堆叠多个自注意力模块。

如果：

$$
\texttt{depth}=3
$$

那么 token 会经过 3 层全局融合。

---

## 9.2 为什么强制令 `mask[:, 0] = False`？

代码为：

```python
mask[:, 0] = False
```

这会强制将每一个场景中的第 0 个 token 标记为有效。

为什么这样做？

如果某一个 batch 样本中的所有 token 都被屏蔽，那么注意力层在计算 softmax 时可能遇到所有位置都是负无穷的情况，进而产生数值异常。

强制保留至少一个 token 可以规避这一问题。

但是需要注意：

> 这是一种工程处理方式。它默认第 0 个 token 可以安全保留。根据拼接顺序，第 0 个 token 通常是第一个动态交通参与者。

如果第 0 个位置也可能是真正的无效占位符，那么它虽然被强制保留，但其内容通常仍是全零向量。理解代码时应注意这一点。

---

## 9.3 全局融合过程

代码为：

```python
for b in self.blocks:
    x = b(x, mask)

return self.norm(x)
```

数学上，可以理解为：

$$
H^{(l+1)}=
\operatorname{SelfAttentionBlock}
\left(
H^{(l)},M
\right)
$$

其中：

- $H^{(l)}$ 是第 $l$ 层 token 特征；
- $M$ 是无效对象 mask。

经过多层融合后：

$$
H^{final}=\operatorname{LayerNorm}(H^{(L)})
$$

最终输出形状仍然为：

$$
[B,P_{total},H]
$$

# 11. 一段简化后的伪代码

```python
def encode_scene(inputs):
    # 1. 将每个动态目标的历史轨迹压缩为一个 token
    agent_tokens, agent_mask, agent_pos = encode_agents(
        inputs['neighbor_agents_past']
    )

    # 2. 将每个静态物体压缩为一个 token
    static_tokens, static_mask, static_pos = encode_static_objects(
        inputs['static_objects']
    )

    # 3. 将每条车道压缩为一个 token
    lane_tokens, lane_mask, lane_pos = encode_lanes(
        inputs['lanes'],
        inputs['lanes_speed_limit'],
        inputs['lanes_has_speed_limit']
    )

    # 4. 拼接所有 token
    tokens = concat(agent_tokens, static_tokens, lane_tokens)

    # 5. 拼接位置、方向和类别信息，并映射为位置嵌入
    pos = concat(agent_pos, static_pos, lane_pos)
    tokens = tokens + position_embedding(pos)

    # 6. 拼接 mask，屏蔽不存在的对象
    mask = concat(agent_mask, static_mask, lane_mask)

    # 7. 使用多头注意力进行全局融合
    encoding = fusion_encoder(tokens, mask)

    return {'encoding': encoding}
```

# 12. 为什么局部编码使用 MLP-Mixer，全局融合使用注意力？

这段代码使用了两种不同的信息融合方式。

## 12.1 局部阶段：MLP-Mixer

动态交通参与者的历史轨迹和车道采样点都是长度固定的局部序列。

例如：

- 一辆车的历史轨迹有固定数量的历史点；
- 一条车道有固定数量的离散采样点。

MLP-Mixer 适合在固定长度序列中融合：

- 不同序列位置的信息；
- 不同特征通道的信息。

## 12.2 全局阶段：多头注意力

全局场景中存在多种不同对象，它们之间的关系更加灵活。

注意力机制可以根据当前输入动态学习：

> 哪些对象之间应该重点交互？

例如，一辆距离很远的车可能不重要，而一辆正在切入当前车道的车可能非常重要。

因此，代码采用：

$$
\boxed{
\text{局部序列编码：MLP-Mixer}
}
$$

$$
\boxed{
\text{全局对象交互：Multi-Head Attention}
}
$$

# 13. 代码中值得特别注意的地方

## 13.1 全零向量被当作无效占位符

动态目标、静态物体和车道都通过“特征是否全为零”判断有效性。

例如：

```python
mask_p = torch.sum(torch.ne(x[..., :10], 0), dim=-1) == 0
```

这意味着数据预处理阶段必须保证：

> 一个真实有效对象不会恰好使用全零向量表示。

如果真实对象可能出现全零特征，最好额外传入显式 mask，而不是依赖数值判断。

---

## 13.2 `has_speed_limit` 应当是布尔张量

代码中使用：

```python
~has_speed_limit
```

因此，`has_speed_limit` 最好是布尔类型：

```python
has_speed_limit.dtype == torch.bool
```

如果输入为浮点数或整数，位运算结果可能不符合预期。

---

## 13.3 动态目标类型取自最后一个历史时刻

代码为：

```python
neighbor_type = x[:, :, -1, 8:]
```

这隐含了一个数据约定：

> 最后一个历史时刻应当保存正确的目标类型。

如果某个目标早期有效，但最后一个历史时刻被补零，那么类型信息也可能变成零向量。是否会出现这种情况，需要结合数据预处理流程确认。

---

## 13.4 车道的部分无效采样点没有显式 valid 特征

动态目标会将有效性特征拼接到每一个历史点：

```python
x = torch.cat([x, (~mask_v).float().unsqueeze(-1)], dim=-1)
```

但车道编码没有做同样处理。

如果一条有效车道中存在部分补零采样点，MLP 中的偏置可能会让这些全零输入产生非零特征。

这不一定是错误，可能是项目数据已经保证每条有效车道的采样点全部有效。但理解代码时需要注意这个数据假设。

---

## 13.5 注意力中的 Query 被归一化，Key 和 Value 没有显式归一化

代码为：

```python
self.attn(self.norm1(x), x, x, key_padding_mask=mask)
```

这与常见写法：

```python
x_norm = self.norm1(x)
self.attn(x_norm, x_norm, x_norm, key_padding_mask=mask)
```

不同。

当前实现可能是有意设计，也可能值得进一步与项目原始实现或实验设置核对。

---

## 13.6 `mask[:, 0] = False` 会原地修改 mask

代码为：

```python
mask[:, 0] = False
```

这会直接修改传入的 mask 张量。

这样做的目的通常是确保至少一个 token 有效，避免全 mask 导致注意力数值异常。

如果后续代码还希望使用原始 mask，需要提前复制：

```python
mask = mask.clone()
```

当前代码中没有复制，因此调用方应了解这个副作用。

---

## 13.7 新建全零张量时没有显式继承 dtype

例如：

```python
x_result = torch.zeros((B * P, x.shape[-1]), device=x.device)
```

它会默认使用 PyTorch 的默认浮点类型，通常是 `float32`。

如果模型采用混合精度训练，例如 `float16` 或 `bfloat16`，更稳妥的写法通常是：

```python
x_result = torch.zeros(
    (B * P, x.shape[-1]),
    device=x.device,
    dtype=x.dtype
)
```

当前代码是否会产生 dtype 转换，需要结合实际运行环境判断。

# 14. 常见报错与调试方法

## 14.1 `mat1 and mat2 shapes cannot be multiplied`

通常表示输入最后一个维度和线性层要求的维度不同。

例如：

```python
self.channel_pre_project = Mlp(in_features=9, ...)
```

那么输入最后一个维度必须是：

$$
9
$$

可以打印：

```python
print(x.shape)
```

检查维度。

---

## 14.2 `embed_dim must be divisible by num_heads`

多头注意力要求：

$$
H\bmod\text{heads}=0
$$

例如：

$$
192\bmod6=0
$$

因此合法。

但如果：

$$
H=190
$$

且：

$$
\text{heads}=6
$$

则无法平均拆分。

---

## 14.3 `~` 运算符报错或结果异常

检查：

```python
lanes_has_speed_limit.dtype
```

最好应为：

```python
torch.bool
```

---

## 14.4 注意力输出出现 `NaN`

需要检查：

- 是否存在某个样本中所有 token 都被 mask；
- 输入是否已经包含 `NaN`；
- 数值是否过大；
- `mask[:, 0] = False` 是否执行；
- LayerNorm 输入是否稳定。

---

## 14.5 `view` 报错

有时经过 `permute()` 后，张量在内存中不连续，直接调用 `view()` 可能报错。

可以使用：

```python
x = x.reshape(...)
```

或：

```python
x = x.contiguous().view(...)
```

当前代码中的主要 `view()` 通常位于可行位置，但调试修改代码时需要注意。

初学者可以按照以下顺序阅读源码：

# 17. 最终总结

这段代码的核心思想是：

$$
\boxed{
\text{先将复杂场景拆成对象，再将每个对象编码为 token}
}
$$

随后：

$$
\boxed{
\text{使用位置嵌入告诉模型对象在哪里、是什么类型}
}
$$

最后：

$$
\boxed{
\text{使用多头自注意力建模对象之间的相互关系}
}
$$

完整流程为：

```text
动态目标历史轨迹
    → 时间序列编码
    → 每个动态目标一个 token

静态障碍物状态
    → MLP 投影
    → 每个静态物体一个 token

车道离散点 + 限速 + 信号灯
    → 车道序列编码
    → 每条车道一个 token

全部 token
    + 位置、方向、对象大类嵌入
    → 多层自注意力融合
    → 全局场景表示
```

最终输出：

$$
\texttt{encoder\_outputs['encoding']}
\in
\mathbb{R}^{B\times P_{total}\times H}
$$

其中，每一个 token 都是一个融合了局部信息和全局上下文的场景特征，可供后续轨迹规划模块继续使用。
