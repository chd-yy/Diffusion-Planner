# `GuidanceWrapper` 原理详解：如何把碰撞规避引导接入扩散轨迹采样

## 0. 这份代码解决了什么问题？

这份代码定义了一个类：

```python
class GuidanceWrapper:
```

它的作用是：

> 将一个或多个轨迹约束函数统一包装起来，计算一个可求梯度的奖励值 `energy`，供扩散模型在采样过程中使用。

当前代码只启用了一个引导函数：

```python
collision_guidance_fn
```

因此，这个包装器当前主要用于：

> 在扩散模型生成轨迹时，额外给出一个“避开碰撞”的梯度方向，使生成轨迹更安全。

如果将扩散模型类比成一个负责生成轨迹的人，那么：

- 扩散模型负责生成“像训练数据”的轨迹；
- `collision_guidance_fn` 负责提醒模型“不要撞车”；
- `GuidanceWrapper` 负责整理输入、还原物理量、调用引导函数并汇总奖励。

---

# 第一部分：先理解整体调用链

## 1. 它通常位于扩散采样流程的哪里？

一个典型的扩散轨迹生成流程可以写成：

```text
随机噪声轨迹 x_T
    ↓
扩散模型预测去噪方向
    ↓
DPM-Solver 或其他采样器推进一步
    ↓
根据碰撞风险计算 guidance 奖励
    ↓
对奖励求梯度，得到避碰方向
    ↓
修正采样方向
    ↓
继续下一步反向扩散
    ↓
最终生成轨迹
```

`GuidanceWrapper` 负责的是中间这部分：

```text
当前轨迹状态
    ↓
构造适合碰撞检测的物理轨迹
    ↓
调用碰撞规避函数
    ↓
返回可求梯度的奖励 energy
```

---

## 2. 为什么需要“引导”而不是只依赖扩散模型？

扩散模型通过训练数据学习轨迹分布。它通常能够生成较自然的轨迹，但不一定能够在每个新场景中严格满足所有约束。

例如：

- 生成轨迹可能靠其他车辆太近；
- 生成轨迹可能短暂越出道路边界；
- 生成轨迹可能不够舒适；
- 生成轨迹可能偏离目标点。

因此，可以额外定义一个奖励函数：

$$
E(x)
$$

其中，$x$ 表示当前轨迹。

如果奖励越大代表轨迹越好，那么：

$$
\nabla_x E(x)
$$

就表示：

> 应该朝哪个方向微调轨迹，才能让奖励上升得最快。

碰撞规避引导就是利用这个梯度，使采样结果朝更安全的方向变化。

# 第二部分：原始代码骨架

## 3. 去掉详细注释后的核心代码

```python
from typing import List

import torch

from diffusion_planner.model.diffusion_utils.sde import VPSDE_linear
from diffusion_planner.model.guidance.collision import collision_guidance_fn


N = 1
sde = VPSDE_linear()


class GuidanceWrapper:
    def __init__(self):
        self._guidance_fns = [
            collision_guidance_fn
        ]

    def __call__(self, x_in, t_input, cond, *args, **kwargs):
        energy = 0
        state_normalizer = kwargs["state_normalizer"]
        observation_normalizer = kwargs["observation_normalizer"]
      
        B, P, _ = x_in.shape
        model = kwargs["model"]
        model_condition = kwargs["model_condition"]
      
        x_fix = model(x_in, t_input, **model_condition).detach() - x_in.detach()
        x_fix = x_fix.reshape(B, P, -1, 4)
        x_fix[:, :, 0] = 0.0
        x_in = x_in + x_fix.reshape(B, P, -1)
      
        # x_in = torch.repeat_interleave(x_in, N, dim=0)
        # t_input = torch.repeat_interleave(t_input, N, dim=0)
        # kwargs["inputs"] = {k: torch.repeat_interleave(v, N, dim=0) for k, v in kwargs["inputs"].items()}
      
        # sigma_t = sde.marginal_prob_std(t_input)
        # sigma_t = sigma_t / torch.sqrt(1 + sigma_t ** 2)
        # x_in = torch.cat([x_in[:, :1] + sigma_t[:, None, None] * torch.randn_like(x_in[:, :1]), x_in[:, 1:]], dim=1)
      
        x_in = state_normalizer.inverse(x_in.reshape(B, P, -1, 4))
        kwargs["inputs"] = observation_normalizer.inverse(kwargs["inputs"])
      
        for guidance_fn in self._guidance_fns:
            energy += guidance_fn(x_in, t_input, cond, **kwargs)

        # energy1 = self._guidance_fns[0](x_in, t_input, cond, **kwargs)
        # energy2 = self._guidance_fns[1](x_in, t_input, cond, **kwargs)
        # energy = energy1 if energy2 < 1 else energy2
        
        assert not torch.isnan(energy).any()
          
        return energy
```

# 第五部分：输入参数与张量形状

## 12. `x_in`

```python
x_in
```

它是当前扩散采样过程中的轨迹状态。

函数开头读取：

```python
B, P, _ = x_in.shape
```

所以 `x_in` 预期是三维张量：

```text
[B, P, D]
```

其中：

| 维度 | 含义 |
|---|---|
| `B` | batch size，一次处理多少个场景或样本 |
| `P` | 参与预测的车辆数量，通常包含自车和邻车 |
| `D` | 展平后的轨迹特征维度 |

后续代码会执行：

```python
x_in.reshape(B, P, -1, 4)
```

所以：

$$
D=T\times4
$$

其中，$T$ 表示轨迹时间点数量。

每个时间点包含 4 个状态分量。结合碰撞引导代码，通常可以理解为：

```text
(x, y, cos_h, sin_h)
```

即：

| 分量 | 含义 |
|---|---|
| `x` | 二维平面中的横坐标 |
| `y` | 二维平面中的纵坐标 |
| `cos_h` | 航向角余弦 |
| `sin_h` | 航向角正弦 |

---

## 13. `t_input`

```python
t_input
```

它表示当前扩散时间。

扩散采样从高噪声阶段逐步走向低噪声阶段。`t_input` 告诉模型：

> 当前轨迹中大约含有多少噪声。

模型需要结合时间判断应该如何去噪。

```python
cond
```


这种设计保留了接口兼容性：即使碰撞引导暂时不用 `cond`，其他引导函数也可能需要。

## 19. 再调用一次扩散模型

```python
model = kwargs["model"]
model_condition = kwargs["model_condition"]

x_fix = model(x_in, t_input, **model_condition).detach() - x_in.detach()
```

这是本文件最值得理解的一段。

先看数值关系：

$$
x_{\text{fix}}
=
\operatorname{model}(x_{\text{in}},t,\text{condition})
-
x_{\text{in}}
$$

因此：

$$
x_{\text{in}}+x_{\text{fix}}
=
\operatorname{model}(x_{\text{in}},t,\text{condition})
$$

也就是说，后续代码会把当前轨迹数值替换为模型预测结果。

但是这里还使用了：

```python
.detach()
```

这会切断梯度。

---

## 20. `detach()` 到底是什么？

假设：

```python
y = f(x)
```

正常情况下，PyTorch 会记录：

```text
x → f(x) → y
```

之后可以计算：

$$
\frac{\partial y}{\partial x}
$$

如果写成：

```python
y = f(x).detach()
```

那么数值不变，但梯度路径被切断：

```text
x    f(x).detach()
╰──×──╯
```

之后，PyTorch 不会通过 `f(x)` 向 `x` 反向传播。

---

## 21. 为什么这里要对两边都 `detach()`？

代码为：

```python
x_fix = model(x_in, t_input, **model_condition).detach() - x_in.detach()
```

因此：

```python
x_fix
```

在梯度计算时会被当成常量。

然后：

```python
x_in = x_in + x_fix.reshape(B, P, -1)
```

数值上：

$$
x_{\text{in,new}}
=
x_{\text{in}}
+
\left[
\operatorname{model}(x_{\text{in}})-x_{\text{in}}
\right]
=
\operatorname{model}(x_{\text{in}})
$$

但梯度上，因为括号中的修正量已经被 `detach()`，所以：

$$
\frac{\partial x_{\text{in,new}}}{\partial x_{\text{in}}}
=
I
$$

也就是说：

> 数值上使用模型预测后的轨迹进行碰撞检测，但梯度反传时不穿过复杂模型，而是沿着一条简单的恒等映射返回。

这是一种非常关键的设计。

可以把它理解为一种“直通梯度”思想：

```text
前向计算：使用模型修正后的轨迹
反向传播：近似认为修正前后梯度可以直接传递
```

这样做的好处：

- 不需要对模型本身做二阶梯度传播；
- 显著降低计算量和显存占用；
- 避免让 guidance 梯度路径过于复杂；
- 仍然可以用模型修正后的轨迹评估碰撞风险。

---

## 22. 为什么需要模型先修正轨迹？

扩散过程中的 `x_in` 可能仍然带有较强噪声。

如果直接对高噪声轨迹计算碰撞，几何关系可能没有实际意义。

因此代码先执行：

```python
model(x_in, t_input, **model_condition)
```

利用扩散模型得到更加合理的轨迹估计，再对该轨迹进行碰撞评估。

直观类比：

```text
原始 x_in：一张很模糊的草图
模型输出：根据草图猜测出的较清晰轮廓
碰撞检测：在较清晰轮廓上判断是否会撞车
```

---

## 23. 恢复轨迹形状

```python
x_fix = x_fix.reshape(B, P, -1, 4)
```

原始：

```text
[B, P, D]
```

恢复为：

```text
[B, P, T, 4]
```

其中：

$$
T=\frac{D}{4}
$$

如果 `D` 不能被 4 整除，会报错。

---

## 24. 固定第 0 个时间点

```python
x_fix[:, :, 0] = 0.0
```

第 0 个时间点通常表示当前时刻。

当前车辆状态是已经观测到的事实，不应被扩散模型或 guidance 修改。

因此，代码把第 0 个时间点的修正量设为零：

$$
x_{\text{fix}}[:,:,0,:]=0
$$

这样：

```python
x_in = x_in + x_fix
```

之后，第 0 个时间点仍然保持原值。

而未来轨迹点会替换为模型预测结果。

---

## 25. 应用修正量

```python
x_in = x_in + x_fix.reshape(B, P, -1)
```

对于未来时间点：

$$
x_{\text{in,new}}
=
\operatorname{model}(x_{\text{in}})
$$

对于第 0 个时间点：

$$
x_{\text{in,new}}[:,:,0,:]
=
x_{\text{in,old}}[:,:,0,:]
$$

因此，新轨迹由两部分组成：

```text
当前时刻：保持原始已知状态
未来时刻：使用模型预测结果
```

# 第八部分：逆归一化

## 28. 为什么一定要逆归一化？

模型通常使用归一化数据训练。

例如，物理距离：

```text
10 米
```

归一化后可能变为：

```text
0.25
```

碰撞检测必须在真实尺度中完成，否则：

```text
车辆长度
车辆宽度
安全距离
矩形间距
```

都会失去正确的物理含义。

---

## 29. 轨迹状态逆归一化

```python
x_in = state_normalizer.inverse(x_in.reshape(B, P, -1, 4))
```

第一步，将轨迹恢复为：

```text
[B, P, T, 4]
```

第二步，通过：

```python
state_normalizer.inverse(...)
```

恢复真实物理尺度。

重要要求：

> 如果后续还需要对 `energy` 关于原始 `x_in` 求梯度，那么 `state_normalizer.inverse()` 的实现必须保留可微分的 PyTorch 运算，不能偷偷转换成 NumPy 或使用不可微操作。

---

## 30. 场景观测逆归一化

```python
kwargs["inputs"] = observation_normalizer.inverse(kwargs["inputs"])
```

`inputs` 可能包含：

- 邻居车辆历史状态；
- 邻居车辆尺寸；
- 掩码；
- 其他场景观测。

碰撞检测需要真实车辆尺寸和真实位置，因此这些观测也要恢复到物理空间。

---

## 31. 一个需要注意的副作用

这行代码直接修改了：

```python
kwargs["inputs"]
```

也就是说：

```python
kwargs["inputs"] = ...
```

会将原值替换成逆归一化后的值。

如果同一个 `inputs` 字典对象被重复使用，并且下次调用时又执行一次逆归一化，就可能产生重复逆变换问题。

是否真的会出错，取决于：

- `kwargs` 每次是否新建；
- `inputs` 是否深拷贝；
- `observation_normalizer.inverse()` 是否原地修改数据；
- 上游调用逻辑如何组织。

这是阅读或调试代码时值得重点检查的地方。

# 第九部分：调用并累计 guidance 函数

## 32. 遍历所有引导函数

```python
for guidance_fn in self._guidance_fns:
    energy += guidance_fn(x_in, t_input, cond, **kwargs)
```

当前列表为：

```python
[
    collision_guidance_fn
]
```

因此等价于：

```python
energy += collision_guidance_fn(
    x_in,
    t_input,
    cond,
    **kwargs

```

如果以后增加多个函数，则奖励会相加：

$$
E_{\text{total}}
=
\sum_i E_i
$$

---

## 33. 奖励相加需要注意什么？

不同奖励函数可能具有不同尺度。

例如：

```text
碰撞奖励：绝对值可能达到 100
车道奖励：绝对值可能只有 0.2
舒适性奖励：绝对值可能只有 0.01
```

直接相加后，碰撞奖励可能完全主导其他目标。

因此，实际扩展多个 guidance 函数时，通常需要加入权重：

$$
E_{\text{total}}
=
\lambda_{\text{collision}}E_{\text{collision}}
+
\lambda_{\text{lane}}E_{\text{lane}}
+
\lambda_{\text{comfort}}E_{\text{comfort}}
$$

当前代码没有显式权重机制，因为只启用了一个碰撞引导函数。


这展示了另一种组合策略：

```text
不是直接相加，而是根据条件选择某一个奖励。
```

# 第十一部分：它如何接入 DPM-Solver 的 classifier guidance？

## 37. 与 `model_wrapper()` 的关系

DPM-Solver 的 `model_wrapper()` 支持 classifier guidance。

其思想近似为：

```python
cond_grad = grad(classifier_fn(x, t, condition), x)
noise = noise_prediction(x, t)
noise_guided = noise - guidance_scale * sigma_t * cond_grad
```

数学形式为：

$$
\epsilon_{\text{guided}}
=
\epsilon_\theta(x_t,t)
-
w\sigma_t\nabla_{x_t}E(x_t)
$$

其中：

| 符号 | 含义 |
|---|---|
| $\epsilon_\theta$ | 原始噪声预测 |
| $E(x_t)$ | guidance 奖励 |
| $\nabla_{x_t}E(x_t)$ | 朝更优轨迹移动的方向 |
| $w$ | 引导强度 |
| $\sigma_t$ | 当前噪声尺度 |

`GuidanceWrapper` 可以充当这个 `classifier_fn`：

```python
guidance_fn = GuidanceWrapper()
```

即使它并不是传统图像分类器，也可以复用 classifier guidance 接口。

---

## 38. 为什么它叫 `energy`，但实际上更像 reward？

代码变量名为：

```python
energy
```

但当前碰撞引导函数的设计更接近“奖励”：安全方向应当对应更有利的梯度。

在不同项目中，可能采用两种约定：

### 约定 A：奖励越大越好

$$
\text{沿 }+\nabla_x E(x)\text{ 移动}
$$

### 约定 B：代价越小越好

$$
\text{沿 }-\nabla_x C(x)\text{ 移动}
$$

因此，不要仅根据变量名 `energy` 判断正负号。必须结合采样器中如何使用梯度来判断。

当前代码应结合 DPM-Solver 的 classifier guidance 更新公式一起阅读。

# 第十二部分：关键的“直通梯度”设计

## 39. 再看一遍核心公式

代码：

```python
x_fix = model(x_in, t_input, **model_condition).detach() - x_in.detach()
x_in = x_in + x_fix
```

令：

$$
f(x)=\operatorname{model}(x,t,\text{condition})
$$

则前向数值为：

$$
x_{\text{new}}
=
x+\operatorname{stopgrad}(f(x)-x)
$$

其中，`stopgrad` 表示停止梯度传播。

### 前向传播时

$$
x_{\text{new}}
=
f(x)
$$

### 反向传播时

$$
\frac{\partial x_{\text{new}}}{\partial x}
=
I
$$

这是一种典型的直通估计思想。

---

## 40. 为什么不直接写成 `x_in = model(...)`？

如果直接写：

```python
x_in = model(x_in, t_input, **model_condition)
```

那么碰撞奖励对输入的梯度需要穿过整个扩散模型：

```text
碰撞奖励
    ↓
碰撞几何
    ↓
模型输出
    ↓
深层神经网络
    ↓
原始 x_in
```

这会带来：

- 更高显存占用；
- 更高计算开销；
- 更复杂的梯度结构；
- 潜在的数值不稳定；
- 可能需要高阶导数。

当前设计改成：

```text
碰撞奖励
    ↓
碰撞几何
    ↓
模型修正后的轨迹数值
    ↓
恒等梯度路径
    ↓
原始 x_in
```

在计算量和效果之间进行折中。

## 41. `GuidanceWrapper.__call__()` 的完整流程

```text
输入归一化轨迹 x_in: [B, P, D]
```

# 第十四部分：伪代码

## 42. 使用更容易理解的伪代码重写

```python
class GuidanceWrapper:
    def __init__(self):
        self.guidance_functions = [collision_guidance]

    def __call__(self, noisy_trajectory, diffusion_time, condition, **kwargs):
        total_reward = 0

        model = kwargs["model"]
        state_normalizer = kwargs["state_normalizer"]
        observation_normalizer = kwargs["observation_normalizer"]
        model_condition = kwargs["model_condition"]

        batch_size, vehicle_count, _ = noisy_trajectory.shape

        predicted_trajectory = model(
            noisy_trajectory,
            diffusion_time,
            **model_condition,
        )

        correction = stop_gradient(
            predicted_trajectory - noisy_trajectory
        )

        correction = correction.reshape(
            batch_size,
            vehicle_count,
            time_count,
            4,
        )

        correction[:, :, 0] = 0

        trajectory_for_guidance = noisy_trajectory + flatten(correction)

        trajectory_for_guidance = state_normalizer.inverse(
            reshape_to_time_series(trajectory_for_guidance)
        )

        physical_inputs = observation_normalizer.inverse(
            kwargs["inputs"]
        )

        for guidance_function in self.guidance_functions:
            total_reward += guidance_function(
                trajectory_for_guidance,
                diffusion_time,
                condition,
                inputs=physical_inputs,
            )

        assert total_reward contains no NaN

        return total_reward
```

# 第十五部分：值得检查的潜在问题

## 43. `model(...)` 会增加额外推理开销

包装器内部再次调用：

```python
model(x_in, t_input, **model_condition)
```

如果外层扩散采样器本来已经调用过一次模型，那么启用 guidance 后，每一步可能会增加额外的模型前向传播。

因此，应关注：

- 实际 NFE；
- 每次规划耗时；
- GPU 显存；
- 是否能复用外部模型预测。

---

## 44. `D` 必须能被 4 整除

因为代码执行：

```python
reshape(B, P, -1, 4)
```

所以必须满足：

$$
D\bmod4=0
$$

否则会报错。

---

## 45. 模型输出形状必须与输入一致

代码执行：

```python
model(...).detach() - x_in.detach()
```

因此：

```python
model(...).shape == x_in.shape
```

必须成立。

---

## 46. `inverse()` 必须保留梯度

如果：

```python
state_normalizer.inverse(...)
```

内部使用 NumPy、`.cpu().numpy()` 或其他不可微操作，奖励梯度可能无法正确回传。

---

## 47. `kwargs["inputs"]` 被直接替换

```python
kwargs["inputs"] = observation_normalizer.inverse(kwargs["inputs"])
```

要检查是否会重复逆归一化。

更保守的写法可以使用局部变量：

```python
physical_inputs = observation_normalizer.inverse(kwargs["inputs"])
local_kwargs = dict(kwargs)
local_kwargs["inputs"] = physical_inputs
```

这样不会直接修改原始 `kwargs`。

---

## 48. `energy = 0` 在空列表情况下仍是整数

如果：

```python
self._guidance_fns = []
```

那么 `energy` 会保持 Python 整数：

```python
0
```

之后调用：

```python
torch.isnan(energy)
```

可能不符合预期。

当前列表不为空，所以正常运行。

---

## 49. 多个 guidance 函数的尺度需要协调

如果未来加入多个奖励，最好显式配置权重，而不是直接相加。

---

## 50. 被注释掉的重复采样代码需要同步更新 `B`

启用：

```python
repeat_interleave
```

后，batch 大小会变化。后续 `reshape(B, P, ...)` 仍然使用旧的 `B`，可能导致形状错误。

# 第十六部分：更加稳妥的参考写法

## 51. 不改变原意的结构化改写

下面的代码是便于理解的参考版本，不是对原项目的强制修改。

```python
from typing import Any, Callable, Dict, List

import torch

from diffusion_planner.model.guidance.collision import collision_guidance_fn


class GuidanceWrapper:
    def __init__(self) -> None:
        self._guidance_fns: List[Callable[..., torch.Tensor]] = [
            collision_guidance_fn,
        ]

    def __call__(
        self,
        x_in: torch.Tensor,
        t_input: torch.Tensor,
        cond: Any,
        *args: Any,
        **kwargs: Any,
    ) -> torch.Tensor:
        if not self._guidance_fns:
            raise ValueError("At least one guidance function is required.")

        state_normalizer = kwargs["state_normalizer"]
        observation_normalizer = kwargs["observation_normalizer"]
        model = kwargs["model"]
        model_condition: Dict[str, Any] = kwargs["model_condition"]

        batch_size, vehicle_count, feature_dim = x_in.shape

        if feature_dim % 4 != 0:
            raise ValueError(
                f"Expected feature_dim to be divisible by 4, got {feature_dim}."
            )

        model_output = model(
            x_in,
            t_input,
            **model_condition,
        )

        if model_output.shape != x_in.shape:
            raise ValueError(
                "Model output shape must match x_in shape: "
                f"{model_output.shape} != {x_in.shape}."
            )

        correction = model_output.detach() - x_in.detach()
        correction = correction.reshape(batch_size, vehicle_count, -1, 4)
        correction[:, :, 0] = 0.0

        guided_state = x_in + correction.reshape(batch_size, vehicle_count, -1)
        guided_state = guided_state.reshape(batch_size, vehicle_count, -1, 4)
        physical_state = state_normalizer.inverse(guided_state)

        local_kwargs = dict(kwargs)
        local_kwargs["inputs"] = observation_normalizer.inverse(kwargs["inputs"])

        energy = None
        for guidance_fn in self._guidance_fns:
            current_energy = guidance_fn(
                physical_state,
                t_input,
                cond,
                **local_kwargs,
            )
            energy = current_energy if energy is None else energy + current_energy

        if energy is None:
            raise RuntimeError("No energy was produced.")

        if torch.isnan(energy).any():
            raise FloatingPointError("NaN detected in guidance energy.")

        return energy
```

该版本重点改进：

- 显式检查 guidance 列表是否为空；
- 检查特征维度是否可被 4 整除；
- 检查模型输出形状；
- 避免直接修改原始 `kwargs["inputs"]`；
- 使用更明确的异常信息。

# 第十八部分：最终总结

## 53. 一句话总结

这份代码的核心作用是：

> 先用扩散模型将当前带噪轨迹修正为更合理的预测轨迹，再在真实物理尺度中计算碰撞规避奖励，最后把该奖励返回给采样器，使反向扩散过程朝更安全的方向发展。

## 54. 最关键的代码

```python
x_fix = model(x_in, t_input, **model_condition).detach() - x_in.detach()
x_fix = x_fix.reshape(B, P, -1, 4)
x_fix[:, :, 0] = 0.0
x_in = x_in + x_fix.reshape(B, P, -1)
```

它实现：

```text
数值上：
使用模型修正后的未来轨迹做碰撞检测。

梯度上：
不穿过复杂模型，而是保留简单的恒等梯度通路。

当前时刻：
固定不动。
```
