# 第四章：固定候选上的Reward排序审计实验协议

> 协议固化时间：10月05日01时  
> 状态：10月05日09时59分完成validation-1000；四种目标资格集合差异为0  
> 性质：只读机制审计，不更新模型参数

## 1. 科学问题

固定同一场景、同一B10和完全相同的32条Repair候选轨迹时，当前`legacy` reward与`nuplan_aligned`、`nuplan_score_proxy_v2/v3`对候选的排序有何差异？引入碰撞、路线与舒适性质量后，能否改善安全与可行性相关候选选择，同时不显著牺牲进度？

该实验用于判断下一轮应当训练哪个reward目标。它不直接回答新reward训练后是否提高闭环性能。

## 2. 严格单因素设计

1. 固定B10 Epoch10 EMA checkpoint、validation-1000、seed 3407和6步DPM-Solver；
2. 每个锚点只生成一次Repair候选池：`0.1×40+0.5×64+1.0×32+1.5×32+2.0×32=200`；
3. 按Repair-100原协议，以legacy reward、安全资格和轨迹多样性选出固定32条候选：`0.1×11+0.5×16+1.0×2+1.5×2+2.0×1`；
4. 将这同一组32条轨迹同时交给四种目标评分，模型、场景、轨迹、未来邻车、地图输入及安全门均不改变；
5. 不执行反向传播、optimizer update或checkpoint写入。

候选子集仍按legacy reward选择，是为了审计Repair-100训练期间实际可见的候选支持。这会对legacy有一定选择偏置，因此最终结论只用于筛选下一项严格训练对照，不将其写成新reward的最终性能优势。

## 3. 对照目标

| 目标 | 排序中直接使用的主要分量 |
|---|---|
| `legacy` | risk、follow、lane、progress guard加权和 |
| `nuplan_aligned` | safety、progress、lane、comfort、follow的加权几何平均 |
| `nuplan_score_proxy_v2` | safety、progress、route、comfort、follow的加权几何平均；连续collision cost仅诊断 |
| `nuplan_score_proxy_v3` | 在v2基础上将连续collision cost显式并入安全质量 |

四组沿用相同risk/TTC安全门、碰撞候选过滤和相同安全资格集合。

## 4. 主要观测量

- 安全集内部reward排序与progress guard、risk、TTC、collision cost、route cost、comfort cost和backward cost的Spearman相关；
- 每个目标选出的安全top-1候选的上述分项、ADE/FDE；
- top-1是否被安全集合内其他候选Pareto支配；
- 各目标与legacy的top-1一致率和排序相关性；
- reward标准差和归一化top-2间隔，用于判断排序分辨率；
- 无安全候选的锚点比例单独报告，不将其混入安全集合排序结论。

## 5. 预注册的下一训练候选门禁

相对legacy的top-1安全候选，某个新目标只有同时满足以下均值条件，才允许进入下一轮严格单因素后训练：

1. collision cost差值不高于`+1e-4`；
2. 截断到8秒的最小TTC差值不低于`-0.01 s`；
3. route cost差值不高于`+1e-4`；
4. comfort cost差值不高于`+1e-4`；
5. progress guard差值不低于`-0.005`；
6. no-collision比例不下降。

该门禁只决定“是否值得训练”，不代表新reward已被闭环验证。若没有目标通过，则停止训练扩张，先分析目标冲突或重新构造reward；不得事后放宽门槛挑选看起来最好的结果。
