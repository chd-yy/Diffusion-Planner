# 第四章：候选生成修复的严格单因素短程后训练对照

> 启动时间：10月04日09时58分  
> 完成时间：10月04日10时47分  
> 状态：已完成（两组各20次更新 + validation-1000×3）  
> 原则：候选修复已经通过只读验收；本实验首次检验其是否能改善后训练信号与策略变化方向

## 1. 科学问题

候选生成修复已将几何多样性、有效优势组和安全候选覆盖提升到预注册门槛，但“更好的候选集合”不等于“后训练后的模型更好”。本实验回答：

> 在其他训练因素完全一致时，修复后的安全多样性候选生成，能否相较原始`noise=0.1×32`产生更充分、方向更正确且不破坏B10基础能力的策略更新？

## 2. 两组严格对照

| Arm | 候选生成 | 其他配置 |
|---|---|---|
| Control | 原始`0.1×32` | 与Repair完全相同 |
| Repair | `200条多尺度搜索池→安全多样性筛选→固定32条` | 与Control完全相同 |

Repair候选池为：`0.1×40 + 0.5×64 + 1.0×32 + 1.5×32 + 2.0×32`；最终组配额为：`0.1×11 + 0.5×16 + 1.0×2 + 1.5×2 + 2.0×1`。

## 3. 固定控制项

- 起点：同一B10 Epoch10 EMA及相同SHA-256；
- 数据：同一10,000训练场景及manifest；
- seed：2026；
- group size：32；DPM steps：6；
- `rl_min_reward_std=0.01`；
- 20个optimizer step；学习率`4e-7`；
- positive-advantage更新；
- 相同collision/TTC/安全资格过滤；
- expert anchor=0.1，reference anchor=0.1；
- encoder冻结，trajectory augmentation关闭；
- 两组顺序运行，GPU不并发。

唯一实验因素是候选生成方法。Repair生成200条只是搜索池，写入replay及参与优势估计的仍是32条。

## 4. 自动门禁

两组训练完成后自动执行相对B10的`validation-1000×3`公共随机数配对评测，报告reward、progress、collision/route/comfort cost、ADE/FDE及行为变化比例。

判定不使用train loss：

1. Repair应显著提高训练侧active group和有回归目标批次比例；
2. Repair相对Control的验证进度方向应更好；
3. 不允许以碰撞、路线或舒适退化换取reward均值；
4. 20步只检验机制与方向，不宣称最终收敛；
5. 本实验不自动启动safety40，离线结果审计后再决定。
