# 第四章：同场景扩散候选生成修复与正式验收

> 完成时间：10月03日23时30分  
> 实验性质：冻结B10的只读推理修复；全过程未更新模型参数、未启动后训练  
> 最终状态：validation-1000预注册11项门槛全部通过

## 1. 问题与直接原因

原始RL rollout对每个场景生成32条候选，但统一使用`noise_scale=0.1`。B10在validation-1000上的终点两两距离中位数只有`0.055530 m`，整轨迹两两距离中位数只有`0.025200 m`；只有12.6%的场景在安全集合内达到`reward std >= 0.01`。

代码审计确认每个候选使用独立`torch.randn`，不存在复制同一噪声的实现错误。直接原因是VP-SDE终端先验接近单位高斯，而正式RL配置把初始噪声缩小到0.1；此外，单纯提高统一noise虽能扩大轨迹分布，却会损害平均轨迹质量，且无法充分修复运动场景中的安全支持缺失。

## 2. 修复方法

最终修复采用“扩大搜索池、压缩训练组”的两阶段候选生成：

1. 从冻结B10生成200条多尺度候选池：
   - `noise=0.1`：40条；
   - `noise=0.5`：64条；
   - `noise=1.0`：32条；
   - `noise=1.5`：32条；
   - `noise=2.0`：32条。
2. 使用与后训练一致的安全资格门筛选候选。
3. 每个尺度内保留安全reward极值，并使用整轨迹最远点采样保持几何覆盖。
4. 按固定配额压缩为最终32条候选：
   - `0.1×11 + 0.5×16 + 1.0×2 + 1.5×2 + 2.0×1`。

这使高温候选主要承担“发现原窄分布之外的安全支持”的作用；最终训练组中`noise>=1.5`仅占3/32，避免宽探索主导优势估计和破坏基础轨迹质量。

## 3. 迭代过程

| 版本 | 方法 | Pilot/Full结论 |
|---|---|---|
| v1 | 32条直接多尺度混合 | 多样性改善，但安全覆盖和有效组不足 |
| v2 | 64/96条池，安全reward跨度筛选 | 有效组增加，但几何多样性不足 |
| v3 | 96条池，安全优先最远点筛选 | Pilot 10/11；几何改善，覆盖仍不足 |
| v2 Full | 128条池，无尺度配额最远点筛选 | Full 8/11；过度选择高温候选，ADE恶化1.64% |
| v3 Full | 128条池，按尺度配额筛选 | Full 9/11；ADE恢复，但安全覆盖增益不足 |
| v4 Full | 168条池，引入少量1.5支持 | Full 9/11；覆盖差4个场景，ADE超线0.018个百分点 |

整个过程中没有放宽预注册门槛。100场景Pilot通过而1000场景失败的版本均被拒绝，避免以小样本乐观结果替代正式结论。

## 5. 可以与不可以得出的结论

可以得出：

- 原始厘米级候选坍缩已被修复；
- 修复后的候选组能够在保持B10平均轨迹质量和碰撞代理的同时，提供明显更强的安全集合内部优势信号；
- 候选生成已经满足进入下一阶段后训练机制实验的前置条件。

不可以得出：

- 尚不能说明RL后训练后的策略一定改善；
- 尚未形成官方闭环安全提升结论；
- 结果来自单个固定推理seed和离线固定邻车未来，不能替代reactive closed-loop；
- 200条搜索池使rollout计算量约为原32条的6.25倍，后续需单独报告训练吞吐和收益—成本权衡。
