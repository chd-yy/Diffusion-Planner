# EXP003｜候选生成覆盖与后训练覆盖并不相同

时间：09月17日 01:29（北京时间）。状态：completed，缓存元数据审计与确定性重建；没有新增训练或仿真。

## 问题

balanced_logs抽取10,000个场景后，当前FIFO1024的Replay是否仍维持相同日志与类型覆盖？

## 方法和边界

逐个读取真实10k NPZ的log_name、scenario_type、token。使用当前训练入口的单卡DistributedSampler默认seed=0、rollout epoch=0，重建完整遍历顺序，取最后1024个条目。不是对实际update抽样进行追踪，也不表示每个保留条目都被更新。

## 真实审计结果

| 指标 | 原10k manifest | FIFO1024保留集合 |
|---|---:|---:|
| 场景条目 | 10000 | 1024 |
| 日志数 | 44 | 44 |
| 每日志条目范围 | 227～229（原缓存报告） | 12～31（本轮元数据重建） |
| 已记录scenario_type种类 | 39 | 31 |
| 与完整Test14唯一token交集 | 0 | 0 |

类别分布总变差距离=0.0595546875，仅为分布差异描述，不是显著性或驾驶性能指标。

保留集合没有以下8种原始标签：near_construction_zone_sign（原12条）、on_carpark（6条）、starting_unprotected_noncross_turn（2条）、stopping_at_crosswalk（2条）、stopping_at_stop_sign_no_crosswalk（1条）、stopping_at_stop_sign_without_lead（1条）、stopping_at_traffic_light_without_lead（3条）、stopping_with_lead（1条）。括号为原10k数量；标签缺失不等于相应语义驾驶行为绝对不存在，因为标签存在粒度及unknown问题。

原10k还有2596条unknown、2317条stationary；因此“balanced”不能被表述成交通类型均衡。它只对log给基础配额。

若后续对1024组均匀有放回抽样1000次，数学期望唯一组数为638.542；实际唯一更新数未知，不可把该期望记作实测。

## 中期可形成的认识

已经定位一个可复现的数据利用边界：全量候选评分量、Replay可用场景量、实际唯一更新量是三个不同概念；日志配额在FIFO后并不保留，部分稀有标签没有进入最终可更新集合。

这支持下一阶段设计覆盖审计与Replay对照，但不能证明FIFO就是闭环退化原因。扩大到10k也不必然提高安全性或样本效率；必须在固定候选/更新预算下做控制实验。
