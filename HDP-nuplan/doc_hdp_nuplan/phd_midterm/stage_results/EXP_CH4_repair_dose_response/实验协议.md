# 第四章：Repair后训练剂量—策略变化实验协议

> 预注册时间：10月04日11时25分  
> 启动时间：10月04日11时30分

> 状态：已完成，100步checkpoint通过全部预注册门禁  
> 原则：只延长已通过候选机制验收的Repair组，不更改reward、安全门控或anchor

## 1. 科学问题

> Repair候选生成所提供的有效优势信号，能否随着更新步数积累为幅度足够、方向正确，且不破坏安全性与基础模仿能力的策略变化？

上一轮20步实验已证明候选修复能将active group由5.0%提高到42.5%，但progress只变化`+0.001050`，不足以进入低样本闭环判定。

## 2. 实验设计

为避免重复rollout引入不必要的随机差异，本实验只进行一次固定Repair rollout，然后连续更新200步，并在实际optimizer update的第20、50、100、200步保存不可覆盖的中间checkpoint。

```text
B10
 └─ 固定Repair rollout与replay buffer
      ├─ 20步checkpoint
      ├─ 50步checkpoint
      ├─ 100步checkpoint
      └─ 200步checkpoint
```

固定项：

- B10 Epoch10 EMA与固定SHA-256；
- 训练seed=2026；
- 同一10,000训练场景；
- Repair候选池`0.1×40+0.5×64+1.0×32+1.5×32+2.0×32`；
- 筛选配额`0.1×11+0.5×16+1.0×2+1.5×2+2.0×1`；
- group size=32，DPM steps=6，`min_reward_std=0.01`；
- positive advantage、collision/TTC/安全资格过滤；
- expert anchor=0.1，reference anchor=0.1；
- encoder冻结，trajectory augmentation关闭；
- 学习率`4e-7`。

## 3. 统一评价

每个checkpoint相对同一B10执行`validation-1000×3`公共随机数配对评价：

- 数据seed=3407；
- 共3000对轨迹；
- 评价推理`noise=0.1`、DPM steps=6；
- 不根据中间结果改reward、门槛或训练配置。

## 4. 预注册门禁

一个checkpoint只有同时满足下列条件，才能成为safety40候选：

1. reward配对差值中位数`>0`；
2. progress配对均值`≥+0.005`，且P10`≥0`；
3. collision cost不上升，no-collision不下降；
4. route cost增加不超过`1e-4`；
5. comfort cost增加不超过`1e-4`；
6. ADE和FDE相对退化均不超过0.5%。

`progress≥0.005`是进入40场低样本闭环评测的计算筛选门槛，不是宣称实际驾驶效果的理论界限。路线和舒适性的`1e-4`容差用于避免把数值级微小波动误判为实质退化。

## 5. 停止与边界

- 评价所有20/50/100/200步checkpoint，不因早期结果中途改变实验；
- 本脚本不自动启动safety40；
- 若多个checkpoint通过，优先保留最早通过者，以减少不必要的策略漂移；
- 若全部未通过，结论是“当前安全约束更新未形成可评价的策略改进”，不追加临时调参。
