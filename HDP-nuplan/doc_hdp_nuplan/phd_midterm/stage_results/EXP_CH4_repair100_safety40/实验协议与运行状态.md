# 第四章：B10与Repair-100固定safety40成对闭环验证

> 协议固化时间：10月04日22时14分  
> 当前状态：10月05日00时08分完成B10与Repair-100各40场成对仿真；10月05日00时40分完成结果审计  
> 实验性质：固定40场景、单推理seed、官方非反应式闭环成对开发集验证

## 1. 实验问题

本实验回答：validation-1000上通过全部离线门禁的Repair-100，能否将reward、progress和collision proxy的离线改善转化为固定safety40上的官方闭环指标改善，同时不引入新的责任碰撞。

两个模型均将在同一当前代码快照下重新评测，不直接复用历史B10闭环均值。Repair的`200→32`候选搜索只用于后训练，闭环部署时不额外启用多候选搜索，避免将模型参数改变与推理搜索混杂。

## 3. 固定评测协议

- benchmark：`midterm_safety40_v1`；
- 40个唯一场景、8个日志、五个预注册研究分组；
- 路口与转向12场、车辆交互10场、行人及规则8场、动态及环境6场、基础能力保留4场；
- 仿真模式：`closed_loop_nonreactive_agents`；
- 推理seed：0；
- worker：单机单worker；
- 两模型使用完全相同的场景、顺序、代码、硬件与评价配置；
- 必须各完成40/40，runner failure不能当作低分或从结果中删除。

## 4. 预注册接受门禁

Repair-100只有同时满足以下条件才通过本次开发集门禁：

1. B10与Repair-100均完成40个成对场景；
2. Repair-100相对B10无新增责任碰撞；
3. 平均综合score不下降；
4. 平均沿Expert路线进度不下降；
5. 平均可行驶区域合规指标不下降；
6. 平均TTC合规指标不下降。

新增责任碰撞直接触发拒绝，不得用其他场景的连续指标均值改善抵消。门禁通过只表示在该40场分层开发集中未观察到预定退化，不构成统计安全保证。
